## 1. 扩展目标和约束（p.2–13）

理想多 GPU 系统希望：

- 参数/状态容量随 GPU 数线性增长；
- 总有效 FLOPs 随 GPU 数线性增长；
- 通信可与计算重叠；
- 单 GPU 上仍保留足够大的高效 GEMM；
- global batch 不被迫超过优化可接受范围。

现实网络分层：节点内 NVLink/NVSwitch 快，节点间网络慢；TPU 常用 mesh/torus，GPU 大域更偏 switched fabric。拓扑决定 parallel axes 的放置：规则邻域通信适合 mesh，MoE all-to-all 更依赖交换网络。

## 2. 数据并行的内存问题（p.14–17）

朴素 DDP 每 rank 拥有完整：参数、梯度、master weights、Adam $m/v$。一种常见混合精度账本为 16 bytes/parameter：

| 状态 | bytes/param |
|---|---:|
| BF16 参数 | 2 |
| BF16 梯度 | 2 |
| FP32 master | 4 |
| FP32 Adam $m$ | 4 |
| FP32 Adam $v$ | 4 |

因此 80GB 卡扣除其他开销前也只能容纳约 5B 参数；增加 DP ranks 不会降低每 rank 参数状态。

## 3. ZeRO-1：切 Optimizer State（p.18–21）

把 optimizer state 和更新责任按参数 shard 分到 $P$ ranks：

1. 每 rank 用本地 batch 计算完整梯度；
2. reduce-scatter 梯度，每 rank 得到自己参数 shard 的全局梯度；
3. 用本地 $m/v/master$ 更新参数 shard；
4. all-gather 更新后的参数，恢复每 rank 完整模型。

若参数+梯度固定占 4 bytes/param，optimizer/master 共 $K$ bytes，则：

$$
M_{Z1}/N\approx4+K/P.
$$

通信量与 ring all-reduce 同量级：reduce-scatter + all-gather，因此在大消息带宽主导时几乎“免费”获得 optimizer state 分片。

## 4. ZeRO-2：再切 Gradient（p.22–23）

反向逐层产生梯度时立即 reduce-scatter；一旦某层梯度发送完成，就释放非本 rank shard，不实例化完整持久梯度。

$$
M_{Z2}/N\approx b_{param}+(b_{grad}+K)/P.
$$

参数仍复制，因此模型权重必须单卡放下；但 gradient 和 optimizer 状态显著下降。实现难点是 autograd bucket、gradient 生命周期和通信重叠。

## 5. ZeRO-3 / FSDP：切全部状态（p.24–28）

参数也只保存 shard：

### Forward

1. 当前 FSDP unit 需要计算前 all-gather 参数；
2. 执行该 unit forward；
3. 若策略允许，释放完整参数，仅保留 shard；
4. 预取下一 unit 参数，与当前计算重叠。

### Backward

1. 再 all-gather 当前 unit 参数；
2. 计算本地完整梯度贡献；
3. reduce-scatter 梯度；
4. 释放完整参数和非本地梯度。

每参数一 step 典型通信约：forward all-gather + backward all-gather + gradient reduce-scatter，约为 DDP 带宽量的 1.5 倍，但每 rank 持久状态近似：

$$
M_{Z3}\approx\frac{N(b_p+b_g+b_{opt})}{P}.
$$

忽略激活和临时 full-param buffer 时可近线性扩展。FSDP unit 太小会产生大量 latency；太大则峰值 gather buffer 高、overlap 差。wrapping policy 是性能参数。

## 6. ZeRO 的边界

- ZeRO-1/2 不切参数；
- ZeRO-3 切参数但不自动切激活；
- all-gather 参数的通信与 layer 参数量相关；
- 计算太短时无法隐藏通信；
- global batch 仍随 DP 增长，受 critical batch size 限制。

所以大模型还需要 model parallelism。

## 7. Pipeline Parallelism（p.31–38）

把连续层切成 $S$ stages，传输边界 activation 和 activation gradient。

### 7.1 Bubble

对 $m$ micro-batches，简单 pipeline 的 bubble/useful work 近似：

$$
\frac{S-1}{m}.
$$

要降低 bubble 需 $m\gg S$，但 global batch、micro-batch GEMM 效率和激活内存限制 $m$。

### 7.2 为什么仍使用 PP

- 参数按 stage 分片；
- 通信量是边界 activation $O(btd)$，不是整层参数；
- 点对点、规则，适合跨节点较慢链路；
- stage 可按层计算量做负载平衡。

### 7.3 Schedule

- GPipe：all-forward then all-backward，bubble 直观但激活多；
- 1F1B：warmup 后 forward/backward 交替，激活更少；
- interleaved virtual stages：一张卡持有多段非连续层，减少 bubble但通信增多；
- zero-bubble：把 backward 分成 input-gradient $B$ 和 weight-gradient $W$。$B$ 必须及时向前一 stage 传播，$W$ 可填充空隙，从而减少 bubble。

## 8. Tensor Parallelism（p.39–43）

以 Transformer MLP：

$$
H=\phi(XW_1),\qquad Y=HW_2.
$$

- $W_1$ column-parallel，得到分片 $H_r$；
- $W_2$ row-parallel，每 rank 算 $Y_r$；
- all-reduce $Y=\sum_rY_r$。

QKV/up/gate 通常列切，attention output/down 通常行切。TP 没有 pipeline bubble，不依赖大 batch，但每个 block 都发生 collective；因此一般在节点内且 TP degree 常不超过 8。TP 过大导致：本地矩阵窄、Tensor Core 利用下降，通信相对计算上升。

## 9. Activation Memory 与 Sequence Parallel（p.44–49）

仅对线性投影做 TP，并不会分片所有激活。norm、dropout、residual 和 block 输入仍可能在每个 TP rank 完整复制，规模约 $O(BTd)$；长序列时成为瓶颈。

这些操作多数沿 hidden 独立、可按 sequence 切：

1. residual/norm/dropout 在 sequence shard 上执行；
2. 进入需要 hidden-sharded GEMM 的区域前 all-gather 或使用等价变换；
3. 输出用 reduce-scatter 回 sequence shards。

Sequence parallel 让非 matmul 激活也随 TP degree 下降。要区分：它主要降低激活复制，不是把 attention 的 $T^2$ 计算本身变成分布式长上下文算法。

## 10. Expert Parallelism（p.50–53）

每 rank 放一组 experts，router 后用 all-to-all 发送 token activations，expert 计算后再 all-to-all 返回。相较 TP：

- 不把单个 expert GEMM 切得很小，可保持大 GEMM；
- 通信是激活而非 partial sums；
- 需要严格负载均衡；
- 只适用于 MoE MLP，attention 仍需其他并行。

因此 MoE 可能希望 MLP 用大 EP、小 TP，而 attention 需要较大 TP。现代系统会解耦 attention 与 expert 的并行布局，避免用同一个 degree 勉强覆盖两者。

## 11. Context Parallel / Ring Attention（p.54）

把一个长序列沿 token 轴分到 $P$ ranks，每 rank 持有一段 Q/K/V。为让本地 queries 看到全部 keys/values，可环传 K/V blocks：

```text
每轮：本地 Q 与当前 K/V block 做 attention
→ online softmax 合并局部结果
→ 把 K/V 发给下一 rank
→ 共 P 轮
```

因果 attention 需跳过未来 blocks或细粒度 mask。它把 KV/activation memory 约分到 $1/P$，适合长上下文阶段，但通信随序列和层数发生，要求与 attention 计算重叠。

## 12. 并行维度组合（p.55–62）

设总 GPU 数：

$$
G=DP\times PP\times TP\times CP
$$

对 MoE 还要说明 EP 与 DP/TP 的 rank-group 关系，不能总是简单再乘一次。

经验流程：

1. **先让模型和激活放得下**：节点内 TP/EP；跨节点 PP 或合适的 FSDP；长上下文用 CP/SP/重计算。
2. **再保证每 rank GEMM 足够大**：不要无限增加 TP；调整 micro-batch。
3. **剩余 GPU 用 DP 扩展吞吐**：直到 global batch/通信接近极限。
4. **映射到拓扑**：高频 TP 放最快域，PP 放慢链路，EP 放 all-to-all 强的域。
5. **用 gradient accumulation 调 batch 与 pipeline bubbles**。

文献中常见 TP≤8，PP 随模型深度/跨节点增长，DP 在最大模型上反而下降；长上下文阶段 CP 会明显增大（p.57–72）。

## 13. 一个统一成本表

| 方法 | 每 rank 参数状态 | 激活/KV | 主要通信 | 对 batch 的影响 |
|---|---|---|---|---|
| DDP | 完整 | 完整 | 每 step 梯度 all-reduce | global batch 随 DP 增长 |
| ZeRO-1 | opt 分片 | 完整 | RS grad + AG params | 同 DP |
| ZeRO-2 | opt+grad 分片 | 完整 | 增量 RS + AG | 同 DP |
| FSDP/Z3 | 全状态分片 | 默认不分 | 每 unit 参数 AG + grad RS | 同 DP |
| TP | 约 $1/TP$ | 部分分片 | 每层 collective | 不要求增 batch |
| PP | 约 $1/PP$ | 按 stage/microbatch | P2P activations | 需多 microbatches 藏 bubble |
| SP | 随 TP/序列分片 | 降低非 GEMM 激活 | AG/RS | 不必增 global batch |
| EP | experts 分片 | routed tokens | all-to-all | 受负载均衡影响 |
| CP | 序列/KV 分片 | 约 $1/CP$ | K/V ring或all-to-all | 面向长上下文 |

## 14. Overlap：理论 bytes 之外的关键

若通信时间 $T_c$ 和计算 $T_m$ 完全串行，step 时间 $T_c+T_m$；理想重叠后接近 $\max(T_c,T_m)$。实现手段：

- FSDP prefetch 下一层参数；
- DDP backward bucket all-reduce；
- pipeline 在不同 micro-batches 上交错；
- MoE all-to-all 与其他 token/expert 计算交错；
- CP 环传下一 K/V block 时计算当前 block。

需要独立 streams、事件依赖和足够大计算块。若通信与计算争夺同一 HBM/互联资源，重叠不会理想。

## 15. 大规模训练的可靠性

Llama 3 等案例表明，数千 GPU 下硬件故障是常态。训练系统还需：

- 分布式 checkpoint 与快速恢复；
- optimizer/RNG/data-loader state 一致恢复；
- health check、hang detection、straggler 监控；
- loss spike 与 silent data corruption 检查；
- elastic job 或明确的失败重启策略。

MFU 平坦不等于整体产出线性，故障恢复和 checkpoint 开销也要计入有效训练吞吐。

## 16. 设计与验证步骤

1. 做每参数/每 token 内存账本，找“放不下”的具体状态；
2. 写出每层每 rank tensor shape；
3. 列出每个 collective 的 bytes、频率、group 和 topology；
4. 估计 bubble、global batch 和本地 GEMM shape；
5. 单并行维度逐一与单卡 reference 对齐；
6. 再组合 2D/3D/4D，检查 groups 是否正交、collective 顺序是否一致；
7. profile 计算、通信、等待、峰值显存；
8. 最后做故障恢复和多 step loss 对齐。

## 17. 常见误区

- ZeRO-1/2 不会让参数本体分片；ZeRO-3 也不自动解决激活内存。
- FSDP 通信量的常数更高，是否快取决于 overlap 和 unit 粒度。
- PP 的通信少不代表一定快，bubble 和 stage imbalance 可能主导。
- TP 无 bubble 但每层高频通信，只适合快互联且 degree 有上限。
- Sequence parallel 与 context parallel 目标不同：前者常分非 GEMM 激活，后者分长序列 attention/KV。
- EP 的 all-to-all 性能由最拥堵 expert/device 决定。
- 多维并行 degrees 的乘积正确，不代表 rank mapping 对拓扑最优。

本讲的核心不是记住某个固定配方，而是把模型沿 batch、depth、width、experts、sequence 五个轴分别切开，再用“内存是否线性、通信能否隐藏、本地计算是否高效、global batch 是否合理”四项约束组合它们。
