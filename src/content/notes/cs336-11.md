## 1. 实践中的三个难题（p.2–5）

1. 架构随宽度/深度放大后，激活和梯度尺度是否保持稳定？
2. 最优 learning rate、batch、optimizer 是否随规模改变？
3. Chinchilla 式 $(N,D)$ 网格若每个点都从头训练，成本如何降低？

完整 recipe 必须把参数化、优化器、schedule、batch 与 data/model ratio 一起设计，不能只拟合最后 loss。

## 2. MiniCPM 案例（p.6–18）

### 2.1 固定可迁移的结构

MiniCPM 使用 μP 思路稳定初始化/学习率，固定 aspect ratio，再整体放大模型。小规模模型约 9M、30M、170M 与目标模型仍有约 5 倍尺寸间隔，所以需要 out-of-range 验证，而不是认为 μP 自动证明外推。

### 2.2 最优学习率

在 μP 理想下，宽度变化时最优 base LR 应近似稳定。验证方法不是只看一条曲线，而是每个模型做 LR sweep，比较 loss–LR 曲线的 minimizer 和宽容区间；若最优点平移，要检查参数组 scaling、norm gain、embedding/output 和 optimizer 实现。

### 2.3 最优 Batch

MiniCPM 在多个模型、数据量、batch 上采样，寻找固定训练进度/最终 loss 的下包络，再拟合 batch 与 loss 的关系。通常训练越后期、目标 loss 越低，optimal/critical batch 越大。

Batch 与 LR 必须联合 sweep：扩大 batch 却保持不合适 LR，得到的是某个 recipe 的失败，不是 batch 的 scaling law。

## 3. WSD Learning-Rate Schedule（p.13–18）

WSD = Warmup–Stable–Decay：

```text
warmup：从小 LR 升到 η_max
stable：长时间保持近似常数
decay：最后一段快速衰减
```

### 3.1 为什么有助于 Scaling Sweep

Cosine schedule 的 LR 由预先承诺的总训练长度决定。若在不同 token 预算早停，同一 checkpoint 经历了不同程度衰减，不可直接比较。

WSD 在 stable 阶段保存 checkpoint。要评估不同 $D$：

1. 从对应 stable checkpoint 分叉；
2. 为每个候选预算运行同样相对长度的 decay；
3. 得到多个“在各自预算下已衰减”的最终 loss。

这样一个长 stable run 可复用为多个数据预算，降低从头训练 $N\times D$ 网格的成本。课程案例中 decay 约占总段的 10%，但比例不是通用常数。

### 3.2 注意事项

- stable checkpoint 本身不是最终模型，必须比较经过 decay 的点；
- 分叉后数据顺序、optimizer state 和 weight decay 历史要一致；
- schedule 改变可能改变 batch/LR law，不能沿用 cosine 下的拟合而不验证。

## 4. DeepSeek 与近期 Scaling Recipe（p.19–30）

DeepSeek 不依赖 μP，而是：

1. 小规模直接 sweep LR 和 batch；
2. 用 WSD/分段 schedule 便宜地产生多个预算点；
3. 用 IsoFLOPs 选择模型大小/数据量；
4. 检查拟合对最终 7B/67B loss 的预测。

Qwen、LLaMA 3、MiniMax、Hunyuan、Kimi 等也采用不同版本：

- dense/MoE 分别拟合 total、active parameters 或 sparsity；
- 某些模型获得远高于经典 Chinchilla 的 data/active-param ratio；
- 下游能力与 pretraining loss 可另拟合，但噪声更大。

共同点不是某个固定指数，而是：把 LR/batch 调优与 IsoFLOPs sizing 分开，再用中等规模验证最终预测。

## 5. LR–Batch 联合地形（p.31–40）

经验上，在固定模型/数据预算下，loss 对 log LR、log batch 的局部地形常近似碗形，可识别宽容区：

$$
(\eta^*,B^*)=\arg\min_{\eta,B}L(\eta,B;N,D).
$$

然后拟合：

$$
\eta^*=f_\eta(N,D,C),\qquad B^*=f_B(N,D,L).
$$

不同论文选自变量不同：critical batch 常按 loss；DeepSeek 风格按 compute power law；StepFun 观察 batch 更主要依赖 data size。函数形式本身也是待验证假设。

### 5.1 公平比较 Optimizer

不同 optimizer 的最优 LR、betas、weight decay、warmup 和 batch scaling 不同。公平比较必须给每个 optimizer 独立调参预算，并在多个 compute scales 上观察曲线。小规模短跑胜出，可能只因为默认参数更合适。

### 5.2 Scaling 失败模式

- 在已测范围拟合很好，目标规模突然发散；
- sqrt-batch LR rule 与具体参数化不兼容；
- gradient clipping 在某规模频繁触发，改变有效更新；
- 同名 optimizer 的矩阵参数归一化/分布式实现不同；
- Chinchilla ratio 和 optimizer 改进互为 confounder。

## 6. Muon Optimizer（p.42–43）

Muon 主要用于二维矩阵参数。先形成 momentum/更新矩阵 $B_t$，再近似极分解：

$$
B_t=USV^T\quad\rightarrow\quad UV^T.
$$

即把奇异值压到近似 1，让更新在各方向更均衡。无需显式 SVD，可用 Newton–Schulz 迭代近似矩阵正交化。例如对适当归一化 $X$：

$$
X_{k+1}=\frac12X_k(3I-X_k^TX_k)
$$

或使用为低精度/有限步数优化的高阶系数。bias、norm、embedding 等非二维参数通常仍用 AdamW。

Muon 在 nanoGPT 和 Kimi K2 等显示可扩展，但比较必须计算正交化额外 FLOPs、通信、参数组 LR 和目标 compute；“小模型 speedrun 更快”不足以证明所有大规模训练更优。

## 7. μP 的目标（p.44–46）

Maximum Update Parametrization 希望宽度 $n$ 增大时：

1. 初始化激活保持 $\Theta(1)$；
2. 一个训练步造成的功能/激活变化保持 $\Theta(1)$；
3. 因而小模型上的最优超参数能迁移到更宽模型。

它关注的是网络函数随宽度的极限，而不只是“方差不爆炸”的初始化。

## 8. 初始化尺度推导（p.47）

考虑线性层：

$$
h_l=W_lh_{l-1},\quad
W_{ij}\sim\mathcal N(0,\sigma_l^2).
$$

若 $h_{l-1}$ 每坐标为 $O(1)$，则 $\|h_{l-1}\|^2=\Theta(n_{l-1})$。要让输出每坐标仍为 $O(1)$，常需：

$$
\sigma_l^2\propto1/n_{l-1}.
$$

课件进一步考虑 fan-in/fan-out 不同，给出按 $n_l/n_{l-1}$ 调整的尺度，使输出范数 $\Theta(\sqrt{n_l})$。标准 Xavier/He 主要满足初始化条件，μP 还要求训练更新条件。

## 9. 更新尺度推导（p.48–50）

SGD 对线性层的梯度近似外积：

$$
\Delta W_l=-\eta_l\nabla_{h_l}\ell\,h_{l-1}^T.
$$

其引起的激活变化：

$$
\Delta h_l\approx W_l\Delta h_{l-1}
+\Delta W_l h_{l-1}.
$$

若 $\eta$ 不随宽度调整，第二项可能随 $n$ 消失或爆炸。μP 为不同参数类型指定独立初始化、LR multiplier 和输出 scaling，使两项都在宽度极限保持 $O(1)$ 最大有效更新。

“baby μP”给出直觉，但 Transformer 的完整规则还要区分：

- hidden-to-hidden matrix；
- input embedding；
- output/readout layer；
- attention Q/K/V/O；
- bias/vector-like 参数；
- SGD 与 Adam 的归一化差异。

不能简单给所有参数乘同一个宽度比。

## 10. Base Shape 与 Delta Width

实际 μP 工具常定义一个 base model shape，目标模型的每个维度相对 base 的 multiplier 决定初始化和 LR scaling。工作流：

1. 构建很小 base shape；
2. 标注哪些维度是无限宽度维、哪些固定（head_dim 等）；
3. 为各参数类型应用 μP initializer/LR multiplier；
4. 在多个宽度 sweep 同一 base LR；
5. 检查最优 LR 曲线是否重合。

改变 depth、head count、vocab 或数据并不一定属于“只增 width”的理论范围。

## 11. μP 的经验鲁棒性与失败（p.51–57）

课程列出的检验：

- SwiGLU、squared ReLU、不同 batch、部分初始化变化通常仍有一定迁移；
- **RMSNorm learnable gain** 可破坏预期 scaling，移除 gain 后更稳定；
- Lion/符号类 optimizer 的更新归一化不同，规则不能直接套；
- 强 weight decay（如 0.1）与参数/LR scaling 耦合，是显著失败源；
- attention、embedding、softmax readout 若漏用专门规则，也会让最优 LR 漂移。

因此 μP 的正确结论是“通常比标准参数化更容易跨宽度调参”，不是“所有超参数对任意规模和架构都恒定”。

## 12. 推荐的 Scaling 实验协议

### 阶段 A：实现校准

- 多宽度下记录每层 activation RMS、gradient RMS、update/weight ratio；
- 一步训练后检查 $\Delta h$ 是否同量级；
- 验证 μP 参数分组和 base-shape metadata。

### 阶段 B：LR/Batch Sweep

- 至少 3 个模型规模；
- 对 log LR × log batch 建网格；
- 固定数据、tokens、schedule 定义；
- 识别 minimizer 和近最优宽容区，不只取单点。

### 阶段 C：Sizing

- 用 WSD checkpoint branching 或 IsoFLOPs；
- 分别拟合 $N_{opt}(C),D_{opt}(C)$；
- 留出若干 runs 做 out-of-sample validation。

### 阶段 D：目标训练保护

- 从更小到中等规模逐级确认；
- 监控 spike、clip rate、norm、loss 与预测偏差；
- 预设偏离 scaling prediction 时的停止/降 LR 条件。

## 13. 常见误区

- WSD 的 stable checkpoint 不能直接当不同预算的最终 loss，需各自 decay。
- μP 主要解决宽度 scaling，不自动解决 depth、data、batch 和架构改变。
- 所有参数用一个 LR scaling 不是 μP。
- 不同 optimizer 用相同默认超参数比较是不公平的。
- LR/batch 最优点应作为二维地形研究，单独扫一维会受另一维影响。
- 一条漂亮的 log-log 线不能替代目标规模外推验证。
- 强 weight decay、learnable norm gain 等“小组件”可能破坏理论 scaling。

本讲的核心是：scaling 成功依赖把训练配方也做成可扩展对象。WSD 降低数据预算 sweep 成本，μP 尝试稳定宽度变化下的函数更新，而严谨的 LR/batch/optimizer 实验负责检验这些假设是否在真实 Transformer 中成立。
