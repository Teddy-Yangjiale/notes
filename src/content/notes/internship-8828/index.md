## 1. 复用的链与必须重新核对的接口

核心仍是条带 → 视觉运动 → 位姿图 → 正射图/环境点云 → 站点。但录像容器、时间戳、定位记录和标定不同，因此复制脚本后需要逐项检查。

|---|---|---|

## 2. 先把采集时刻说清楚

`t01e_1012.py` 从容器记录取每帧时刻，再与外部定位建立对应。实际帧间隔并不必然精确等于一个固定常数，因此按“帧号除名义 FPS”推时间只是近似。

若定位比照片超前 $\tau$，匀速下位置偏移近似 $v\tau$。历史分支记录采用 0.56 s 修正，这个数来自该数据链的诊断，不是所有车辆的统一延迟。需要记录符号：到底是把定位时间加上延迟，还是从空间位置减去前进量，两种实现都可能表达同一物理关系，但不能重复修正两次。

## 3. 图像压缩怎样导致轨迹碎片？

角点依赖局部二维纹理。DVR 压缩会抹掉沥青细节，LK 找到的可靠对应减少。`viewer1012` 历史 README 记录过增加角点数量、降低质量门槛、扩大 LK 窗口，并在细配失败时加入受定位比例和相关峰限制的粗配备用边。

粗配不是无条件补边。若相关峰不够强，或位移与定位预测不相容，就不应把它当可靠测量。否则连续性看起来提高了，却可能是在用错误边强行连接轨迹。

![1012 前摄实际帧 3540](/notes/internship/media/8828-front-003540.jpg)

*不同路段的纹理和遮挡差别很大。不能仅用一张清楚的图证明全路线都适合相同跟踪阈值。此处的 3540 是 1012 解码序号，不是 0903 的同一时刻。*

## 4. 俯仰为什么能伪装成速度尺度错误？

对道路像素，前向距离大致与 $h/\tan\alpha$ 成正比，$\alpha$ 是向下看地面的夹角：

$$
Z=\frac{h}{\tan\alpha},
\qquad \frac{dZ}{d\alpha}=-h\csc^2\alpha.
$$

当 $\alpha$ 很小时，导数绝对值很大。相机俯仰略偏，远处道路就被明显拉伸；条带中估出的前进量随之改变，看起来像里程计尺度错误。

历史诊断用远近两半条带的位移差与整幅位移对照，修正过 4.61° 到 4.93° 的俯仰设定。这些是该记录的参数，不是本文重新标定结果。道路有坡度、车辆加减速点头时，一个固定俯仰仍有局限。

**手算。** 在简化几何中 $h=1.5$ m、$\alpha=5^\circ$，$Z\approx17.15$ m；夹角变成 $4.7^\circ$，约为18.25 m，差约1.1 m。小角度误差为何值得单独诊断，现在就有了数量级。

## 5. ABot 环境点云如何与新轨迹合并？

1012 分支使用自己的 ABot 输出，并把模型点图恢复到原图射线，再按新轨迹进入 ENU。尺度仍靠道路几何约束；它并不是把旧 0903 点云整体搬过去。

历史 README 记录的高分辨率点图为 420×756，而模型配置默认可能为 280×504。回映射必须采用本次运行的实际输入尺寸、裁剪规则与点图尺寸，不能只看模型仓库的默认配置。

## 6. 两天卷帘比较究竟比较什么？

![1012 现有道路正射瓦片](/notes/internship/media/8828-ground-0.jpg)

*从当前站点的已有 L0 瓦片读取。单块瓦片只覆盖局部，不能代表两天共同观测的全部路面；无覆盖边界应保留。*

卷帘让同一屏幕区域切换显示两天结果，适合检查标线、覆盖与环境外观。要判定真实病害变化，还需要控制地图配准误差、不同车道、遮挡、光照与检测差异。

历史比较发现去程可能开在不同车道。两天没有共同看到的地面，不能当作“某一天没有病害”。比较分母应是共同可见、分辨率足够且可定位的区域。

## 7. 一个容易制造假好结果的相关计算

若两张正射图在无覆盖处都填 0，再高通计算相关，两者相同的覆盖边界会贡献一个很强的零位移峰。算法看似估出几乎零误差，实际上匹配的是人工边界。

更合理的检查包括：先填本图均值再计算纹理，收缩共同有效区域，加入不相关瓦片作为负对照。仅在可信峰的少数瓦片上报告偏移时，也必须同时写出通过率。
