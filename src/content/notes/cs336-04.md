## 1. 两类瓶颈与两类稀疏

标准 Transformer 的两个大计算块：

```text
Attention：token 与 token 交互，长序列成本高
MLP：每个 token 经过相同大网络，参数计算高
```

- Attention alternatives 试图把 $O(T^2)$ 的 token 交互改为线性、递归或稀疏形式；
- MoE 把一个 dense MLP 换成多个 expert，但每个 token 只调用 top-$k$ 个，使总参数增大而 active FLOPs 近似不变。

两者都以“不是所有输入都需要使用所有计算”为前提，但优化目标和系统瓶颈不同。

## 2. Linear Attention（p.2–5）

### 2.1 通过结合律改变复杂度

忽略 softmax，若 attention 为：

$$
Y=(QK^T)V,
$$

可利用结合律改写：

$$
Y=Q(K^TV).
$$

设 $Q,K\in\mathbb R^{T\times d_k}$，$V\in\mathbb R^{T\times d_v}$：

- 先算 $QK^T$：$O(T^2d_k)$，再乘 $V$：$O(T^2d_v)$；
- 先算 $K^TV$：$O(Td_kd_v)$，再乘 $Q$：$O(Td_kd_v)$。

当 $T\gg d$ 时后者近似线性于序列长度。

### 2.2 softmax 为什么破坏简单重排

标准 attention：

$$
\operatorname{softmax}(QK^T/\sqrt d)V
$$

softmax 对每个 query 的整行 logits 归一化，不能直接把括号移到 $K^TV$。Kernelized linear attention 用特征映射近似：

$$
\exp(q^Tk)\approx\phi(q)^T\phi(k),
$$

再维护：

$$
S=\sum_j\phi(k_j)v_j^T,\qquad
z=\sum_j\phi(k_j),
$$

$$
y_i=\frac{\phi(q_i)^TS}{\phi(q_i)^Tz}.
$$

近似是否稳定、特征维度多大、因果 mask 如何处理，都会影响质量和常数成本。

### 2.3 递归形式

对 causal、无归一化版本：

$$
S_t=S_{t-1}+k_tv_t^T,
\qquad y_t=q_t^TS_t.
$$

状态 $S_t\in\mathbb R^{d_k\times d_v}$ 的大小不随上下文长度增长。训练时可使用并行 scan/chunk 算法，推理时逐步更新固定状态。这种“同一算子既有并行矩阵形式，也有递归形式”的 duality 是线性 attention/状态空间模型的重要系统优势。

但固定状态会压缩全部历史，无法像 full attention 那样按需精确访问任意 token；表达能力与遗忘机制成为核心问题。

## 3. 从线性状态到 Mamba-2 与 Gated DeltaNet（p.6–11）

### 3.1 衰减/选择性状态

Mamba-2 风格可抽象为：

$$
S_t=\gamma_tS_{t-1}+k_tv_t^T,
$$

$$
y_t=q_t^TS_t+Dv_t,qquad \gamma_t=f(x_t).
$$

$\gamma_t$ 决定旧状态保留多少；输入依赖的门控让模型能对不同 token 使用不同时间尺度。$Dv_t$ 是直接通路，避免所有信息都必须先写入压缩状态。

### 3.2 Delta rule：先擦除再写入

Gated DeltaNet 形式：

$$
S_t=\gamma_t(I-\beta_tk_tk_t^T)S_{t-1}
+\beta_tk_tv_t^T,
$$

$$
y_t=q_t^TS_t.
$$

直觉：

1. $(I-\beta k k^T)$ 擦除状态中与当前 key 方向相关的旧关联；
2. $\beta k v^T$ 写入新的 key-value 关联；
3. $\beta=0$ 时可以选择不写；
4. $\gamma$ 控制整体遗忘。

这比不断累加外积更能处理同一 key 需要更新 value 的场景，也与 fast-weight programmer 的在线联想记忆解释相连。

### 3.3 为什么采用 Hybrid

Minimax、Nemotron、Qwen 等模型常按 7:1 或 3:1 组合线性/GDN 层与 full-attention 层：

- 大多数层用固定状态，获得长上下文线性扩展和小推理状态；
- 少量 full layers 提供精确内容寻址，补偿状态压缩的信息损失。

公开结果显示可行，但受控 ablation 仍有限。hybrid ratio、full layer 位置、状态维度、并行 scan kernel 都可能影响结论（p.6–11）。

## 4. Dynamic Sparse Attention（p.12–13）

另一条路线保留 softmax attention，但只选择少数历史 token：

1. 用轻量 indexer 为当前 query 计算候选分数；
2. 选择 top-$k$ blocks/tokens；
3. 只对被选 K/V 运行标准 attention；
4. 用专门 sparse kernel 避免 gather 成本吞掉收益。

复杂度理想上从 $O(T^2)$ 降到 $O(Tk)$。DSA 还可在 dense、短上下文预训练后适配，但必须处理选择器训练、召回损失、非连续内存访问以及 causal 边界。算法稀疏不等于硬件高效；若索引和 gather 不规则，实际速度可能不如理论。

## 5. MoE 的计算模型（p.14–26）

### 5.1 从 dense MLP 到 sparse experts

设有 $E$ 个 expert $f_e(x)$，router 输出 logits：

$$
r(x)=W_rx,qquad p_e(x)=\operatorname{softmax}(r(x))_e.
$$

选择集合 $S(x)=\operatorname{TopK}(p(x),k)$，输出：

$$
y=\sum_{e\in S(x)}g_e(x)f_e(x),
$$

其中 $g_e$ 是被选 expert 的归一化权重。总参数约随 $E$ 增长，单 token active MLP FLOPs 只随 $k$ 增长。

### 5.2 为什么 MoE 有吸引力

- 相同 active FLOPs 下拥有更多参数和潜在专业化容量；
- 在足够规模上，训练 loss/下游能力常优于 FLOPs 匹配的 dense 模型；
- experts 可分布到不同设备，形成 expert parallelism；
- 训练和推理只激活少量参数。

代价是：总权重内存仍很大；跨设备 all-to-all、负载不均、离散路由和 fine-tuning 稳定性都更复杂（p.16–24）。

## 6. 路由算法（p.27–35）

### 6.1 Token-choice Top-$k$

主流流程：

```text
tokens [N,d]
 → router logits [N,E]
 → 每个 token 选 top-k experts
 → 按 expert 对 token 排序/dispatch
 → 每个 expert 批量执行 MLP
 → combine 回原 token 顺序
```

Switch Transformer 用 $k=1$；GShard/Mixtral/Grok 常用 2；Qwen/DBRX/DeepSeek 等使用更高 $k$。$k$ 越大通常表达更强、路由更稳，但 active FLOPs 和通信增加。

不同实现可能：

- 先对全部 experts softmax，再取 top-$k$；
- 先取 top-$k$ logits，再在选中集合 softmax；
- 用 sigmoid 独立打分，再归一化选中权重。

这会改变竞争关系和梯度。

### 6.2 Expert-choice 与全局匹配

- Expert-choice：每个 expert 选择最想处理的 tokens，天然控制容量，但 token 可能被选零次/多次；
- 线性分配/匹配：在全局优化效用和容量，目标更直接但求解与并行成本高；
- hash routing：固定映射，便宜且可作 baseline，但缺乏输入自适应；
- REINFORCE 路由：理论上直接优化离散决策，但梯度方差和工程复杂度使其不主流。

### 6.3 Fine-grained 与 Shared Experts

把一个大 expert 切成多个小 expert，在相同 active 参数下选择更多模块，可增加组合数和专业化粒度。Shared experts 对所有 token 始终开启，负责通用知识；routed experts 学剩余差异。

DeepSeek 的 ablation 支持 fine-grained/shared 设计，OlMoE 对 fine-grained 有收益但对 shared 未观察到收益，说明它不是无条件定律（p.32–35）。

## 7. 离散路由如何训练（p.36–43）

### 7.1 Top-$k$ 不可导问题

被选 expert 内部和选中 gate 权重可正常反传，但“未选 expert 是否应该被选”经过离散 top-$k$，没有普通梯度。实践依靠：

- soft router 分数对已选路径的梯度；
- noise/jitter 增加探索和鲁棒性；
- load-balancing 辅助损失；
- 在线调整 router bias。

### 7.2 随机扰动

可给 router logits 加 Gaussian noise，或对输入/分数加小幅乘性 jitter。目的不是提升最终随机性，而是避免早期微小差异永久锁死专家，让边界附近 token 偶尔探索其他 expert。

### 7.3 Load-balancing loss

定义 batch 中分配到 expert $e$ 的 token 比例：

$$
f_e=\frac1N\sum_{i=1}^{N}\mathbf1[e\in S(x_i)],
$$

以及平均 router 概率：

$$
P_e=\frac1N\sum_i p_e(x_i).
$$

Switch 风格辅助项常写成：

$$
\mathcal L_{bal}=\alpha E\sum_{e=1}^{E}f_eP_e.
$$

若某 expert 已被大量使用，$f_e$ 大，会推动其概率 $P_e$ 下降。也可按 device 聚合，直接平衡通信和设备负载。

问题是辅助损失可能与语言建模目标冲突：为了均衡而把 token 送给不合适的 expert。DeepSeek V3 使用每 expert bias 做在线负载控制：过载 expert 的 bias 下调，空闲 expert 上调；仍保留较弱的序列级辅助约束，所以“auxiliary-loss-free”并非完全没有辅助机制（p.40–43）。

### 7.4 Capacity 与 Token Dropping

每个 expert 常有容量：

$$
C=\left\lceil \text{capacity factor}\times\frac{Nk}{E}\right\rceil.
$$

超容量 token 可能被丢弃、送往次选 expert 或走残差。若容量按 batch 决定，同一个请求是否丢 token 会受其他请求影响，带来额外非确定性。现代 dropless MoE/sparse GEMM 尽量处理不等长 expert batch，减少这种行为。

## 8. MoE 系统实现（p.44–50）

### 8.1 Expert Parallel 的通信

若 expert 分布在多 GPU：

1. 本地计算 router；
2. 按目标 expert pack tokens；
3. all-to-all 把 token 发到 expert 所在设备；
4. 本地执行 grouped/sparse GEMM；
5. 第二次 all-to-all 送回；
6. 按原 token 顺序 combine。

通信量与 active token hidden states 成正比，不与 expert 参数总量直接成正比。负载不均会造成 straggler，最慢设备决定 step 时间。MegaBlocks 等库通过 block-sparse/grouped GEMM 支持不同 expert token 数。

### 8.2 降低通信

- 按 node/device 限制候选 experts（top-$M$ device routing）；
- 在 dispatch 前把 activation 投影到较小维度，返回后再恢复；
- 将共享 experts 本地复制；
- 通信与 expert GEMM 重叠；
- 共同优化 parallel layout，避免 MoE all-to-all 与 tensor parallel collectives 冲突。

### 8.3 Router 数值稳定

router logits 的小误差可能改变 top-$k$ 离散选择，因此常用 FP32 计算 router，并对其 log-partition 加 z-loss：

$$
\mathcal L_z=\beta\left(\log\sum_e e^{r_e}\right)^2.
$$

这抑制 logits 无界增大，降低 overflow 和过度确定的路由（p.48–49）。

### 8.4 Fine-tuning 风险

小数据微调时只有少数 tokens 到达每个 expert，易过拟合或路由漂移。可选策略：

- 冻结 router 或 experts，只调 dense/shared 部分；
- 使用更多、更均衡的 SFT 数据；
- 监控每 expert token 数、熵和容量溢出；
- 降低 router 学习率。

## 9. Upcycling（p.51–53）

把已有 dense MLP 复制/切分成多个 experts：

1. 载入 dense checkpoint；
2. 用相同权重初始化 routed experts，使初始函数接近原模型；
3. 初始化 router 为近似均匀并加小扰动打破对称；
4. 继续预训练，让 experts 分化；
5. 逐步调节 balancing 和容量。

MiniCPM、Qwen MoE 展示了成功案例。关键是对称破缺：若 expert 权重和路由完全相同，它们可能收到相同梯度而无法专业化。

## 10. DeepSeek MoE 演进（p.54–56）

- **V1**：top-$k$、shared + fine-grained experts、expert/device 辅助均衡；
- **V2**：更多专家，引入通信方向的平衡与 top-$M$ device routing；
- **V3**：约 256 routed experts、8 active、1 shared，使用 bias 在线均衡和较弱序列级辅助项。

数字本身不是结论；真正的演进方向是：更细专家、更大的总容量、保持少量 active 参数，同时让路由目标越来越贴近实际通信瓶颈。

## 11. 相关组件：MLA 与 MTP（p.57–59）

### 11.1 Multi-head Latent Attention

MLA 将 K/V 表示为低维 latent $c_t^{KV}$ 的上投影。推理只缓存 latent，减少 KV cache。若无位置旋转，一部分上投影可吸收到 query 投影中；RoPE 的位置相关矩阵会阻碍简单吸收，因此 DeepSeek 将内容和位置部分拆分处理。

### 11.2 Multi-Token Prediction

训练时增加轻量预测头，让中间表示预测未来多个 token：

$$
\mathcal L=\mathcal L_{next}+\sum_{j=2}^{K}\lambda_j\mathcal L_{t+j}.
$$

它可提供更密集训练信号，也可为 speculative decoding 提供 draft 候选。DeepSeek V3 实际重点使用有限的未来步数，不能把它理解为一次无条件生成多个准确 token。

## 12. 选择与验收

### Attention alternative

必须同时比较：固定质量下的训练 tokens/s、prefill latency、decode state/cache、长上下文检索、短上下文 loss、kernel 成熟度。只报告理论 $O(T)$ 不足以证明更快。

### MoE

除 loss 外至少监控：

- 每 expert token 数与 coefficient of variation；
- router entropy、top-1/top-2 margin；
- capacity overflow/drop rate；
- all-to-all 时间与每 GPU expert GEMM 时间；
- total parameters、active parameters 与 active FLOPs；
- 微调后路由漂移。

## 13. 常见误区

- 线性 attention 不是把 softmax attention 随意换括号；必须改变/近似归一化结构。
- 固定大小状态带来线性推理，也带来历史压缩的信息瓶颈。
- 稀疏 FLOPs 不等于稀疏系统更快；索引、all-to-all 和小 GEMM 可能主导。
- MoE 的总参数仍要存储和加载，不能把 active parameters 当作显存占用。
- Top-$k$ 的离散选择没有普通梯度，实际训练依赖启发式均衡和噪声。
- 负载均衡不是纯统计美观，而是避免设备空闲和 token dropping 的系统必要条件。
- Shared experts、fine-grained experts、aux-free routing 的收益依赖具体设置，不能从单一模型推广为定理。

本讲的统一思想是条件计算：让每个 token 只使用与其相关的历史或参数。真正困难的部分不是写出稀疏公式，而是让选择机制可训练、质量可控，并映射成规则且高利用率的硬件执行。
