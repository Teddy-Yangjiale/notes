## 一、这一讲在课程里的位置

整门课的主线是一条逐级抬升的闭环：L02 讲**推理时扩展**（同一模型多采样、多搜索就能变更强）→ L03 讲**验证**（闭环的瓶颈在于有没有可靠信号判断"哪个更好"）→ L04/L05 讲**从反馈中学习与多步规划**（让模型在环境里行动并纠错）→ L06 讲**训练时扩展**（把推理时搜出来的好东西蒸馏回权重）。到 L07 为止，"被改进的对象"始终是**模型的输出或模型本身**。

这一讲把闭环再抬一层：**被改进的对象变成智能体系统本身**——提示词、工具、控制流、乃至整个代码库都由 AI 自己来写和改。这是"自我改进"字面上最激进的形态，也是整门课的高潮。而它成立的前提，恰好是前面每一讲攒下的东西：推理时采样提供多样性（L02），自动化评估提供选择压力（L03），代码执行提供验证环境（L04），搜索与档案机制提供规划结构（L05）。

## 二、核心概念

- **开放式进化（open-endedness）**：不收敛于单一最优解、而是持续产生新颖且有趣的变体的搜索过程。源自人工生命研究，核心洞见是"通往某个目标的踏脚石往往长得不像目标本身"。
- **ADAS（Automated Design of Agentic Systems）**：自动设计智能体系统这一研究方向的统称——把 agent 的提示词、工具使用、工作流当作可搜索的对象，而不是人手工调出来的。
- **元智能体（meta agent）**：在 ADAS 中负责"发明新 agent"的 agent。因为 agent 用代码定义、而编程语言图灵完备，理论上元智能体可以发明任何可能的 agentic system。
- **档案（archive）**：开放式搜索中保存所有历史发现的库，新的变异从档案中采样父代，保证多样性而不是只盯着当前最优。
- **哥德尔机（Gödel machine）**：Schmidhuber 提出的理论构想——一个能改写自身代码、且能**证明**每次改写都有净收益的自我改进机器。实践中"证明有益"几乎不可能，DGM 用"经验验证"替代"形式证明"，故名 Darwin Gödel Machine。
- **自动化科研闭环**：AI Scientist 代表的思路——想法生成 → 写代码 → 跑实验 → 画图 → 写论文 → 自动审稿，全链条无人类参与。
- **进化式编码智能体（evolutionary coding agent）**：AlphaEvolve 代表的思路——LLM 充当变异算子，自动化评估器充当适应度函数，在程序空间里做进化搜索。

## 三、论文精要

### 3.1 《Automated Design of Agentic Systems》（ADAS / Meta Agent Search）

- **一句话贡献**：定义了 ADAS 这个新研究领域，并用一个简单算法 Meta Agent Search 证明——让元智能体用代码迭代地"编程"出新智能体，可以发明出大幅超越手工 SOTA 的智能体设计。
- **方法**：元智能体（GPT-4）维护一个不断增长的"发现档案"，每轮从档案中参考已有设计，编程出一个"有趣的新 agent"（新提示、新工具、新工作流的组合），在目标基准上评估后入档。迭代 25–30 次。被发现的 agent 用 GPT-3.5 评估以压低成本。
- **关键结果**（Table 1，对比 COT、COT-SC、Self-Refine、LLM Debate 等手工基线和提示优化基线 OPRO）：
  - **DROP**（阅读理解，F1）：**79.4** vs 最佳手工基线 65.8 → **+13.6/100**
  - **MGSM**（多语言数学，Acc）：**53.4%** vs 39.0% → **+14.4%**
  - MMLU、GPQA 上提升较小（作者归因于**模型知识瓶颈**：知识不够的问题，优化 agent 结构救不回来）
  - ARC 挑战（GPT-3.5）：发现的最佳 agent 13.7% vs COT 6.0% —— 接近翻倍
- **最惊人的是迁移性**：
  - 跨领域：在 MGSM 上搜出的 agent 直接迁到 GSM8K 得 **69.5%**（最佳手工基线 43.6%，**+25.9%**）；迁到 DROP 得 F1 71.9，仍优于手工基线 65.8
  - 跨模型：GPT-3.5 上搜出的 agent 迁到 Claude-Sonnet，ARC 准确率达 **48.3%**（基线 39.3%），接近 50%
- **局限（作者自述）**：只测了单步 QA 任务；只优化性能单目标（不管成本/延迟）；评估函数粗糙（只看数值，没让元智能体读运行日志）；搜索算法朴素（没用上 Quality-Diversity 等更高级的开放式算法）。
- **与课程主线的关系**：这是"改进对象从输出升到系统"的第一次具体化——而且它发现的 agent 设计（结构化反馈、集成、动态角色扮演）本质上是 L02 那些推理时技术的**自动组合与超越**。

### 3.2 《Darwin Gödel Machine》（DGM）

- **一句话贡献**：把 ADAS 的思路推到自我指涉的极致——智能体**修改自己的代码库**，每次修改用编程基准做经验验证，同时维护一个不断分叉的 agent 档案做开放式探索，实现了持续自我改进。
- **方法**：从档案中采样一个 agent → 基础模型生成它的一个"有趣的新版本"（改代码编辑工具、长上下文窗口管理、peer-review 机制等）→ 在 SWE-bench / Polyglot 上验证 → 入档。改进是**可复合的**：修改代码库的能力本身也在被改进。相对哥德尔机的"证明有益"，DGM 只要求"基准上经验有效"，换来可行性。
- **关键结果**：
  - **SWE-bench：20.0% → 50.0%**
  - **Polyglot：14.2% → 30.7%**
  - 显著优于"去掉自我改进"或"去掉开放式探索"的消融基线——两个成分缺一不可
- **安全设定**：全部实验在沙箱中运行，有人类监督。
- **与课程主线的关系**：DGM 是"AI 自己设计 AI"目前最完整的实证——注意它的选择压力完全来自**可自动验证的编程基准**，这正是 L03 主题在最高层的复现。

### 3.3 《The AI Scientist》

- **一句话贡献**：第一个覆盖科研全流程的自动化框架——生成想法、写代码、跑实验、可视化、写成完整论文、再跑一轮模拟审稿，成本低于 **15 美元/篇**。
- **方法**：三个 ML 子领域（diffusion modeling、transformer 语言建模、learning dynamics）上验证；配套设计了自动审稿人，作者声称其评分接近人类审稿水平，且有论文被自动审稿人判定**超过顶会接收线**。
- **关键结果**：每篇论文端到端成本 <$15；自动审稿接近人类水平（论文自述）。
- **局限（论文自身及后续社区广泛指出的）**：想法新颖性浅（多为已有方法的增量组合）；实验规模小；写作与引用会出错（幻觉引用）；**自动审稿人给出的"超过接收线"是它自己的评分，不等于真能通过人类评审**；没有人类把关时错误会沿链条放大。
- **与课程主线的关系**：它是"深度研究智能体"（L07 录像实际讲的主题）的激进版本——不止检索与综合文献，而是试图走完整个科研闭环。它也最直观地暴露了瓶颈：**没有可靠验证器的环节（想法质量、写作正确性）就是质量塌方的地方**。

### 3.4 《AlphaEvolve》（Google DeepMind）

- **一句话贡献**：Gemini 驱动的进化式编码智能体，在"解可被自动验证"的数学与系统问题上做出了一系列可量化的新发现，并已部署进 Google 生产环境。
- **方法（进化循环）**：提示采样器组装 prompt → LLM 集成生成程序（**Gemini Flash 负责广度、Gemini Pro 负责深度**）→ 自动化评估器验证、运行、打分 → 程序数据库执行进化算法，决定哪些程序进入下一轮 prompt。相比前代 FunSearch 只能发现单个函数，AlphaEvolve 能**进化整个代码库**。
- **关键结果**：
  - **矩阵乘法**：找到 4×4 复数矩阵乘法用 **48 次标量乘法**的算法，优于 1969 年以来该设置下最优的 Strassen 算法；进化过程经历 **15 次非平凡变异**（含梯度优化器、损失函数、超参扫描的设计）
  - **开放数学问题**：在 50+ 个分析/几何/组合/数论问题上，**约 75% 复现了已知最优解，20% 改进了已知最优解**；11 维 kissing number 问题给出 **593 个外切球**的新下界
  - **生产部署**：Borg 数据中心调度启发式（生产运行一年以上，持续回收 Google 全球约 **0.7%** 的计算资源）；TPU 电路 Verilog 重写（去除冗余位，须通过严格功能验证）；Gemini 训练关键 kernel 加速 **23%**、整体训练时间省 **1%**；FlashAttention 加速最高 **32.5%**，把专家数周的 kernel 优化压到数天
- **局限（硬前提）**：只适用于**解能被写成算法、且能被自动验证**的问题——评估函数就是它的"适应度"，没有可量化指标就无从下手；目前应用集中在数学与计算领域。
- **与课程主线的关系**：AlphaEvolve 是"L02 大规模采样 + L03 可靠验证器 + 进化搜索"在工业界的完全体。它的存在本身就是对"自我改进为什么首先在代码/数学领域成立"的最好注解：**验证器便宜且可靠的地方，自我改进就先成立**。

## 四、放进课程主线里看

四篇工作排开，正好是一条递进链：

| 工作 | 被改进的对象 | 选择压力（验证器） | 探索机制 |
|---|---|---|---|
| ADAS | agent 设计（提示/工具/工作流） | 任务基准分数 | 元智能体 + 发现档案 |
| DGM | agent 自身代码库（含自我修改能力） | SWE-bench / Polyglot | 开放式 agent 档案树 |
| AI Scientist | 科研产物（想法→论文全链条） | 自动审稿人（弱验证） | 迭代式想法链 |
| AlphaEvolve | 算法与生产代码 | 自动化可执行评估（强验证） | LLM 集成 + 进化数据库 |

两个贯穿性结论：

1. **验证器强度决定自我改进的上限**。AlphaEvolve（可执行、可量化的评估）成绩最硬；DGM/ADAS（基准分数）次之；AI Scientist（LLM 自动审稿，弱验证）最不稳定。这正是 L03「鲁棒验证」在整个课程最高抽象层的回响。
2. **开放式探索与自我改进缺一不可**。DGM 的消融实验证明：去掉档案机制（只贪心改当前最优）或去掉自我修改，性能都显著下降——多样性维护和 Mountain Climbing 同样重要。

## 五、这一主题为什么可能是整门课最"名不副实"的部分

课表把这讲叫"自我改进智能体的开放式进化"，听着像 AGI 前夜。冷静看论文里的证据：

- **所有成功案例都发生在验证便宜且客观的窄域**。矩阵乘法、调度启发式、kernel 优化——都有精确适应度函数。AI Scientist 一旦进入"想法好不好"这种弱验证环节，产出就滑向增量式灌水。没有任何一篇论文展示了在开放、主观、长时程任务上的持续自我改进。
- **"自我改进"目前仍是外循环**。DGM 改的是自己的代码库，但改进的能力边界（基础模型本身）是冻结的；AlphaEvolve 的"智能"来自被冻结的 Gemini——权重层面的自我改进并未发生。
- **自动科研的产出质量被高估**。AI Scientist 的"超过接收线"是自动审稿人自己的评分；社区复现与后续分析普遍指出其想法新颖性有限、引用与实验细节错误频发。
- **成本与失控风险真实存在**。自我修改代码的系统需要沙箱与人类监督（DGM 论文明确写了这一点）；评估成本随搜索深度线性甚至超线性增长。

一句话：这是目前"能 work 的自我改进"的最远边界，但边界恰好画在"有可靠验证器"的地方——这门课自己的逻辑已经解释了为什么。

## 六、如果自己动手

1. **从有自动评估器的问题入手**。选一个能用脚本打分的任务（编程题、数学答案、配置文件性能），先写评估器再谈进化——评估器质量就是天花板。
2. **复现 ADAS 的最小版本**：一个 while 循环 + 一个 agent 档案 + "参考档案发明新 agent"的元提示词，几十行代码就能跑起来（官方代码已开源：github.com/ShengranHu/ADAS）。
3. **维护档案，不要贪心**。始终保存历史全部变体并从中采样父代，而不是只改当前最优——DGM 的消融证明开放式探索贡献了实打实的增益。
4. **LLM 集成分工**：便宜模型跑广度（大量变异），强模型跑深度（关键改进），与 AlphaEvolve 的 Flash/Pro 分工同构，能显著压成本。
5. **沙箱先行**。任何让 AI 改自己代码的实验，第一步是容器隔离 + 人工检查产出，这是 DGM 与 ADAS 论文共同的标准做法。

## 七、延伸阅读

- **FunSearch**（2023，DeepMind）：AlphaEvolve 的前身，LLM+进化发现单函数
- **AlphaTensor**（2022，DeepMind）：RL 发现矩阵乘法算法，AlphaEvolve 的对比基线
- **STOP: Self-Taught Optimizer**（Zelikman et al. 2023）：更早的"脚手架自我改进"探索
- **Quality-Diversity / MAP-Elites** 与 **Novelty Search**（Lehman & Stanley）：档案机制与开放式探索的算法源头
- **Voyager**（Wang et al. 2023）：Minecraft 中的开放式技能库积累，agent 自我课程学习的代表
