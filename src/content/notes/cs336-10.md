## 1. 推理请求的生命周期

对 prompt 长度 $T_p$、输出长度 $T_o$：

1. **排队/调度**：等待进入 batch；
2. **Prefill**：并行处理全部 prompt tokens，建立每层 KV cache；
3. **Decode**：每一步输入最新 token 和 KV cache，生成一个新 token；
4. **终止/回收**：遇到 EOS、长度或外部取消，释放 cache pages。

Prefill 与训练前向类似，有大矩阵和序列并行，常 compute-bound；decode 有严格 token 依赖，每步矩阵的 batch/token 维小，需反复读取权重和历史 KV，常 memory-bound。

## 2. 关键服务指标

- **TTFT**（time to first token）：排队 + prefill + 第一次采样；
- **TPOT/ITL**：相邻输出 token 的时间；
- **End-to-end latency**：完整请求耗时；
- **Throughput**：系统每秒完成的 prompt/output tokens 或 requests；
- **Goodput**：满足 SLO（如 TTFT/TPOT 上限）的有效吞吐；
- **Cost/token、能耗/token**；
- **尾延迟**：p95/p99，而不只是平均值。

提高 batch 常增加 throughput，却可能增加排队和单请求延迟。服务优化是多目标约束，不存在脱离 workload 的“最快模型”。

## 3. 推理的 Arithmetic Intensity

### 3.1 MLP/线性层

权重 $W\in\mathbb R^{D\times F}$，一次处理 $M$ tokens：

$$
\text{FLOPs}\approx2MDF.
$$

若主要 bytes 是读取一次权重和读写 activation：

$$
I\approx\frac{2MDF}{b(DF+MD+MF)}.
$$

当权重项占主导，$I\approx2M/b$。因此 decode batch/token 数 $M$ 越大，权重可被更多 tokens 复用，越可能从 bandwidth-bound 走向 compute-bound。

### 3.2 Attention

Prefill 可用 FlashAttention 对整个序列做大 tile 计算。Decode 每层每步要读取 K/V cache：

$$
M_{KV,layer}=2BT H_{kv}d_h b.
$$

上下文 $T$ 增长时，每个新 token 的 cache 读取线性增长；即使 attention FLOPs 不占总量最大，KV 带宽和容量也会限制 batch。

## 4. KV Cache 的精确账本

总 KV cache：

$$
M_{KV}=2LBT H_{kv}d_h b,
$$

$L$ 为层数，$B$ 为并发序列，$b$ 为每元素 bytes。它决定：

- 单 GPU 可承载多少并发；
- 长 prompt 是否需要 context parallel/offload；
- continuous batching 是否被 cache 容量而非 FLOPs 限制。

预留最大长度会产生巨大浪费，PagedAttention 因而重要。

## 5. 减少 KV Cache（无须量化模型）

### 5.1 GQA/MQA

把 $H_q$ 个 query heads 映射到较少 $H_{kv}$：

$$
\text{cache reduction}=H_q/H_{kv}.
$$

MQA 为 $H_{kv}=1$；GQA 是质量与带宽折中。需要在训练/转换时支持，不能在任意 MHA checkpoint 上无损直接改头数。

### 5.2 MLA

把 K/V 压成 latent：

$$
c_t=W_{down}h_t,qquad K_t=W_K^{up}c_t,quad V_t=W_V^{up}c_t.
$$

cache 只存 $c_t$ 及必要的位置部分。通过代数吸收投影，可避免每步显式恢复完整 K，但 RoPE 的位置相关旋转不能简单与固定权重合并，需拆出 decoupled RoPE 分量。

### 5.3 Cross-Layer Attention（CLA）

若若干相邻层共享 K/V，cache 可按共享组数缩小。代价是层间表示自由度下降；共享方式必须在训练中学习。

### 5.4 Sliding Window / Hybrid Attention

局部层只保留最近 $w$ tokens：cache 从 $O(T)$ 降为 $O(w)$。每若干层插 full attention 维持全局路径。需要分析某条信息经过多少层才能跨越窗口，以及 full layers 是否仍主导峰值。

### 5.5 DeepSeek 新型注意力方向

课件讨论了进一步压缩/选择历史的 attention 设计。统一评估维度仍是：每 token 缓存字节、每步读取字节、恢复计算、位置编码兼容性和质量，而不是只比较命名。

## 6. 量化（有损捷径）

把权重近似为：

$$
W\approx s(q-z),
$$

$q$ 是低 bit 整数，$s$ scale，$z$ zero point。推理量化可分：

- weight-only：权重低位，activation 保持 BF16/FP16；
- weight+activation：需要处理 activation outliers 和动态 scale；
- KV-cache quantization：直接降低长上下文 cache bytes。

### 6.1 AWQ

Activation-Aware Weight Quantization 的核心观察：少量与大 activation 相乘的权重通道对误差特别敏感。通过 activation calibration 选择 per-channel scaling，在不真正保留大量高精度权重的情况下保护显著通道，再做 group-wise quantization。

评估必须包括 perplexity、任务、不同 context、真实 kernel throughput 和 dequant 开销。压缩 4 倍不代表 latency 4 倍提升：小 batch 可能受益显著，大 batch 已 compute-bound 时收益有限。

## 7. Pruning 与 Distillation（有损）

### 7.1 非结构化剪枝

把小权重设零可减少参数“有效数量”，但若硬件仍执行 dense GEMM，就不减少实际 FLOPs。只有达到硬件支持的 N:M sparsity 或使用高效 sparse kernel 才可能加速。

### 7.2 结构化剪枝

删 heads、channels、MLP neurons 或 layers，直接改变 dense shape，更容易兑现速度；但不同组件敏感度不同，通常需要校准和恢复训练。

### 7.3 Distillation

student 学 teacher 的 soft distribution、hidden 或生成数据：

$$
\mathcal L=(1-\lambda)\mathcal L_{hard}
+\lambda\tau^2\operatorname{KL}
(p_T^\tau\|p_S^\tau).
$$

得到更小模型后可永久降低推理成本，但质量/覆盖范围受 teacher 数据和 student capacity 限制。

## 8. Speculative Sampling（保持目标分布）

用便宜 draft 模型 $q$ 提议 $K$ 个 tokens，再让 target $p$ 一次并行评分。

### 8.1 接受规则

对第 $i$ 个 draft token $x_i$：

$$
a_i=\min\left(1,\frac{p(x_i\mid prefix)}{q(x_i\mid prefix)}\right).
$$

以概率 $a_i$ 接受；一旦拒绝，从修正分布采样：

$$
r(x)\propto\max(0,p(x)-q(x)).
$$

若全部 $K$ 个接受，再从 target 的下一位置分布采一个 token。该 rejection-sampling 修正确保最终样本精确来自 $p$，不是近似 draft 分布。

### 8.2 何时加速

收益要求：

- draft 足够快；
- $q$ 与 $p$ 接近，平均接受长度高；
- target 能并行验证多 token，增加的 prefill-like 计算小于节省的 decode steps；
- 调度、KV rollback 和采样实现高效。

draft 太差时会多做计算。也可用目标模型的多 token heads、EAGLE 类 feature draft 等减少独立 draft 成本。

## 9. Continuous Batching

静态 batching 等最慢请求结束后才换 batch，短请求结束产生空槽。Continuous batching 在 token step 边界：

1. 移除完成请求；
2. 释放其 KV pages；
3. 加入新请求或 chunked prefill；
4. 重新组成当前 iteration 的 token batch。

它提高 GPU 占用并减少 head-of-line blocking，但调度器必须平衡：

- prefill 很大，可能阻塞 decode 的 TPOT；
- decode 请求数量影响权重复用；
- 长请求可能饥饿短请求或相反；
- SLO、优先级和公平性。

Chunked prefill 把大 prompt 切成块，与 decode tokens 混合，限制单 iteration 的 prefill 工作量。

## 10. PagedAttention

传统做法为每请求预留 `[max_length]` 连续 KV，造成内部碎片，并难以增长。PagedAttention 把逻辑 token 位置映射到固定大小 physical blocks：

```text
request logical block table
  logical block 0 → physical page 17
  logical block 1 → physical page 3
  ...
```

优点：

- 只随实际长度分配；
- 不要求物理连续；
- 请求结束可立即回收 pages；
- beam search / parallel samples 可 copy-on-write 共享 prompt pages；
- prefix caching 可跨请求共享相同前缀。

attention kernel 要按 block table gather K/V；page 太小会增加表和不连续访问，太大增加内部碎片。它是虚拟内存思想在 KV cache 上的应用。

## 11. Prefix Caching 与 KV 复用

对共同 system prompt 或共享文档前缀，可按 token block hash 查找已有 KV pages。安全复用要求：

- tokenizer、model weights、adapter、position、rope scaling 完全一致；
- prefix token 序列逐 token 相同；
- cache 生命周期和权限隔离正确。

命中率取决于 workload；随机用户 prompt 上收益可能很低，固定 agent/system template 上很高。

## 12. Prefill–Decode 调度与分离

Prefill 偏 compute-bound、decode 偏 bandwidth-bound，混在同一 GPU 会互相干扰。可：

- 在同一 engine 中 chunk/interleave；
- 或 disaggregate 到不同 GPU pools，prefill 后通过网络传 KV cache。

后者可独立扩缩容和优化，但 KV 传输量大，网络/序列化/故障处理成为新瓶颈。是否有益取决于 prompt/output 比例和拓扑。

## 13. 推理优化的验收矩阵

必须固定：模型、采样参数、prompt/output 长度分布、并发、硬件、精度、SLO。至少报告：

- TTFT、TPOT、E2E 的 median/p95/p99；
- input/output tokens/s 与 goodput；
- 峰值 KV/总显存；
- quality/perplexity 或分布精确性；
- 不同 batch、context、arrival rate 的曲线；
- scheduler 饱和点和 OOM/拒绝率。

## 14. 常见误区

- Prefill 和 decode 不能用同一个 arithmetic-intensity 结论概括。
- tokens/s 不说明单请求体验，必须同时看 TTFT/TPOT 和尾延迟。
- KV cache 不只占容量，每个 decode step 还要读它。
- 量化模型变小不保证 kernel 和硬件能实现等比例加速。
- 非结构化稀疏若仍跑 dense GEMM，没有真实 FLOPs 收益。
- 普通“让小模型写、 大模型检查”不一定精确；speculative sampling 的接受/修正规则才保证目标分布。
- Continuous batching 不是无限加请求，最终受 HBM、KV 容量和 SLO 限制。
- PagedAttention 解决分配/碎片，不改变 attention 的数学复杂度。

本讲的统一思路是先识别请求阶段，再针对主导资源：prefill 优化计算密度，decode 优化权重/KV 带宽，服务层优化动态调度和内存碎片；最后用质量与 SLO 约束判断捷径是否真正有价值。
