## 一、本讲要解决什么问题（TL;DR）

本讲是整门课的"地图"：先用约 20 分钟把 2018—2025 年大语言模型的能力来源梳理成一条主线——**预训练 Scaling Law → 少样本/零样本 → 思维链（chain of thought）→ 指令微调（instruction tuning）与 RLHF → 推理时扩展（inference / test-time scaling）**，说明"把模型做大"这条路为什么开始碰壁、以及"在推理时多花算力"为什么成为新前沿。随后用约 20 分钟讲清楚**从聊天机器人到 Agent 工作流**的跃迁：目标（goal）、规划（planning）、工具调用（tool calls）、验证器（verifier）与自我纠错（self-correction）如何把单轮对话变成端到端完成任务的智能体，并给出编码 Agent、客服、深度研究、AI 科学家四类落地场景。最后约 10 分钟讲课程机制（三次作业 + 课程项目、评分、里程碑、海报日）。核心问题一句话：**当模型已经"知道"的比它一次回答所能展现的更多时，我们如何通过推理时扩展与自我改进把这些能力榨出来，并让它真正替你完成任务。**

## 二、核心概念与术语

- **Scaling Law（规模化定律）**：模型测试损失随**算力、数据量、参数量**三个轴的增长呈可预测下降的规律。是 2018—2024 年所有基础模型（foundation model）投入决策的依据；本讲指出它"直到去年开始触及某种饱和点"。
- **零样本学习（zero-shot learning）**：只给任务描述（如 "translate English to French" + "cheese"）不给示例，模型直接给出答案。
- **少样本学习（few-shot learning）**：在任务描述之外再给若干示例，模型照模板作答。价值在于**极大降低原型验证成本**——不必为特定领域微调。
- **涌现行为（emergent behavior）**：在小模型上不存在、模型变大后才"突然"出现的能力（如推理、模运算、单词重组）。关键在于它**不可预测**，只能把模型训大后才发现。
- **思维链（chain of thought, CoT）**：在示例里不只给答案，还展示推导过程（如 "Roger 有 5 个球，2 罐 × 3 个 = 6，5 + 6 = 11"），让模型学会"走过程"。它是后续所有推理模型/思考模型的地基。
- **指令微调（instruction tuning）**：用"指令 + 问答对"（人类生成 + 模板 + 合成数据）微调，使模型学会遵循问题并作答；也包含 CoT 微调（展示推导过程再给结果）。
- **RLHF（reinforcement learning from human feedback，人类反馈强化学习）**：不直接监督标签，而是先让人（有时是专家，有时是普通标注者）对模型多个答案打分排序，训练出**奖励模型（reward model）**，再用它引导 LLM 参数。奖励维度包括正确性、有用性（helpfulness）、具体性（specificity）、无害性（harmlessness），可加权组合。
- **推理时扩展（inference scaling / test-time scaling）**：**不动模型参数**，只在推理阶段用重复采样、并行生成等手段换更高准确率。
- **Large Language Monkeys（大模型猴子）**：Azalia 实验室的推理时扩展工作，灵感来自"无限猴子定理"——把 LLM 当猴子，对同一问题重复采样 N 次，再由选择机制挑出正确解。
- **覆盖率（coverage / pass@K）**：N 个采样中**至少一个正确**的问题占比。
- **pass@1**：模型**一次就答对**的准确率，是推理模型提升的目标指标。
- **验证器（verifier）**：能客观判定输出对错的东西，如代码的单元测试、数学的已知答案。有一整讲专门讲验证器。
- **生成器—验证器差距（generator-verifier gap）**：模型很容易产出一大堆看似合理的推理链，但判断其有用与否需要反馈回路；在创意写作这类领域，人类反馈成为瓶颈。
- **Agentic workflows（智能体工作流）**：把 LLM 调用、工具调用、验证器、评判者（judge）编排成图，端到端完成任务。
- **编排者—执行者（orchestrator-workers）**：由中央 LLM 做规划与调度，其它 LLM/工具执行子任务。
- **Outcome / Process Reward Model（结果奖励模型 / 过程奖励模型）**：对最终答案打分 vs 对推理中间步骤打分，是训练推理模型的关键区分（后续讲座展开）。

## 三、主线内容

### 3.1 Scaling Law 三条轴（约 02:08—04:11）
屏幕上三张图：横轴算力增加 → 测试损失下降；横轴数据集规模增加 → 测试损失继续下降；第三个轴是**参数量**（增加 transformer 层数或参数量）→ 损失下降。讲师强调这是从 GPT-3 一直到 PaLM、Gemini、ChatGPT 的"基础"，**但到去年开始碰到某种饱和**（"starting to hit some kind of a saturation point"）。

模型规模时间线（原样保留）：**BERT 3.4 亿参数 → GPT-2 15 亿 → GPT-3 1750 亿 → PaLM 5400 亿 → GPT-4 估计为万亿级**。"large 就大在它们一直在变大"。规模增长带来三件事：① 在自然语言/推理等各类 benchmark 上持续变好；② 学会少样本学习；③ 出现推理等涌现行为。

### 3.2 零样本 / 少样本 / 思维链（约 05:11—10:15）
举例：任务 "translate English to French"，零样本是直接问 "cheese"；少样本是先给几组英法对照再问。**思维链的关键实验观察**：LaMDA、GPT、PaLM 三个模型在小规模时（如 8B、7B）**无法从 CoT 获益**（给了推理过程也没用），规模变大后才能利用上下文里的推导过程提升解题率（转写此处说 "PaLM 模型在 8B 时可利用 CoT"，与上下文矛盾，待核对）。同样地，模运算（modular arithmetic）、单词重组（word unscramble）等能力也是在某一规模上**突然出现**的。这也是前沿实验室仍愿意继续推 scaling 的理由：不只是损失曲线的自然外推，还可能有更多涌现行为。

### 3.3 指令微调与 RLHF：ChatGPT 的配方（约 10:15—19:29）
- ChatGPT 于 **2022 年 11 月**发布，**达到 100 万用户只用了 5 天**，远快于其他知名软件/服务。
- 训练流程四步：① **预训练**（next token prediction，喂所有文本数据）；② **在更高质量数据上继续微调**（书籍、创意散文等，公司为此付数百万甚至上亿美元买数据）；③ **指令微调**（指令 + 问答对，含 CoT 微调，数据由人工生成 + 模板 + 合成数据构成，数据集的质量与泛化性对模型质量影响极大）；④ **RLHF**（用人类偏好数据训奖励模型，再用奖励模型引导 LLM 参数；不同奖励可按侧重点加权）。
- 对齐（alignment）层面：预训练模型"统计上知道世界的状态"，但没有是非观、不会遵循指令；用精心标注的 **sensibleness（合理性）/ safety（安全性）**等高质数据微调可提升对齐度，但讲师明确说**这个问题至今没有被解决**。

### 3.4 为什么"继续扩大模型"遇到瓶颈，转向推理时扩展（约 19:29—27:38）
转折点：过去一年到一年半，**推理（inference）本身也成了提升模型能力的前沿**。
- **Large Language Monkeys**：把 LLM 当猴子，对同一输入问题反复采样（parallel sampling / parallel generation），再用验证器或选择机制挑出正确的那个。模型生成有方差，可用 **temperature** 控制多样性。
- **关键实验结果**：在数学与代码 benchmark 上，把每题采样数从 1 提到 **10,000**，画"覆盖率 = 至少一个采样解出的问题比例"曲线。红色虚线是 **GPT-4o**；蓝/绿线是 **Llama 3 8B 与 7B**（转写此处命名含混，待核对）——它们在**单样本时不如 GPT-4o**，但当样本数增加后，在**所有这些任务上都超过了 GPT-4o**。结论："模型已经知道的，远多于你只问它一次所能得到的。"
- 其中某些难题，10,000 个解里**只有 3—4 个是对的**，可见推理扩展对触及模型真实能力上限有多关键。
- 与学生的 Q&A（保留要点）：
  - 采样空间远大于可穷举范围（树搜索/随机搜索都"远不够"），所以 **10,000 次采样依然是高样本效率的**；部分 FrontierMath（转写记作 F2F，待核对）题目是 IMO 级别难题。
  - **延迟与成本**：并行采样可在并行硬件上跑，延迟问题较小，但**计算成本与收益的权衡**取决于问题类型与复杂度，后续讲座展开。
  - **无验证器时**怎么办：靠训练 LLM-as-judge / LLM 奖励函数 / 带工具的 LLM——课程有专门一讲讲验证器。
  - **temperature 上限**：一般**超过 1.2 就不好了**，输出会变成乱码；需要其它技巧增加多样性（此处有一条相关的调温研究，未给出处）。

### 3.5 推理时扩展 × 微调 = 自我改进（约 27:38—31:41）
- **DeepSeek**（讲师说发布于 **2024 年 12 月**，待核对）与 o1 系列、Gemini thinking 的核心创新：**把测试时扩展和微调接成一个闭环**——在测试时扩展中，让模型对数学题（知道标准答案）或代码题生成大量正确推导轨迹，把这些**合成数据回流进训练集**再去微调模型。讲师称这就是"**self-improving piece**"，且是"开放式的、看不到边界"的方向。
- 指标差异：Large Language Monkeys 在有验证器时看的是 **coverage，随样本数呈 log-linear 增长**；OpenAI 发布 **o1（去年 9 月）**时展示的是 **pass@1 随测试时算力（横轴为 log scale）同样呈 log-linear 上升**，且**不改变模型参数量**。
- 沿革对比：过去 scaling 只在训练侧被验证，**同样的规律适用于测试时**这一点很新颖。

### 3.6 推理模型在做什么（约 31:41—35:45）
对人类而言，难题需要"想更久、试更多策略"，思考型模型同理。典型步骤：**问题分析（problem analysis）→ 任务分解（task decomposition）→ 自我演化策略（self-evolution strategies，跑测试/用计算器/自我评判获得反馈）→ 自我纠错（self-correction）→ 备选方案与回溯（alternative proposals / backtracking）**。

举例（o1 写"矩阵转置"的 bash 脚本）：模型先像人一样思考"用户要的是 bash 脚本，先搞清楚矩阵的输入输出格式"，再做分解（解析输入、把矩阵建成数组的数组），中途还会自我纠错——在思考轨迹里出现"**Wait，这里可能有问题，也许我需要修一下**"这类话，讲师称这"非常常见、也非常酷"。

能力边界：推理模型（如 o1）相对 GPT-4o 在**数学计算、数据分析、编程**上明显更强，但**在个人写作、文本编辑上未必更强**。

学生提问"究竟是推理过程本身，还是'分步思考'这个指令在起作用"，两位讲师的回答（值得记）：
- Azalia：数据让模型成为**泛化的思考者（generalized thinker）**，分解、回溯、分析这些技能是在思考优化过程中习得并泛化的。
- Aakanksha：基础模型预训练后**本来就能做一定的推理，但它不知道哪条推理链是对的**；训练时/测试时扩展的本质就是**让它学会哪一条是对的**——所以提升的是 **pass@1**，而不只是重复采样下的 coverage/pass@K。
- 另一条观察：生成这些"深度思考"很贵，但仍然值得，因为它带来更好的答案。

### 3.7 从聊天机器人到 Agent 工作流（约 40:49—50:59）
- **为什么需要 Agent**：LLM 作为聊天机器人或推理模型，本质上仍是**单轮的、聊天形态的**，"好玩，但不一定替你完成任务"。
- **今年的变化**：Claude Code、Deep Research 这类 Agent 开始能端到端跑真实工作流。例：让模型研究"在斯坦福上课、要在哪租一整年的房子"，它会分析、浏览大量网站、汇总并给出各方案的利弊；Claude Code / OpenAI 的 **Codex** 让工程师用英文指令就能改文件、找测试用例，已成为日常编码生产力工具。
- **LLM → Agent 的定义差别**：给定**目标** → 规划步骤 → 与环境交互 → 依据反馈修正步骤 → 达成目标或回报"我做不到"；关键是**知道何时停止**。这通常还需要**外部工具调用**（搜索、天气等）和某种形式的**记忆**来跟踪任务。
- **现实是"静态工作流"居多**：常见形态是"一个模型产出方案、另一个模型当评判者决定接不接受"；Deep Research 更像"对多个输入各调一次 LLM，再聚合输出成综述"。讲师直言：对开放式问题，**手工搭出这张图（人类会怎么做）+ 用 LLM 当评估器给反馈**比开放式自主循环更容易落地；目前只在编码、研究等少数场景"看到生命迹象"。
- **工作流的组成元件**：LLM 调用、验证器（verifier，有专讲）、批评者/评判者（critic / judge，即 LLM-as-a-judge）、工具调用（web 搜索、天气查询等）。
- **四种典型编排模式**（原话要点）：
  1. **提示链（prompt chaining）**：把端到端目标拆成一串子任务依次执行。
  2. **路由（routing）**：复杂输入走更复杂的 LLM 调用链，简单输入走简化流程。
  3. **并行化（parallelization）**：如 Deep Research 让多个 LLM 调用同时研究不同关键词再聚合；或把任务拆成独立子任务后合并结果。
  4. **编排者—执行者（orchestrator-workers）**：中央 "LLM 经理"先做规划，再发起后续调用（Claude Code 的 plan 模式即此类）。
  另加**评判者（evaluator/judge，用 LLM 代替单元测试或真人反馈）**与**验证器（如跑单元测试）**；在**数学、代码等可验证的规则型领域**，验证是把反馈还给模型、让它纠错的好办法。
- **对模型的三点新要求**：更强的**规划**、更强的**多步推理**、更强的**自我改进/自我纠错**——这些是当前仅靠 reasoning 的模型尚未很好做到的，也是后续讲座的主题。
- **编码 Agent 具体形态**：Agent 通过**终端**与计算机交互，做仓库导航、文件搜索、查看文件、编辑行、执行命令，再根据输出决定下一步去改/看哪个文件。讲师自评：这个循环**去年还很不可靠，今年开始变得可靠**。原因归结为三点：**更强的模型 + 更好的 RL（带可验证奖励的 RL 起作用了）+ 训练时扩展有效**；一旦模型变好，**自我改进回路就启动**了——可以生成任务，任务本身也变得更可靠。例证是去年的 **CodeMonkeys**：为模型生成的代码生成单元测试，看这些测试是否让结果变好。
- **生成器—验证器差距（generator-verifier gap）**：产出一堆内容容易，判断是否有用需要反馈回路。**创意写作这类领域人类反馈成为瓶颈**；只有在"能拿到好反馈"的领域才能持续改进，而**鲁棒的验证本身就很难**。Azalia 会讲她实验室一篇关于**如何组合多个验证器**的论文。

### 3.8 三类落地场景（约 54:02—58:05）
1. **编码**：适合高度重复的任务——**代码迁移、版本升级、重构代码库**；数据工程里的抽取、清洗、**数据仓库迁移**；以及单元测试编写。
2. **客服**：实时转写（会议场景已普及）、**知识辅助**（客服不必什么都懂，让 LLM 从资料库里捞出相关文章，优于单纯的索引+搜索）、智能回复（smart replies）、通话摘要。多家公司在这个方向竞争。
3. **深度研究与报告**：过去做文献综述要读论文、逐篇总结、再综合；现在可以交给 LLM，而且**能比人读更多文章**。例子：**2022 年冬奥会开幕式**——先识别要查哪些引用、构造大纲、逐篇总结相关内容、再合成一篇完整长文（这是**作业之一**）。更前瞻的是 **AI scientist**：LLM 用于**想法生成（idea generation）**、**实验迭代（experiment iteration）**、**论文撰写（paper write-up）**（出自 *AI Scientist* 论文）。讲师补充：即便模型会幻觉，它能提出**跳出框框的想法**，作为头脑风暴伙伴很有价值。

## 四、讲师的关键论断（带时间戳）

- **[02:08]** 规模化有三条轴：算力、数据集规模、参数量，任一增大都能让测试损失下降；这套规律是 GPT-3 之后所有模型的基础，"但直到去年开始触及某种饱和点"。
- **[04:11]** 规模爆炸史：BERT 3.4 亿 → GPT-2 15 亿 → GPT-3 1750 亿 → PaLM 5400 亿 → GPT-4 估计万亿级（"The large stands for that they're growing in size"）。
- **[05:11]** 模型变大的三个后果：benchmark 持续变好、学会少样本学习、出现推理等**涌现行为**——"reasoning only emerge in larger models"。
- **[07:12]** 思维链的本质：不只给答案，而是"walk the model through how to get to this"；这个性质"到今天依然成立，是推理模型和思考模型最重要的一项性质"。
- **[10:15]** ChatGPT 2022 年 11 月发布，**5 天达到 100 万用户**；除了把模型做大，**指令微调与 RLHF 是让它跃过 GPT-3 的两块关键创新**。
- **[22:32]** "**模型已经知道的，远多于你只问它一次所能得到的**"（"models already know a whole lot more than what you get out of them when you just ask them once"）——Llama 3 8B/7B 在单样本时不如 GPT-4o，但采样数增加后在**所有任务上**反超。
- **[23:33]** 推理时扩展的定义："**we're not touching any of the parameters of the model**"，模型固定，只在推理时改变生成方式。
- **[27:38]** 温度经验值："usually, if you go beyond like **1.2** or so, it's not great"（再高就是乱码）。
- **[28:38]** 自我改进闭环：把测试时扩展中生成的大量合成数据"**becomes part of our training set now**"再微调——"that's kind of the self-improving piece that we are very excited about"。
- **[30:40]** o1 的展示：在困难的 **AIME**（转写作 Amy）benchmark 上，**pass@1 随测试时算力（log scale）呈 log-linear 上升**，且"without changing the parameter count of the model"。
- **[36:45]** 训练/测试时扩展的本质：基础模型本就能做推理，但"**it doesn't quite know which one is correct**"，扩展的价值是"learns which is correct"，因此提升的是 **pass@1** 而非 coverage。
- **[37:46]** 模型"更喜欢自己的推理轨迹"（"they like their own traces more"），即便轨迹来自更好的模型——这条会与 **SWiRL**（转写作 swirl，待核对）等论文一起讨论。
- **[41:51]** Agent 与聊天机器人的分界：有目标、会规划步骤、与环境交互、按反馈纠错、**并知道何时停止**（"deciding when to stop"）。
- **[43:53]** 对落地现实的判断：大多数场景仍是**静态的 agentic workflows**（一个模型产出、另一个模型评判 / 多路调用再聚合），而不是开放式自主循环；目前只在编码和研究等少数场景"看到生命迹象"。
- **[47:57]** 编码 Agent 变可靠的三个原因："**more powerful models, and then better RL. RL with verifiable rewards is working. The train time scaling is working well.**"——之后自我改进回路启动。
- **[49:58]** 生成器—验证器差距："it's easy for models to generate a whole bunch of nonsense... **human feedback ends up becoming a bottleneck**"；只有能拿到好反馈的领域才能持续改进，而鲁棒验证本身很难。
- **[58:05]** 思维链的来源澄清：CoT **不是设计出来的**，是被发现的——"**GSM8K was the first paper that kind of showed signs of life**"，到 PaLM 规模才成为大事（能解释笑话）；但**推理模型是"被训练得越来越会思考"的**，两者要区分开。
- **[51:59]** 关于 RL 与预训练数据多样性谁在起作用："**I don't think there's single point of consensus**"，两者都有帮助，整个回路"not completely well understood"。

## 六、动手启示

1. **先测 coverage 再谈能力上限**。想判断一个模型"是否已经会做"某类题，别只看 pass@1：在允许的温度下采样数百到数千次，看覆盖率曲线。如果 coverage 明显高于 pass@1，说明瓶颈在"选对"，而不在"会不会"。
2. **优先挑有验证器的领域做项目**。代码（单元测试）、数学（标准答案）这类可验证领域能形成"生成 → 验证 → 回流微调"的闭环；创意写作这类反馈稀缺的领域，人类反馈会成为瓶颈。
3. **temperature 有硬上限**。经验值是不要超过约 **1.2**，再高输出会退化成乱码；需要多样性时应改用其它技巧（不同提示/不同分解方式），而不是一味升温。
4. **做智能体先画静态图，再谈自主循环**。按"提示链 → 路由 → 并行化 → 编排者—执行者"的顺序由简到繁搭，用 LLM-as-judge 或单元测试当反馈源；把"用户意图澄清"作为流程的第一环，因为用户往往描述不清任务。
5. **把"何时停止"显式写进智能体设计**。Agent 与聊天机器人的分界线之一就是能否判断任务已完成或不可完成并回报，而不是无限循环。
6. **从课程论文里找项目选题**。对某篇论文的一个设计决策提出质疑并重新评估，是被明确鼓励的项目形式；也可直接拿现有 benchmark 做 hill-climbing。

## 七、遗留问题与开放挑战

- **RL 与预训练数据多样性，谁才是能力提升的主因**：两位讲师明确说"**目前没有共识**"，两者都有帮助（51:59）。
- **"采样出正确解 → 用反馈训练 → pass@1 提升"这个闭环为何能成立**：按朴素理解，反馈只应提高 pass@1 而不应提升模型本身的能力，但这个跳跃很大、机理"**not completely well understood**"，属于"刚看到生命迹象、已经开始商业化"的阶段（51:59）。
- **推理模型到底是怎么被教会推理的**：讲师说"**没有一篇发表的工作真正覆盖这一点**"，推测是"两者兼有"——既有人工整理的 CoT/模板做自举（bootstrapping），也依赖模型在微调中的泛化，模型能力已远超训练数据与指令本身（38:47）。
- **能否让采样次数随问题难度自适应**："没有已发表的工作做到这一点"；后续工作尝试用带复杂度概念的奖励模型来指导"是否继续采样/是重复还是并行"，但仍是开放方向（39:48）。
- **验证（verification）仍是核心瓶颈**：产出容易、判定难；在创意写作等不可验证领域，人类反馈成为瓶颈；如何组合多个验证器（Azalia 实验室的论文会讲）——"**what verification continues to be one of the bottlenecks in this space**"（49:58）。
- **推理时扩展的成本—收益权衡**：延迟靠并行可缓解，但算力开销如何随问题类型与复杂度取舍，**仍未被很好刻画**（26:38）。
- **开放式自主 Agent 仍未跑通**：现实中的系统大多是人工搭建的静态工作流图，只有编码、深度研究等少数场景"看到生命迹象"（43:53）。
- **自我纠错、回溯究竟算涌现还是被强化出来的**：讲师的原话是"是，也不是……**it's hard to say**"（60:06）。
- **除了推理与 CoT，还有哪些涌现行为会被发现**：讲师未给出确定清单，只指出当前在 agentic 工作流中主动寻找的三项能力——**规划、多步推理、自我改进/自我纠错**（59:05—60:06）。
