## 一、本讲要解决什么问题（TL;DR）

当单步"输入提示 → 输出答案"不够用时，模型必须把任务拆成**推理（reasoning）→ 行动（acting）→ 根据反馈搜索/修正（search）**的循环，例如规划一趟夏威夷旅行：推理要做什么、预算多少；行动是搜索 Reddit/旅行博客；再根据收集到的信息回到规划层，考虑替代目的地。本讲用三篇论文回答三个递进的问题：**(1) 如何在测试时用树搜索把"更多推理算力"换成"更好的解"（LATS）；(2) 如何把长思维链中彼此独立的部分识别出来并并行执行，从而压缩顺序生成的 token 数与墙钟延迟（SPRINT）；(3) 如何在训练阶段让模型学会"何时调用工具、如何一步步推理、何时收尾"，并且不依赖昂贵的在线工具执行（SWiRL）。** 贯穿三篇的一条暗线是：**奖励该给谁**——是给最终答案，还是给轨迹里的每一个中间动作。

## 二、核心概念与术语

| 术语 | 一句话定义 | 为什么重要 |
|---|---|---|
| 多步推理与工具使用（multi-step reasoning and tool use） | 模型需连续多轮生成文本、推理、与环境交互后才给出答案 | 现实任务（多跳问答、数据分⁠析、行程规划、软件工程）几乎都是多步的 |
| 树搜索（tree search） | 把候选"动作/思路"展开成一棵树，在树上选择、扩展、评估 | 是把"更多测试时算力"转化为准确率的通用机制 |
| 语言智能体树搜索（LATS, Language Agent Tree Search） | 用语言模型同时做推理、行动与规划，在动作构成的树上做 MCTS 式搜索 | 本讲第一篇，把 RL 里成熟的搜索搬进 LLM 推理 |
| 蒙特卡洛树搜索（MCTS, Monte Carlo Tree Search） | 通过"选择—扩展—模拟—反向传播"反复迭代来估计各节点价值的搜索算法 | 让模型不必一次性赌对，而是可以试错、回溯 |
| UCT（Upper Confidence Bounds applied to Trees） | 选择节点时的打分公式，把"价值高的节点"（利用）和"访问次数少的节点"（探索）加权相加 | 纯贪心会漏掉"当前分低但后续分高"的节点 |
| 价值函数（value function）V(s) | 对某个状态"有多大希望通向成功"的估计 | 树搜索的导航信号；LATS 里由两个分数加权得到 |
| LLM-as-a-judge（模型当裁判） | 直接提示模型给某状态/某动作 0–1 的评分 | 无需训练验证器，成本极低，但依赖提示质量 |
| 自一致性分数（self-consistency score） | 采样 N 次（讲师举例 N=50），某个动作被采到的频率越高，分数越高 | 作为价值函数的第二路信号，廉价且与 judge 互补 |
| 反向传播（back propagation） | 一条轨迹结束后，用其回报增量式更新路径上各状态的价值 | 这是本讲的"信用分配"：把最终结果的好坏折算回中间步骤 |
| 反思（reflection） | 轨迹失败/成功后，让模型自己写一段"我为什么失败/成功"的文字，并追加进上下文 | 讲师说这一步"apparently very helpful"，对效果提升很大 |
| 信用分配（credit assignment） | 把轨迹级回报分摊到具体某一步动作上的问题 | 多步任务的核心难点。**注意：转写全文未出现 "credit assignment" 这个英文词（0 次），但 SWiRL 的逐步奖励、LATS 的反向传播都在处理这个问题** |
| 交错规划与并行执行（interleaved planning and parallelized execution） | 模型先产出若干个彼此独立的计划，再同时执行它们，同步结果后进入下一轮 | SPRINT 的核心：把"顺序生成"改成"规划批次化" |
| 有向无环图（DAG） | 用节点表示推理步骤、边表示依赖关系的图 | SPRINT 用它标注哪些步骤可并行、哪些必须等待 |
| 顺序 token（sequential tokens） | 推理过程中必须按先后串行生成的 token 数量 | SPRINT 的真实优化目标：并行并不省总 token，但省顺序 token（=延迟） |
| 逐步强化学习（SWiRL, Step-Wise Reinforcement Learning） | 把一条多步轨迹拆成 K 个子轨迹，对每个动作单独给奖励再做 RL | 让 RL 从"单步 RLHF"扩展到多步工具使用场景 |
| 过程过滤 / 结果过滤（process-filtered / outcome-filtered） | 前者要求"每一步都被 judge 判定合理"，后者只要求"最终答案正确" | 本讲最反直觉的结论就出在这两者的对比上 |
| 不可逆动作（irreversible actions） | 一旦执行就无法撤销的动作（如付款、下单） | LATS 明确未处理的风险场景 |
| 探索与利用（exploration vs. exploitation） | 是去试新分支，还是深耕当前最优分支 | UCT 与 AB-MCTS 的 "wider/deeper" 都是这个权衡的不同表述 |

## 三、主线内容

### 3.1 开场：为什么需要"推理 + 行动 + 搜索"（00:05–03:10）

多步任务的三段式：

- **推理（reason）**：想清楚要做什么——以旅行规划为例，就是预算多少、行程怎么安排。
- **行动（act）**：基于推理去获取更多信息——浏览网页、生成搜索查询去搜 Reddit 或旅行博客。
- **搜索（search）**：拿到环境反馈后**回头修订计划**——考虑替代目的地、重新搜"到了那边玩什么"。

讲师强调 LATS 想解决的痛点：从"模型生成一个计划然后执行它"，转向"**鼓励生成并探索多样化的计划/路径**"。原话是：模型"至今仍然"弱于"产生多样化的解、并据此行动、以及做多步优化以抵达解"（*"models ... can be weak in creating a diversity of solutions or acting upon them and planning multiple steps of optimization to reach a solution ... and this is true still to this day"*）。LATS 的做法是把**已有的 RL 与多步规划技术（含 MCTS）搬进 LLM 的推理路径**，并让模型把探索过程中从环境拿到的反馈带回后续搜索。

### 3.2 LATS 的六个阶段与一个迷宫例子（07:15–12:22）

LATS 明确列出六个阶段：**选择（selection）→ 扩展（expansion）→ 评估（evaluation）→ 模拟（simulation）→ 反向传播（back propagation）→ 反思（reflection）**。讲师用"在迷宫里走到出口"的提示词完整走了一遍：

1. **初始观察**："你在一个昏暗的房间里，左边一扇门、右边一扇门"，目标是找到出口。
2. **选择**：依据 UCT 选一个待扩展的节点（根节点即初始观察）。
3. **扩展**：从选中节点采样若干动作。本例采样了 3 个——开左门、开右门、检查房间寻找线索。
4. **执行与观察拼接**：每个动作在环境中真实执行，观察结果被追加进上下文（开左门 → "挂满油画的黑暗走廊"）。
5. **评估**（见下节）：给新状态打分，本例状态 A 分最高。
6. **模拟**：从最高分状态继续向下采样扩展，直到到达终止状态（成功/失败）或耗尽扩展预算；本例中走楼梯后"出口门清晰可见"，得分。
7. **反向传播 + 反思**（见下节）。

### 3.3 价值函数、UCT 与反向传播的数学（09:18–16:28）

**价值函数 V(s) 是两个分数的加权平均：**

- **LM 分数**：把 LLM 当裁判，直接提示它"给定这个观察和这个动作，成功概率多大，请给 0 到 1 的分数"。
- **自一致性分数**：假如不是采样 3 个而是采样 **50 个**动作，把同类动作归并，某动作被采样的频率就是它的分数。讲师举例：状态 A 的自一致性分数更高，因为**有 75% 的次数采到了动作 A**。

**UCT 用于"选择"**：公式为 `UCT = V(s) + c · sqrt( ln(N_parent) / n_s )`。其中 `V(s)` 是利用项，`N_parent` 是父节点被访问次数，`n_s` 是当前节点被访问次数，`c` 是超参数。直觉：相对于父节点，某节点被访问得越少，`N_parent/n_s` 越大，探索项越大 → 鼓励去访问它；被访问得越多，该项趋小，UCT 相对未被探索的兄弟节点变低。讲师明确说明这是**从 MCTS 文献直接照搬**的，并且坦承"**没有证据表明它是最优选择**（there's no proof that this is the optimal）"，只是"公认更优化的一种做法"，其背后的动机是：如果只看当前最高价值，可能错过"此刻分低但走下去最终分高"的节点。

**反向传播**：一条轨迹结束（成功或失败）后，用其回报 `return` 更新路径上各状态的价值：
`V_new(s) = [ V_old(s) × (n_s − 1) + return ] / n_s`
即把新回报做一次增量式平均。这一步就是本讲的"信用分配"机制——最终结果的好坏被折算回此前的每一个动作。

**反思**：反向传播之后，模型再生成一段关于"这条轨迹为什么成功/失败"的自述并追加进上下文。讲师说这一步"**显然对整体提升方法质量非常有帮助**（apparently has been very helpful）"。

### 3.4 LATS 与 Math-Shepherd、ReAct 的区别（05:11–07:15）

- **vs. Math-Shepherd**（此前课上讲过）：Math-Shepherd 用一个**验证器（verifier）**在测试时给推理轨迹打分、引导搜索；而 **LATS 的打分不是基于"推理选择"，而是基于"模型所采取行动的结果（outcomes of the actions）"**。
- **vs. ReAct**：LATS 借用了 ReAct 的反馈回路，但在其上叠加了**记忆（memorization）、反思（reflection）**，以及与环境的交互，并且"**把越来越多的规划塞进了这个过程（we have more and more planning into the process）**"。

### 3.5 LATS 的实验与短板（16:28–22:34）

- **HotpotQA**：数据集设计上就要求**至少检索两个不同的维基百科页面**才能作答，天然强制多步。结论：样本/轨迹数量越多，性能显著提升；反思与推理痕迹的引入带来额外大幅增益。
- **WebShop**：一个贴近实际应用的购物数据集（例：找一张"已组装好的小型便携折叠桌，要特定颜色和表面处理，还要比价"），本身就是多步流程。结论：**无需任何微调、纯测试时方法**，结果就能接近人类专家水平。
- **优点**：测试时方法 + 模块化，非常可移植、相对容易搭建。
- **缺点一：成本**。反向传播、树的扩展都在大量加成本，而**论文并没有真正分析成本收益（the cost benefits was not really analyzed in the paper）**。
- **缺点二：不可逆动作**。讲师明确指出论文未处理这一假设——有些动作一旦执行就难以撤回（模型在跑交易、为服务付款等），LATS 这类方法在这类场景下未必适用。

**课堂 Q&A 两条**：
- 学生问：UCT 本质就是 bandit 里的置信上界，论文有没有对比多臂老虎机的其他算法？讲师答：**没有**，多臂老虎机那一整套探索/利用文献都可以搬进来试；作者的主要贡献是"**搭了一个平台，别人可以把其他优化方法接进来**"。
- 学生问：如果出现重复动作序列（A-B-A-B）怎么办？讲师答：设计哲学是——在同一父节点下重复出现的动作会**增加该动作的计数**，而这个计数直接进入 UCT 公式；前提是这里形成的是**树**，不是任意连通图。

### 3.6 SPRINT：动机与观察（23:35–26:38）

- **观察一**：o1、Gemini 2.5 Pro 等前沿推理模型有"**难题想得更久**"的倾向，而更长的思考对应更高的准确率。讲师展示了 **DeepSeek-R1 的训练曲线**：随着训练推进，AIME 类数学题越做越好，**同时每条回答的平均长度也在上升**——思考更长（更多 token）与准确率之间存在相关性。
- **观察二**：这些长思维链里**许多步骤其实是相互独立的**——模型会尝试替代解法、把任务分解成能并行的子任务、或者回头验证前面的步骤。既然独立，就不必等模型把它们一个个顺序生成出来。

SPRINT 是一个**后训练 + 推理时**框架：它让推理模型在生成过程中扮演一个**规划器（planner）**，一次产出一组计划，再由一组**执行器（executor）并行**执行；可以反复进行"一批计划 → 并行执行 → 同步 → 下一批计划"，这种**交错（interleaving）**就是加速的来源。

### 3.7 SPRINT 的数据构造流水线（27:39–31:44）

这是一个"**用 LLM 自己造微调数据来教会模型某种行为**"的范式，讲师特意提醒"要跳出这篇论文看这个套路"：

1. 让 **DeepSeek-R1** 对一批问题生成推理轨迹与回答。
2. 用 **GPT-4o**（转写作 GPT40）去读这些轨迹，**把轨迹切成步骤 1…K**，并**逐步标注哪一段是"计划（plan）"、哪一段是"执行（execution）"**；某些计划下会挂多个执行块。
3. 用模型判断步骤之间的依赖关系，构造出 **DAG**：例如"步骤 4 与步骤 2 互不依赖，但两者都依赖步骤 1"。
4. 据此做**打包（packing）**：步骤 1 先做，步骤 2 和 3 完全并行，等等。
5. 在 DeepSeek-R1-Distill-7B 上做**监督微调（SFT）**：让模型学会先吐出 `plan 1`、再吐出它的执行块、再吐出 `plan 2`……推理时系统识别这些标签，真正并行地跑执行（例如调用计算器或 Python），把结果同步回上下文，再进入 plan i+1。

讲师澄清了两个高频疑问：

- **要回溯修订计划怎么办？** 模型仍然能看到完整上下文，"**如果它想回头推翻某个计划，它照样可以做（if the model wants to go back and reverse on a plan, it still can do that）**"。训练目标只是"**在每一时刻尽可能并行地思考**"——只要 plan 2 与 plan 1 独立，就不要等 plan 1 执行完再生成 plan 2。
- **是不是改了 next-token 预测的结构？** 没有，"**它永远是 next token**"，只是顺序从"计划/执行逐个交替"变成了"plan 1、plan 2 连着生成，再一起执行"。

### 3.8 SPRINT 的训练配方与结果（35:52–49:11）

- **配方**：为数学数据集生成 **6K 条思考轨迹**，保留其中**并行度更高**的那些，在 **DeepSeek-R1-Distill-7B** 上对这些重排后的轨迹做 SFT。（论文侧核对：NeurIPS 2025。）
- **意外收获**：项目初衷是最大化并行度、压缩顺序生成 token，**结果准确率也跟着涨了**——讲师的原话是"这个更结构化的思考方式似乎让模型更准"。具体数字：**在基线 R1-Distill-7B 之上提升了 3.5%**（转写作 "3 and a half% jump"），同时在顺序 token 数上**比一个 32B 模型还要高效得多**。
- **域外泛化**：训练只在数学数据集上做，但在 **Countdown** 和 **GPQA Diamond** 上，模型不仅找到了更多并行机会，准确率也更高——完全没有在这些数据集上训练过。（论文侧核对：GPQA 与 Countdown 上，较长推理轨迹的平均顺序 token 分别最多减少 **45%** 与 **65%**；数学任务在需要 >8000 输出 token 的问题上最多减少 **39%**。转写中讲师口头说的是"数学上约 **40%**"。）
- **收益与难度正相关**：讲师展示了一张"SPRINT 相对 rejection fine-tuning（RFT）基线的顺序 token 缩减"随难度变化的图——**如果思考 token 本来就很少，几乎没有并行空间，SPRINT 甚至可能比基线更差**；收益集中出现在"更难、需要更多思考和更多并行 token"的问题上。
- **两条过程性规律**：① **更难的问题需要更多轮"规划—执行"迭代**（这个符合直觉）；② **更反直觉的一条**——在推理的**早期阶段模型表现出更多并行/探索**，而**后期阶段会收敛到更少的计划**，越到后面越倾向深耕单一计划并执行到底。
- **时代背景注脚**（46:07）：讲师提到 **Sonnet 4.5 的 system card 里鼓励模型尽可能多用工具、至少用 100 次**，说明业界正在进入"解题规模远超 8–10k token"的新阶段。
- **推理时的真实行为**（47:09–49:11）：模型**先把 plan 1 和 plan 2 一次性生成出来**，一旦 plan 1 输出完毕就启动执行，plan 2 输出完也启动执行（二者真正并行，可用工具），结果回写上下文后再生成下两个计划。训练数据里 plan 1、plan 2 是**并排放置**、执行块也并排，以此匹配推理时的形态。

**课堂 Q&A 摘录**：
- **并行分支各自正确、合并后矛盾怎么办？** 无论串行还是并行，最终一切都会 condense 进上下文，模型应在生成最终答案前自行消解冲突；不过讲师补充，SPRINT 里的并行计划"**更像是解决同一个问题的不同步骤，而不是同一问题的不同解法**"，因此这类冲突较少。
- **负载均衡 / straggler？** 无法保证各并行分支耗时相近，仍可能出现慢分支（step 4 远慢于 step 2），但总耗时被限制在"最慢的那一个"而不是"所有之和"。已采取的措施包括：如果某个执行太简单，就把它**并入计划、合并成更大的并行块**。讲师承认"**我不确定论文里是否有针对这一点的专门分析**"。
- **树的宽度是多少？** 讲师答：**视任务而定**，没有给出具体数字；并行度低的任务（相对 GPQA-Diamond，数学的顺序 token 占比更低，说明数学并行空间更小——此处表述在转写中略含混，待核对）收益就小。核心前提是"**并行性必须存在，才用得上这个方法**"。

### 3.9 SWiRL：动机与设计目标（50:13–54:21）

- **动机一**：真实任务（多跳搜索问答、解数学题、软件工程、规划行程、数据分析）都需要**连贯的多步推理 + 工具使用**；单步就已经复杂，**多步时错误会随步数复合放大**。
- **动机二**：训练时**在线调用真实工具非常痛苦**——工具会失败、会慢、训练本身已经够耗时，这只会雪上加霜。
- **动机三**：RLHF / RLAIF / 执行反馈这类方法大多面向**单步**任务优化——模型一口气生成最终答案，奖励只基于最终答案对不对，然后回传；这里需要对中间过程有更强的治理。

**SWiRL 的设计目标**：让模型学会①解复杂多步问题；②**知道什么时候该调工具**；③生成正确的查询来调用工具；④在多步中保持准确性；⑤**学会从错误中恢复**；⑥**知道何时停止调新工具、给出最终答案**。同时**训练时完全不调用工具**，并且希望能力能泛化到新工具、新任务。（这是 Azalia Mirhoseini 本人参与的论文，讲师预告"下周在蒙特利尔的 COLM 上宣讲"。）

### 3.10 SWiRL 的方法：两阶段（54:21–64:33）

**阶段一：离线合成多步数据（迭代式提示）。**

给定提示词，告诉模型"你有这些工具；你可以生成一步推理、调用工具，或者给出最终答案"。模型先产出动作 1（推理步骤 + 工具调用），系统把**环境返回**接上，再**重新提示**模型："这是原始问题、这是你上一步的动作、这是环境的返回结果，你可以采取新动作或输出最终答案。"如此循环，得到长度从 1、3、5 步不等的轨迹。

逐步奖励由 **LLM-as-a-judge** 给出：给定"之前的上下文 + 当前动作（推理步骤 + 工具调用）"，请它给出这一步的奖励。**这一步可以完全离线、大规模并行地跑**。

**阶段二：逐步强化学习（step-wise RL）。**

目标函数是：**在多步过程中，给定此前所有状态与动作，优化"单个动作"的期望奖励**，动作下标从 1 一路到 K。也就是说，把一条 K 步轨迹拆成 K 条子轨迹分别优化。

**关键设计：训练时不执行工具。** 转写里讲得很细——RL 阶段只让模型在给定上下文下产出"下一个动作"，**拿到这个动作的奖励就够，不需要真的去执行它**；所有真实工具调用都发生在阶段一的离线数据标注中。讲师对"裁判看不到工具输出怎么能打分"的回答是：**裁判评判的是"模型生成的这个查询本身是不是一个合理的问题"，而不是搜索结果的对错**——例如"这个人的年龄是多少"这个查询好不好，裁判不需要先知道答案就能判断。此外，**裁判/奖励模型没有经过任何训练，只是被提示（prompted）出来的**。

**推理时**：同样用迭代提示 + 标签驱动。提示词里声明可用工具（如计算器）、声明"请用 `<tag>` 包裹你想让工具计算的表达式"、以及"信息够了就用 answer 标签给最终答案"。模型产出一个带标签的动作 → 系统执行工具 → 把输出回喂 → 再提示，直到模型给出答案标签。

### 3.11 SWiRL 的实验与结论（65:34–74:47）

**设置**：用 **Gemma 2 27B**（转写作 "GMO 227B"，已据论文核对为 Gemma 2 27B）生成多步合成数据；问题来自 **HotpotQA** 与 **GSM8K**；共约 **50K 条轨迹**（转写只给了 50K 这一个数；论文侧核对为 HotpotQA 50,000 条 / GSM8K 37,500 条）。数据进行四种处理：仅过程过滤、仅结果过滤、过程+结果都过滤、随机。

**核心结论：**

1. **只做"过程过滤"反而最好。** 一开始反直觉：只保留"每一步都被 judge 判为合理"的轨迹（**不管最终答案对不对**），比只保留最终答案正确的轨迹、或两者都要的轨迹，对训练更有帮助。讲师给出的解释是：如果只拿"模型本来就已经做对"的轨迹训练，你就没在帮它解决测试时做不出来的问题。（论文侧核对：论文明确写 "filtering for correctness usually harms performance"，且 SWiRL **受益于正负例混合**；过程过滤由 Gemini 1.5 Pro Thinking 担任 judge、逐步奖励由 Gemini 1.5 Pro 给出，**不使用 golden labels**——讲师强调"我们没有训练 judge，只是 prompt 它"。）
2. **跨任务、跨工具泛化（本讲"最重要的一张图"）。** 在 **GSM8K**（配计算器工具）上做多步 RL 后，去测 **HotpotQA**，准确率从 base 的 **65 提升到 75**（转写数字写作 "751"，疑为 75.1，**待核对**）；而在 HotpotQA 上（配搜索工具）训练，同一评测从 **65 到 73**。反向同样成立：在 HotpotQA + 搜索工具上训练，模型在 GSM8K + Python 上也表现良好。讲师的解读："**学到的不只是某个具体工具的用法，而是如何分步思考、如何调用工具。**"（论文侧核对：仅在 HotpotQA 上训练，GSM8K 零样本**相对提升 16.9%**；五个数据集上的相对提升分别为 GSM8K 21.5%、HotPotQA 12.3%、CofCA 14.8%、MuSiQue 11.1%、BeerQA 15.3%。）
3. **数据规模是可伸缩的杠杆。** 从 **100 条**训练样本扩到 **10,000 条**，即使在完全不同的任务（数学 / GSM8K）上，推理时表现也持续提升。讲师认为这是"**在容易造数据的环境里造合成数据，把多步思考与工具使用的行为泛化到全新工具与领域**"的路径，且"**把它 scale up 可能是一种非常强的方法论**"。（论文侧核对：1,000 条即可稳定提升，10,000 条仍有增益。）
4. **模型确实"每一步想得更对了"。** 作者统计了微调前后模型在答题时**每步的平均过程奖励（average process reward per step）**，结果显示过程正确性在**分布内（HotpotQA）与分布外（GSM8K）都提升了**——这是对"为什么变好"的一个可解释证据。
5. **多步 RL 明显优于 SFT。** 同样的数据与流程，换成监督微调来做，**多步 RL 好出"相当一截"**。而且两者的偏好相反：**SFT 需要"过程 + 结果都过滤"（即最终答案必须正确）的数据才更好**；讲师的解释是 SFT 本质是**模仿学习（imitation learning）**——把轨迹摆给模型让它复现，所以错误的最终结果会伤害性能；而 **RL 是在给定前文的情况下给模型一次"重新选择动作"的机会，并对这个新动作给奖励**，因此能从错误结局的轨迹中跳出来。

## 四、论文精要

### 4.1 LATS（Language Agent Tree Search）— 录像精讲

- **一句话贡献**：把 MCTS 式的树搜索引入语言智能体，用"选择—扩展—评估—模拟—反向传播—反思"六阶段统一了推理、行动与规划。
- **关键结论/数字**：价值函数 = LLM-as-judge 分数（0–1）与自一致性分数（采样频次）的加权和；选择用 UCT `V(s) + c·sqrt(ln N_p / n_s)`；反向传播用增量平均 `V_new = [V_old·(n−1) + return]/n`；HotpotQA（每个问题至少需检索 2 个维基页面）上随采样轨迹数增加性能显著提升；**WebShop 上无需微调、纯测试时推理即可接近人类专家水平**。
- **讲师强调的点**：① 与 Math-Shepherd 的分野在于"**分数来自行动的结果，而非推理选择本身**"；② 相比 ReAct 多了记忆、反思与环境交互，且"规划成分更重"；③ 反思步骤对质量提升"非常有帮助"；④ **UCT 没有最优性证明**；⑤ **成本收益未被分析**，且**不可逆动作场景未被处理**；⑥ 最大价值是"搭了一个平台"，别人可以换上别的探索策略（多臂老虎机等）。

### 4.2 SPRINT — 录像精讲

- **一句话贡献**：让推理模型学会**交错地规划与并行执行**——先把可并行的计划一次性生成，再并行执行，从而压缩顺序 token 与延迟。
- **关键结论/数字**：6K 条数学思考轨迹，保留高并行度的样本，在 **DeepSeek-R1-Distill-7B** 上 SFT；**准确率提升 3.5%**；顺序 token 效率**优于 32B 模型**；数学任务上顺序 token 减少约 **40%**（论文：需要 >8000 输出 token 的问题上最多 39%）；**GPQA 与 Countdown 上顺序 token 最多分别减少 45% 与 65%**；训练只用数学数据，**零样本泛化到 Countdown 与 GPQA Diamond**。
- **讲师强调的点**：① 初衷是省 token，**准确率提升是意外收获**；② "**它永远是 next token**"，只是生成顺序变了；③ 收益高度依赖难度——**思考越少的问题越可能不如基线**；④ **早期并行/探索多，后期收敛到单一计划**；⑤ 数据构造范式本身值得借鉴：**用 DeepSeek-R1 生成轨迹 + GPT-4o 标注计划/执行 + 构造 DAG**；⑥ 目前只做了 SFT，**用 RL/GRPO 可能带来更大收益**，且**真正实现墙钟加速（wall-clock speedups）**仍是待做的工程工作。

### 4.3 SWiRL — 录像精讲

- **一句话贡献**：用"**合成多步轨迹 + 逐步（step-wise）RL**"教会模型多步推理与工具使用，且**训练过程完全不调用真实工具**。
- **关键结论/数字**：Gemma 2 27B 生成约 **50K 条**多步轨迹（HotpotQA + GSM8K）；逐步奖励由**未经过训练的** LLM judge 给出；**过程过滤（不看最终答案对错）效果最好，结果过滤通常损害性能**；跨任务泛化：GSM8K 训练 → HotpotQA **65→75**，HotpotQA 训练 → 同评测 **65→73**；训练数据从 **100 扩到 10,000** 条，域外任务持续提升；微调后**每步平均过程奖励在分布内与分布外双双上升**；**多步 RL 明显优于 SFT**。（论文摘要侧的相对提升：GSM8K 21.5%、HotPotQA 12.3%、CofCA 14.8%、MuSiQue 11.1%、BeerQA 15.3%；仅 HotpotQA 训练 → GSM8K 零样本 +16.9%。）
- **讲师强调的点**：① **训练时不执行工具**——裁判评的是"模型生成的查询是否合理"，而非执行结果；② 裁判与奖励模型**都是 prompt 出来的，没有训练**；③ 反直觉的过滤结论，以及"**SFT 是模仿学习，RL 给了模型重新选动作的机会**"这一对比；④ 泛化的本质是"学会分步思考与调用工具"，而非记住某个工具；⑤ "**把它 scale up 可能是一种非常强的方法论**"。

### 4.4 ADaPT（As-Needed Decomposition and Planning）— **录像未涉及**

> 转写中 0 次出现（连 "Prasad"、"decomposition" 作为方法名都未出现）。以下来自论文摘要，供补齐阅读清单，**非本讲转写内容**。

- **一句话贡献**：不做一次性全量分解，而是"**按需分解**"——只有当 LLM 执行不了某个子任务时，才递归地把它继续拆解，从而同时适应**任务复杂度**与**执行模型的能力**。
- **关键结论/数字**（论文摘要）：相比强基线，成功率提升最高 **ALFWorld 28.3%、WebShop 27%、TextCraft 33%**（TextCraft 是该论文新提出的组合式数据集）；分析表明**多级分解**很关键，且 ADaPT 会随执行器能力与任务复杂度动态调整。（NAACL 2024 Findings。）
- **与本讲的接口**：它与 LATS 是"分解 vs. 搜索"两种互补路线；与 SPRINT 的关系是"先分解出子任务，才谈得上并行执行"。

### 4.5 Wider or Deeper?（AB-MCTS, Adaptive Branching MCTS）— **录像未涉及**

> 转写中 0 次出现（"wider"/"deeper"/"branching" 均无）。以下来自论文摘要，**非本讲转写内容**。

- **一句话贡献**：提出 **AB-MCTS**，在每个搜索节点上依据外部反馈**动态决定"变宽"（go wider，扩展新的候选回答）还是"变深"（go deeper，回到已有候选上继续打磨）**，是对 repeated sampling 的推广。
- **关键结论/数字**（论文摘要）：在复杂编码与工程任务上用前沿模型评测，**AB-MCTS 稳定优于 repeated sampling 与标准 MCTS**；结论强调"**LLM 的回答多样性**"与"**多轮方案打磨**"必须结合。（Sakana AI，NeurIPS 2025 Spotlight，代码在 `SakanaAI/treequest`。）
- **与本讲的接口**：本讲 LATS 部分的 UCT（探索 vs. 利用）与 SPRINT 的"早期宽、后期深"的经验规律，都与这条 wider/deeper 主线呼应——讲师在 SPRINT 里观察到的"早期并行多、后期收敛"实际上是同一现象在推理模型内部的表现。

- **[67:37] 最反直觉的一条**："当我们只做过程过滤——也就是保留那些每一步都被 LLM 裁判判定合理的推理轨迹，**却不按最终答案正确性过滤**——对训练的帮助，反而比严格只保留结果正确的轨迹更大。"
- **[70:43] 最有价值的一张图**："在**更容易造数据的环境里**造合成数据，教会模型如何使用工具、如何多步思考，**我们可以把这种行为泛化到全新的工具与全新的领域**；把它 scale up 可能是一种非常强大的方法论。"
- **[72:44] RL 与 SFT 的根本差别**："多步 RL 比监督微调好出相当一截……在监督微调里，数据必须**同时经过过程和结果过滤**才更好——因为那本质上是**模仿学习**；而在 RL 里，我们在给定前序步骤的情况下给模型一次采取新动作的机会，并据此给奖励，模型因此能从中跳出来。"
- **[73:47] 总结句**："SWiRL 能跨数据集、跨工具泛化……**模型从过程过滤的数据里学得更好**，并且能从更多合成数据中同时获得域内与域外增益；而**过程正确性（process correctness）本身提升了**——这一点在分布内和分布外都成立。"

## 六、动手启示

1. **先判断你的任务是否真的"多步"**：用 HotpotQA 式的标准来检验——是否**至少需要两次独立的信息获取/动作**才能得到答案？如果单步就能解决，上树搜索或并行执行只会白白增加成本（SPRINT 在思考量小的问题上甚至不如基线）。
2. **测试时想提升，优先做"搜索 + 反思"而非微调**：LATS 证明了纯测试时方法在 WebShop 上就能逼近人类专家。最小可用配方是：**采样 N 个动作（N 给到 50 量级以便自一致性分数可信）→ 用 LLM-as-judge 打 0–1 分 → 与采样频次加权 → UCT 选择 → 轨迹结束后反向传播 → 追加一段失败/成功反思**。别忘了强制模型产出反思文本，讲师明确说这一步增益很大。
3. **别用纯贪心做选择**：哪怕没有完整 MCTS，也要在打分里加一项 `sqrt(ln N_parent / n)` 式的探索奖励。讲师也提醒：这个公式**没有最优性保证**，多臂老虎机里的其他策略（Thompson sampling 等）都值得一试。
4. **并行化的杠杆在"顺序 token"而不在"总 token"**：要减少用户等待，就去识别推理轨迹中的独立片段。可复现的做法是**用强推理模型生成轨迹 → 用另一个模型逐步标注 plan/exec 与依赖 → 构造 DAG → 重排后 SFT**。同时记住：并行块要"合并到足够大"，否则简单任务产生的调用开销与 straggler 会吃掉收益。
5. **多步 RL 的数据配方：过程过滤优于结果过滤**。造合成多步数据时，**用 LLM judge 逐 step 判定"这一步是否合理"，但不要因为最终答案错就丢掉整条轨迹**——正负例混合反而更好（SWiRL 的关键发现）。反过来，如果你走 SFT 路线，则**必须同时过滤过程和结果**。
6. **把工具调用留在离线阶段**：训练时不要真调工具（慢、会挂）。只要让 judge 评判"模型生成的查询/动作本身是否合理"，就不需要执行结果——这样 RL 训练循环会快很多、也稳定很多。
7. **合成数据是跨域迁移的杠杆**：在**容易造数据的领域**（如带搜索的问答）造数据、做多步 RL，可以泛化到**完全不同的工具与领域**（如带计算器的数学）。数据量从 100 到 10,000 条时，域外任务仍在持续变好。

## 七、遗留问题与开放挑战

- **成本—收益没有被量化（LATS）**：讲师明确指出论文"没有真正分析成本收益"。树的扩展、反向传播、反思都在叠成本，但**多少测试时算力换多少准确率**仍是空白。
- **不可逆动作（LATS）**：论文假设动作可以反复试探。一旦动作不可逆（付款、下单、发消息），树搜索的"试错"前提就崩了，**该如何适配完全没被解决**。
- **失败/矛盾如何在并行分支间仲裁（SPRINT）**：并行分支各自看起来正确、合并后却矛盾时，**没有机制保证**——目前完全依赖模型在生成最终答案前"自行消解冲突"，讲师承认两种（串行/并行）方式都可能受此困扰。
- **负载均衡与 straggler（SPRINT）**：无法保证并行分支耗时相近，仍有慢分支限制整体时间；已有的"合并过小的执行块"只是启发式，讲师原话是"**我不确定论文里是否有针对这一点的专门分析**"。
- **树的宽度没有定量结论（SPRINT）**：讲师被直接问到"树的平均宽度与最大宽度是多少"时**给不出具体数字**，只说"**取决于任务**"。并行度与任务类型的定量关系（数学为何比 GPQA-Diamond 更"窄"）未被刻画。
- **SPRINT 只走了 SFT，RL 未做**：讲师明确说"像 RL、GRPO 这样的方法有可能从这份数据里榨出更大的收益、更好的泛化"，**这是明摆着的下一步**。
- **墙钟加速尚未真正落地（SPRINT）**：讲师把"真正实现 wall-clock speedups、重叠不同工具的调用"列为**其他可做的工作**——即论文主要证明的是顺序 token 的减少，端到端延迟收益仍是工程未完成项。
- **为什么过程过滤更好，只有假说（SWiRL）**：讲师用的是 "perhaps"、"we kind of realized" 的措辞——如果只训练模型本来就会做的题，就没帮它解决测试时不会的题。**这是一个尚未被严格验证的解释**。
- **未训练的 LLM judge 是否可靠（SWiRL）**：judge 与奖励模型都是**纯 prompt 出来的、没有经过训练**，其噪声、偏差、以及被 reward hack 的风险没有被讨论。
- **本讲三篇方法之间的组合是空白**：树搜索（wider/deeper 的算力分配）、并行执行（顺序 token 压缩）、逐步 RL（过程奖励）三者如何叠加，讲座没有给出答案；ADaPT（按需分解）与 AB-MCTS（wider vs. deeper 的自适应决策）虽在阅读清单上，但**录像完全没讲**，这两条线如何与 LATS/SPRINT/SWiRL 对接，需要自行读论文补齐。
