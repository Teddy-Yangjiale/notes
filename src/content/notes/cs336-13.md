## 1. 数据决定模型的隐形产品规格

预训练目标只要求预测下一个 token。模型学到什么语言、知识、风格、价值观、许可证风险和错误模式，主要取决于数据分布：

$$
p_{train}(x)=\sum_s w_s p_s(x),
$$

$s$ 是 web、Wikipedia、code、books、papers 等来源，$w_s$ 是 mixture weight。改变 $w_s$ 不只是“多一些文本”，而是在改变模型被优化去逼近的目标分布。

一条可审计的数据链：

```text
来源与获取依据
→ 原始文件/WARC/仓库快照
→ 解析与文本抽取
→ 语言/质量/安全过滤
→ exact + fuzzy dedup
→ 基准污染清理
→ mixture 与采样
→ tokenizer 后 token 计数
→ 版本化 manifest、统计与 provenance
```

## 2. 版权、许可和合同是不同问题

### 2.1 Intellectual Property

课程区分：事实/思想通常不等同于受保护的具体表达；文本、图像、代码等表达可能受版权保护。训练是否构成合理使用、模型输出是否构成实质性复制，取决于法域和具体事实，不能从“网页可访问”推出“可任意训练和再分发”。

### 2.2 License

许可证是权利人预先给出的使用条件。开源代码许可证可能要求保留 notice、相同许可证或提供源码；Creative Commons 也有署名、非商业、禁止演绎等组合。把不同 license 的内容混入一个 corpus，不会自动消除其条件。

### 2.3 Terms of Service、robots 与 privacy

服务条款/访问控制属于合同和计算机访问层面；robots.txt 是爬虫偏好协议，不等价于版权许可。个人信息、敏感信息和删除请求又属于隐私/合规维度。数据治理至少要分别记录这些依据。

### 2.4 Lawsuits 与不确定性

课程列举围绕 books、news、code 和 web scraping 的诉讼，强调当前实践并无统一确定结论。工程上应保留来源 URL/快照、获取日期、license、过滤和删除链路，才能在政策改变时追溯和重建。

## 3. Common Crawl：Web 数据的基础设施

Common Crawl 定期抓取公开网页并发布：

- **WARC**：原始 HTTP 请求/响应和页面 bytes；
- **WAT**：结构化元数据、headers、links；
- **WET**：抽取后的纯文本。

典型处理：

1. 读取 WARC record，检查 HTTP 状态和 MIME；
2. 解压/解码 HTML，处理 charset；
3. 去 boilerplate、导航、脚本、cookie banner；
4. 保留文档 URL、时间、域名等 provenance；
5. 语言识别、质量过滤、去重；
6. 分 shard 输出并记录统计。

Common Crawl 不是“干净互联网”：含模板、SEO、垃圾、机器文本、重复镜像、隐私信息、错误语言和版权内容。直接使用 WET 也会继承抽取器错误。

## 4. 高价值来源及其偏差

### 4.1 Wikipedia

优点：结构清晰、编辑质量高、多语言、许可明确且 dump 易获得。偏差：百科语体单一，主题/语言覆盖不均，事实随时间变化；模板、引用、表格处理会改变文本。

### 4.2 GitHub / Code

包含代码、README、issues、commits。价值是编程能力与软件知识；风险包括：

- 许可证碎片化；
- secrets、PII、恶意代码；
- vendored/generated files 大量重复；
- fork 与镜像；
- tests/solutions 导致代码 benchmark contamination。

应按 repository/file 级 license、路径、大小、语言、生成标记过滤，并做 repo-aware dedup，而不只是逐文件 hash。

### 4.3 arXiv / Scientific Papers

提供技术语言、公式和研究知识。PDF/TeX 抽取会引入断行、公式丢失、参考文献噪声；版本和许可需记录。只保留纯文本会损失图表和布局语义。

### 4.4 Books

长程连贯叙事对长上下文和文体有价值，但 BooksCorpus、Books3 等来源/许可争议突出。公共领域 Project Gutenberg 更清晰，但含历史语言和重复版本，仍需元数据及去重。

### 4.5 Stack Exchange

问答结构、投票和标签可用于技术解释；许可要求署名/相同方式分享等条件，页面模板和重复问题也需处理。

## 5. 早期数据集：从 BERT 到 GPT-2

### 5.1 BERT

BERT 主要使用 BooksCorpus + English Wikipedia。相对当时规模不大，但包含文档级文本，支持 masked LM 与句间任务。它显示 curated book/encyclopedia 已足以推动通用表征，但覆盖范围有限。

### 5.2 WebText

GPT-2 不直接抓全网，而是从 Reddit 外链且达到一定 karma 的网页构建 WebText，用人类社交筛选作质量 proxy。优势是比无差别 crawl 更可读；偏差是 Reddit 用户群、链接偏好和流行度决定分布，且原始 WebText 未完全公开。

这个模式的重要思想是：先找一个可扩展的**选择信号**，再抓被选内容。

## 6. CCNet 与 C4：可扩展 Web 清洗

### 6.1 CCNet

典型步骤：

1. Common Crawl 文本抽取；
2. language identification；
3. paragraph/document dedup；
4. 用 Wikipedia-trained language model perplexity 为文档打质量分；
5. 按分位数分高/中/低质量。

Perplexity filter 偏好接近 Wikipedia 的文本，可能排除口语、方言、新领域和低资源语言。质量模型定义了“好文本”的风格。

### 6.2 C4

T5 的 Colossal Clean Crawled Corpus 在 Common Crawl 上应用语言、标点、脏词、模板和重复过滤。规则可解释且高效，但 brittle：关键词过滤会误删包含敏感词的健康/身份讨论，英文启发式对其他语言不适用。

## 7. GPT-3 与数据混合

GPT-3 使用过滤后的 Common Crawl，并混入 WebText2、Books1/2、Wikipedia。训练采样比例并不等于原始 token 比例：高质量小来源可被多次 epoch，Common Crawl 只取一部分。

Mixture 设计需要记录：

$$
P(s)=w_s,qquad x\sim p_s(x).
$$

来源被重复多少次、tokenizer 后有多少 tokens、随训练阶段是否改变，比简单的“数据集大小”更重要。

## 8. The Pile：显式多来源组合

The Pile 将约 22 个来源（books、papers、code、forums、legal、medical 等）显式组合，贡献在于：

- 来源透明、可分别研究；
- 扩大 domain diversity；
- 让 mixture ablation 成为可能。

但它也包含后来有法律/下架争议的组成。透明 provenance 能让使用者移除单一来源，是比“无法追溯的大文本桶”更可治理的设计。

## 9. Gopher MassiveText 与规则化清洗

Gopher 展示大规模 heuristic pipeline：文档长度、平均词长、符号比例、重复行/段、stop-word、质量信号等。规则目标通常是去模板和垃圾，但各阈值会形成 selection bias。

应对规则做：

- 随机抽样 before/after；
- 分语言/域统计保留率；
- false positive/negative 人工审计；
- 记录规则版本；
- 防止多个相关规则叠加后过度筛选。

## 10. LLaMA、RefinedWeb 与开放数据趋势

### 10.1 LLaMA

公开描述组合 Common Crawl、C4、GitHub、Wikipedia、Books、arXiv、Stack Exchange 等，并强调只用“公开可获取”数据。公开可获取不等于许可证无风险，但多来源 recipe 成为后续开放模型参考。

### 10.2 RefinedWeb / Falcon

RefinedWeb 论证经过强过滤和去重的 web-only 数据也能与人工多来源 mixture 竞争。核心不是“Web 天然足够”，而是 extraction、quality filtering、dedup 和规模可产生强 corpus。

## 11. Dolma：开放、可复现的数据工程

Dolma 强调：公开数据、处理代码、来源 mixture 和文档级 metadata。可复现数据集应提供：

- 原始来源与版本；
- 每阶段输入/输出文档和 token 统计；
- 过滤/去重代码及参数；
- PII/安全处理；
- benchmark decontamination；
- 数据许可和使用说明。

可复现不是只发布最终 shards，而是让 selection function 可检查。

## 12. DCLM：把数据选择变成 Benchmark

DataComp-LM 固定训练/评测框架，让参赛者主要改数据 pipeline，以减少模型和算力 confounder。其 model-based filtering 大致是：

1. 准备高质量正例和随机 web 负例；
2. 用文本特征/embedding 训练 classifier；
3. 给海量候选文档打分；
4. 选阈值或 top fraction；
5. 用固定模型训练并比较下游。

这种过滤比单条启发式灵活，但 classifier 会学习参考数据的风格和偏见。需要校准不同语言/领域的 score，防止把“像 benchmark/百科”误当通用质量。

## 13. Nemotron-CC 与后续 Web 管线

新数据集进一步组合多种质量模型、分类器、合成重写和不同质量 buckets。一个重要趋势是：低质量文档不一定全部丢弃，可用模型抽取/重写有价值部分；但这会引入模型生成分布、事实变化和 provenance 模糊。

应分别标注 original、extracted、rewritten/synthetic，避免将合成文本伪装为原始网页。

## 14. The Stack 与代码数据治理

The Stack 以 permissive-license code 为目标，并提供 opt-out/移除机制。代码 corpus 的特殊算法问题：

- 用 Git object/repo graph 识别 forks；
- 按文件内容 hash + near-dedup；
- 按 commit 时间切 benchmark；
- secrets scanning；
- license detector 的置信度与冲突处理；
- generated/minified/vendor directory 分类。

仅按扩展名识别语言和许可远远不够。

## 15. Common Pile 与公共领域路线

课程介绍 Common Pile 等尝试只使用 public-domain 或开放许可来源，目标是降低法律不确定性并提高 provenance。挑战是可用规模、领域覆盖和 license metadata 本身也可能错误。合法性更清晰的数据仍需要质量、去重和代表性工程。

## 16. 数据集谱系中的技术演进

```text
少量人工选择（BERT）
→ 社交信号筛选 Web（WebText）
→ 规则 + LM perplexity 清洗 Common Crawl（CCNet/C4）
→ 大型多来源 mixtures（GPT-3/Pile/Gopher）
→ 强 Web-only refinement（RefinedWeb）
→ 开放处理与 benchmark 化数据选择（Dolma/DCLM）
→ model-based filtering、重写与许可证优先 corpus
```

演进不是简单“数据越来越多”，而是 selection signal、透明度、法律约束和可复现性不断增强。

## 17. 数据来源审计表

每个 source 至少记录：

| 字段 | 问题 |
|---|---|
| provenance | URL、snapshot、date、version |
| access | 如何获取，是否需账号/绕过控制 |
| license/IP | license、public domain、未知比例 |
| content | 语言、领域、时间、格式 |
| extraction | parser 版本与失败率 |
| quality | 规则/模型、阈值、校准集 |
| dedup | source 内/跨 source 的策略 |
| safety/privacy | PII、secrets、有害内容处理 |
| evaluation | benchmark overlap 与 time cutoff |
| removal | opt-out、删除传播到哪些 artifacts |

## 18. 常见误区

- “网上能访问”不等于“有训练和再分发许可”。
- robots、版权、服务条款和隐私是不同问题。
- Common Crawl 是原始基础设施，不是干净训练集。
- Wikipedia perplexity 低不等于普适高质量，会偏向百科风格。
- 高质量小来源被 oversample 后，实际训练影响可能远大于原始占比。
- 发布最终 shards 却不发布 selection code，仍难以复现。
- 模型重写能改善形式，但会增加合成偏差和 provenance 复杂度。
- 数据集名称相同也可能因 snapshot/version 不同而内容显著变化。

本讲的核心是 provenance-first：预训练数据的价值、偏差和风险都来自来源与选择过程。只有把每一阶段当作可版本化、可统计、可删除的工程对象，模型行为才有可能被解释和治理。
