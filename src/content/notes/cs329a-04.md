## 一、本讲要解决什么问题（TL;DR）

大语言模型擅长 NLP 任务，但要真正有用，必须能与真实环境、工具和代码交互，并**从交互后果中学习**。本讲用三篇论文回答一个统一问题：**如何为模型搭一个反馈回路（feedback loop），让它超越训练数据分布持续自我改进**。三者差别不在"要不要反馈"，而在**反馈从哪来**：ReAct 来自环境交互（搜索/API 返回），RLEF 来自代码执行（测试通过与否），Constitutional AI 来自模型按原则的自我批判（critique）。两条贯穿全讲的判断：其一，模型并不可靠地"知道自己知道什么"（过度自信、校准很差），所以应用设计者该做的是**让模型用对工具以拿到落地（grounded）的知识**；其二，**只有当反馈信号足够客观可验证时（如测试通过/失败这种可执行判定的二元信号），自改进回路才真正成立**。

## 二、核心概念与术语

- **ReAct 循环（Reasoning + Acting）**：模型交替生成思考（thought）与行动（action），把环境返回的观察（observation）拼回上下文继续推理。最早把推理与行动合一的抽象，也是今天工具调用智能体的雏形。
- **工具调用（tool calling）**：模型输出可被外部执行的动作（如 `search[...]`、`lookup[...]`、`finish[...]`），由环境返回结果。
- **落地 / 接地（grounding）**：输出有外部世界证据支撑，而非仅来自模型内部状态。不 grounded 的输出即幻觉（hallucination）温床。
- **执行反馈（execution feedback）**：真正运行代码/测试后拿到的结果（通过/失败、超时、报错）。最客观、最难被蒙混、可自动生成、无需人工标注的监督信号。
- **双层测试策略（two-tier test strategy）**：把测试拆为 public tests（小子集，推理时即时反馈）与 private tests（生成期完全隐藏，只用于算奖励）。防止模型背下测试输出。
- **轮次级价值函数（turn-level value）**：token 逐个生成，但价值/优势在"整轮回复"粒度计算，用 prompt 最后一个 token 估计，全序列共享一个 advantage。近 GSPO 的整序列奖励思路（*讲师原话为 GSPO，待核对*）。
- **结果 vs 过程奖励模型（outcome vs process reward model）**：只在最终答案给奖励，还是在每步中间推理给奖励。讲师明确说此争论"没有彻底解决"。
- **人类反馈 / RLHF**：人类对多个输出排序 → 训偏好/奖励模型 → RL 微调。收益随模型规模提升明显，但需上万条人工标注，不可扩展。
- **AI 反馈 / RLAIF**：用模型按原则生成的偏好标签替代人类标签，成本可控、可规模化。
- **宪法（constitution）**：人类一次性写下的原则集合（本讲说为 **16 条原则**），定义期望行为。人类只写规则、不逐条打分，是 CAI 可扩展的关键。
- **批判—修订（critique & revision）**：模型按宪法原则批评自己的输出再改写，构成 CAI 监督学习阶段的训练数据。
- **偏好模型（preference model）**：用 AI 反馈训练的排序模型，RL 阶段替代人类偏好；仍需少量人类数据做一致性校验。
- **自一致性 / 多数投票（self-consistency, SC）**：采样多条推理路径取多数答案。讲师明确说 SC 与多数投票是同一件事；它是 ReAct 的回退（fallback）搭档。
- **模仿学习（imitation learning）**：在交互轨迹上做监督微调，是 WebShop 实验的基线之一。

## 三、主线内容

### 3.1 开场：三种范式，差别只在反馈来源 [00:05–01:06]

前三讲已覆盖思维链、测试时计算与鲁棒验证，本讲加一层：**让模型行动，并从行动的后果里学**。统一框架：ReAct → 与**环境**交互；RLEF → 与**执行器**交互；Constitutional AI → 与**批判机制**交互（或用"我们知道的正确答案"去接地）。

### 3.2 ReAct：为什么推理与行动必须交替 [01:06–08:20]

**动机**：人的循环是"想（这门课有用吗）→ 行动（去上课）→ 观察（喜不喜欢）→ 新推理 → 再行动"。而模型现有两种范式各缺一半：

- 纯 Chain-of-Thought：展示中间步骤，但**这些步骤基于模型内部状态，没有外部反馈，可能不 grounded**（[04:11]）。
- 纯行动型模型（如 **WebGPT**）：学会操作浏览器，但**没有推理过程**，只在交互轨迹上微调、学人类偏好。
- 直接问答：问"今天气温多少"，模型**没有当前事件信息，除非真的发起一次搜索**。

ReAct 的抽象极简：**用提示让模型先生成一段语言化推理轨迹，追加进 prompt，再决定下一步行动**。关键：这些 thought 在**语言空间**生成，**不直接影响环境**，只为下一步动作提供正确抽象（[07:16]）。

**两个收益**：（1）在需要 grounding 的任务上性能更好——HotpotQA（多跳问答）、FEVER（事实验证）、WebShop（按指令上网买商品，需一串工具调用）；（2）**可解释性**，逐步展示让人更信任。

**一个工程技巧**：不要自由生成动作，而是给出**当前世界的合法动作子集**，把动作生成变成分类任务。讲师提到她在 Google 与机器人团队合作的一篇论文也用了这招（机器人场合动作必须绝对合法）——论文名未在课上点出。

### 3.3 实现细节与课堂 Q&A [08:20–17:32]

- 实现用 **PaLM** 这类冻结模型 + 少样本示例（示例里拼接 action / thought / observation）。模型看到"世界状态 + 思考"后，**决定是继续推理还是采取行动**。
- **Apple Remote / Front Row 例子（HotpotQA，[09:21–11:24]）**：问"除了 Apple Remote，还有什么设备能控制它最初设计用来交互的那个程序？"标准 prompt 答错；CoT 列出全部中间步骤仍错（幻觉）；Act-only 搜到 Front Row 后发现"已停产"，给不出答案；**ReAct** 先想"要搜 Apple Remote 并找到它最初控制哪个程序"→ 搜到它是 2005 年推出的遥控器、最初控制 **Front Row 媒体中心** → 想"下一步搜 Front Row"→ 搜索失败 → 想出新术语 **"Front Row software"** → 再搜 → 确认是已停产的媒体软件中心 → 再推理 → 答对。
- **严格串行**：thought₁ → act₁ → thought₂ → act₂，每一个影响下一个（讲师用"渴了→走向厨房→发现没水→改去超市"类比）；并行采样需显式设计。
- **Q：模型知道自己知道什么吗？** 讲师：存在两派观点，但**让模型自评自信度时通常过度自信、校准很差（not well calibrated），这仍是待解决的研究问题**（[13:27]）。工程建议：别问模型知不知道，**让模型用对工具拿到 grounded 的知识**。
- **Q：搜索结果互相矛盾怎么办？** 应用层需自己决策；可用第 2 讲的多数投票、或在把答案交给用户前加验证（guard rails）。讲师补充：**"带搜索结果的幻觉，比单纯依赖模型内部状态的幻觉要好控制得多"**（[15:29]）。
- **Q：thought 算动作空间的一部分吗？** 不算——动作在右循环、推理在左循环。保留 reasoning token 是因为语言模型在语言上训练，**需要这些 token 才能以正确抽象输出正确动作**（若有中间表示也许就不需要）。
- **学生提问**：能否研究 KV cache 里 thought 与 observation 的表征差异？讲师：观察是环境给的、不是 LM 生成的，这角度有意思——"**这可能就是你这门课的研究项目**"。

### 3.4 ReAct 的实验结果与局限 [17:32–27:44]

**知识密集型任务（HotpotQA / FEVER）**：动作空间极简，就是模拟人逛 Wikipedia——`search[页面]`、`lookup[字符串]`、`finish[答案]`。基线：标准 prompt（无思考/无动作/无观察）、CoT、CoT-SC、Act-only；另有两种组合变体：ReAct 若干步失败后回退 CoT-SC，或多数答案出现频率不足一半时回退 ReAct。结论：ReAct **普遍优于 Act-only**；**并没有总是优于 CoT**（在 FEVER 上超过 CoT，在 HotpotQA 上并非总是，讲师称之"which was interesting"）；**与 CoT-SC 组合后才稳定超过标准方法**。失效模式上，**CoT 的主要失效模式是幻觉**，ReAct 有外部知识库而更可信。训练方式排序：**prompting < fine-tuning < RL 循环**（RL 部分"下周讲"）。

**决策型任务（WebShop）[20:34–21:34]**：按用户指令购买商品（例：找"带抽屉的床头柜"），在模拟环境中评估 **score**（中间步骤即时得分）与 **success rate**（任务是否最终成功）。基线为模仿学习（IL，即纯监督微调）与 IL+RL。结果：ReAct 的 score 与 success rate 均高于两条基线，但**仍远低于人类专家——ReAct 66.6 对 人类 82.1**（讲师说的是 score 这一档；success rate 更低，因为多步任务中**任何一步出错，误差会随时间级联放大**）。

**三大局限 [22:36]**：（1）动作空间大时需大量示范，**上下文装不下**；（2）多步推理 → **推理成本更高**；（3）虽有代价，但在问答、事实验证、决策任务上总体更好，**幻觉更少、决策轨迹更可读**。

**课堂讨论 [22:36–27:44]**：
- 环境反馈有噪声/误导？→ 加一层**反思（reflection）**；让智能体具备**回溯（backtracking）**能力，否则会被带进重复循环；需要更好的置信度度量；同一任务多跑几次取最好。
- 还需要哪些认知机制？→ **任务分解**（先拆子任务）；并行思考路径；**记忆/过往经验**；**推理与行动的最优配比**（讲师接话：今天很多模型 **overthink**，简单任务也生成极长思考链，"怎么让模型别想太多"是一批有意思的工作）；以及**复合系统**——按子任务对不同模型做基准、按强项分派（"这也许又是一个项目点子"）。

### 3.5 RLEF：把执行反馈接进 RL 回路 [27:44–31:47]

讲师现场调研："你们有多少人今天用 Claude Code？"——**几乎是全班**。结论：大量工程/编码任务已交给智能体，核心变成**理解用户意图，并基于生成的代码拿到反馈来迭代**。

RLEF 是**端到端 RL 微调框架**（[28:44]）：**动作 = 生成的代码**；**观察 = 执行反馈**（即测试反馈，跑测试看通过/失败）；**奖励 = 二元**（通过与否）；**算法 = PPO**（转写误写作 PPU / PO / PBO）。两大贡献：**双层测试策略**与**混合 token/轮次级策略**。

**迭代反馈回路 [29:45]**：自然语言问题描述 → 生成代码解 → 在 **public tests** 上评估 → 失败则把执行反馈回喂给 LLM 再来一次 → 循环直至通过或达到**轮次上限** → 通过的候选解交给 **private tests** 定奖励 → 奖励进入 PPO 更新策略。讲师拆解：左边是 RL 的**利用（exploitation）阶段**（用当前策略做推理时迭代），右边是**基于执行结果的策略更新**，二者构成持续自我改进。

**例子（回文子串检测，[30:45]）**：turn 1 的朴素实现在 public tests 上失败（**执行超时**，很常见）→ 拿到反馈后 turn 2 做优化 → 通过 public tests → 提交 private tests。

**为何分两层 [31:47]**：public tests 是**很小的子集**，用于快速迭代、在推理时引导模型；private tests 在生成过程中**完全隐藏**。**这种切分让模型无法靠背下测试输出蒙混过关**——它拿到的是真实执行反馈，训练信号只来自没见过的 private tests。讲师称之为"自改进回路里非常有用的一个创新"。

### 3.6 第二个创新与实验结果 [32:48–37:52]

**混合粒度**：模型逐 token 生成代码（对生成过程有最终控制权），但**价值函数在轮次级计算**——用 prompt 最后一个 token 估计，**整条回复的所有 token 共享同一个 advantage**。讲师类比："这更接近 **GSPO** 的做法，即给整个序列奖励，而不是逐 token 给。"

**结果曲线 [35:50]**：y 轴 = **solve rate**，x 轴 = **采样预算**，且 **x 轴为对数刻度（log scale）**；分别画 validation set 与 test set；基座为 **Llama 3.1**，训练数据为 **CodeContests**（竞赛编程题）。加 RLEF 后解题率明显上升（讲师解释 solve rate@10 为"生成 10 个解、其中通过若干个"——*K 的具体口径待核对*）。

**为什么有效 [35:50–36:50]**：**基座模型本身并不能从"看到错误解 + 执行反馈"中获益**；真正起作用的是**训练时每一轮都把执行反馈喂给它**——是"解里的那个错误"在帮模型变好，且这种训练能**泛化到其他代码基准**。

**错误分析 [36:50]**：对比 turn 1/2/3 的错误数、代码改动数、错误类型，小模型与大模型各一份。结论：RLEF 下随轮次推进**错误输出递减、后续轮次在做修复**；没有迭代循环时模型的编辑基本是错的。红利来自**采样多样性更高** + **编辑更有针对性**（能看到自己错在哪）。讲师补充："这也是你们作业里会用到的思路"（作业是数学题，用的是识别错误解而非执行反馈）。

### 3.7 RLEF 遭遇的课堂质疑 [37:52–43:01]

- **二元反馈够用吗？** 学生：这些题可能太简单（"不超过几十行代码"），更难的题大概还需要 **error trace 或其他元数据**。讲师："很有可能，这也许是个很好的项目。"
- **反馈里含"怎么修"吗？** **只含失败本身**（"你失败了"）：把"题目 + 你生成的输出 + 你得到的反馈"拼起来，让模型再生成一次。
- **会不会鼓励"先写错再修"？** 讲师：取决于错误类型；复杂问题可能确实要多轮，但有**推理时反馈**兜底——送进 PPO 前 public tests 已让它自我纠正过几次。顺势引出：**过程 vs 结果奖励模型之争没有彻底解决**，每个领域、每个基准都要重新选。
- **SFT 能否打赢 RLEF？** 讲师：在推理轨迹上做 SFT 或许能拿到部分收益，但**RL 能解决更新颖的问题、泛化略好**；SFT 在**域内**一定有效（"损失函数还是同一个"）。她承认这仍有争议。
- **为何非要分两层测试？** 讨论陷入术语拉扯（学生质疑"反正都是训练用的测试，泄漏与否有区别吗"），讲师最后说"**这个我们线下再聊**"——本讲唯一没在课上收敛的问题。
- **消融中的反直觉现象 [43:01]**：RLEF **错误输出更少但超时错误更多**——因为它能自我修复，修复后仍不正确，于是**测试跑超时了**；讲师强调"这很多是领域特有的"。

### 3.8 讨论：代码库装不进上下文怎么办 [44:05–46:10]

学生方案：让模型判断"我需要什么信息"并配搜索工具，训练它直到认为"信息够了"再动手；把每个文档压缩成摘要；把代码做**图分解（graph factorization）**、按相似度检索（类 RAG），并在循环里加"信息够了吗"的验证。讲师回应：**"这基本就是 Claude Code 里跑的东西"**——先搜索相关代码，再应用编辑。她点名对应基准 **SWE-bench**，并说 **Azalia 实验室的 CodeMonkeys** 瞄准同样思路：所有"搜索+摘要+表征"的办法都只是**第一步**，之后才是"该打什么补丁、测试过不过"。

### 3.9 Constitutional AI：用 AI 反馈替代人类反馈 [46:10–59:28]

**起点**：RLHF 有效但不可扩展。课上一个对比：**Python 微调 + RLHF vs 纯 Python 微调，随模型规模增大，RLHF 的响应明显更好**（[47:11]）。代价是**上万条人类标签**，极其耗时乏味。

**核心洞察 [48:12]**：**"规则之所以奏效，是因为模型越来越擅长遵循指令。"** 既然模型能按格式输出、能回答"这个回复是否含有某种行为"，就可让**人类只写一次宪法**，之后人类不进循环。

**结构**：**16 条原则（constitution）** → 用原则写成 prompt，配 **red-teaming prompts** 激出有害输出 → 模型**批判**自己的输出 → **修订** → 用这些数据微调。三对 critique / revision request 示例：（1）"是否含有有害或不道德内容？"→"请删除所有有害/不道德内容"；（2）"是否含有性别偏见？请论证"→"请移除任何性别偏见的痕迹"；（3）"是否不适合儿童？"→"请改写为适合儿童的版本"。这要求模型既能**识别这些行为**，又能**遵循"移除某类内容"的指令**。

**阶段一：监督学习（SL）[49:13–51:16]**：在"自我批判+修订"生成的数据上微调。规律：**修订轮次↑ → 无害性↑、有用性↓**（被约束到固定原则后确实会变没那么有用），但**"有用性+无害性"整体单调改善**——原论文主张。学生追问（[56:20]）：这不就是在强化自己本就生成的东西的似然吗？有什么显式反馈？讲师答：是的，**这个阶段没有反馈**，就是把批判—修订轨迹当监督数据（"如果你在训练思考能力，这些就是推理轨迹"）；关键是**只要微调规模远小于基座训练规模，模型不会丢能力，只是输出分布被拉向这类回复**。

**阶段二：强化学习（RL）[52:18]**：用阶段一的回复 + 宪法训练**偏好模型**，再用它做 RL 微调（即 RLAIF），让回复趋向"最有思想、最尊重、最客气（thoughtful, respectful, cordial）"。这就是把 RLHF 的人类偏好换成"按宪法训出来的偏好模型"。**偏好模型仍需人校验 [57:21]**：让它对样例打分并**与人类做一致性比对**，只是**规模不必到上万条**，因为它基于组合性原则工作。

**结果 [53:18–55:20]**：x 轴为**训练序列数量**，y 轴分别为 **helpfulness Elo** 与 **harmlessness Elo**（人类偏好打分）。四条对比线：仅 helpfulness 的 RLHF、helpful+harmless 的 RLHF（均人类反馈）、Constitutional AI、Constitutional AI + CoT。结论：**只让模型按原则自评，模型基本同样有用（也许略差），但无害性分数明显高得多**——Claude 系列曾在这方面极强，这套技术现已被普遍采用。（*转写此处讲师先说 "much less harmless"、紧接着说 "harmlessness scores are much higher"，前后矛盾，据上下文应为"有害性低得多/无害性分数高得多"*）有学生指出**带 CoT 版本有用性更低**，讲师认同现象，但把原因归于**有用性与无害性之间的此消彼长（inverse relationship）**，而非 CoT 本身——"你总得在两者之间找到正确的平衡"。

**Pareto 前沿图 [58:26]**：y 轴 harmlessness Elo、x 轴 helpfulness Elo。预训练基座在最原始位置；只优化 helpfulness 的 RLHF 把前沿往"更有用"推；helpful+harmless 的 RLHF（橙色曲线）再往前；**Constitutional 监督学习仍不如 RLHF**；**只有 Constitutional RL + CoT 才拿到最好的帕累托前沿**——论文关键结论之一。

**可推广性与后续工作 [59:28]**：凡是"要让模型遵循一组可能互相冲突的指令"的场景都适用。后续工作包括：比较 **RLIF 与 RLHF** 的工作、**Self-Refine**（用自我反馈迭代改进）、以及"教模型用 RL 自我纠错"的工作。坑位提示：**让模型批判自己往往更难**；用**多个模型达成共识来批判**有时效果更好，因为模型会对"自己不知道什么"过度自信。

### 3.10 收尾讨论 [60:28–70:41]

- **认知科学能否系统性指导 LLM 设计？[63:32]** 现在确实在借用人类解题的类比（任务分解、并行分析），但**闭源模型做得比"把推理空间用语言写出来"更好**；根本问题是**能否自动化地在推理空间里搜索**——**搜索空间良定义（如游戏）就能自动化**，而真实任务并不良定义，只能先去环境收集观察。
- **RL 后训练成熟后，ReAct 这类手工框架会过时吗？[67:35]** **"是的，也不是。"** 是：若某任务的搜索空间能定义清楚就不需要手工框架。不是：**不可能为所有任务定义清楚搜索空间**——金融智能体、法律智能体的步骤极其领域特定。ReAct 的价值在于**定义了"推理→行动→再推理→再行动"的序列，也就是工作流**；而工作流本身领域特定，所以**跨领域泛化很难**。
- **形式化细节（课件第 12 页）[68:37]**：`C_t`（context）就是**状态**（"prompting 里的 state 就是上下文里实际有什么"）；模型每步在"输出推理轨迹"与"输出动作"之间**做选择**，所以"花一个 step 写推理"本身也算一种动作。
- **能否在解码阶段硬性限制有害输出？[69:39]** 讲师：这在一定程度上被做了，但**这些模型是在互联网上训练的，任何限制都不可能把有害内容全部清掉**；数据过滤确实存在。

## 四、论文精要

### 1) ReAct（Yao et al. 2022）

**贡献**：用提示式抽象把推理轨迹与环境动作交错（thought₁→act₁→thought₂→act₂），使外部观察能接回推理链。**关键结论**：ReAct 优于 Act-only，**在 FEVER 上超过 CoT、但在 HotpotQA 上并非总是**，与 CoT-SC 组合（双向回退）后才稳定超过基线；CoT 的主要失效模式是**幻觉**；WebShop 上 ReAct **66.6** vs 人类专家 **82.1**（score 档，success rate 更低，多步错误级联）；效果排序 prompting < fine-tuning < RL。**讲师强调**：thought 在语言空间生成、不直接影响环境；把动作生成构造成**在合法动作集上分类**是实用的接地技巧；可解释决策轨迹带来信任；局限是**大动作空间装不进上下文**与**推理成本更高**。

### 2) RLEF

**贡献**：把执行反馈接成 PPO 的二元奖励，形成"推理时迭代 + 训练时更新"的端到端自改进回路。**关键结论**：动作=代码、观察=测试通过/失败、奖励二元、算法 PPO；**双层测试**（public 小子集做推理时反馈 / private 完全隐藏只用于算奖励）**防止模型背测试**；**轮次级价值函数**让整条回复共享一个 advantage（近 GSPO 的整序列奖励）；Llama 3.1 + **CodeContests** 上 solve rate 随采样预算（**对数 x 轴**）上升并**泛化到其他代码基准**；turn 1→2→3 错误输出递减、后续轮次做**修复**；消融中**错误更少但超时更多**。**讲师强调**：基座模型光"看到错误解+反馈"不会变好，**必须训练**；二元反馈也许只在简单题上够用（可作项目方向）；过程 vs 结果奖励之争未解决；SFT 域内一定有效、RL 泛化略好。

### 3) Constitutional AI（Bai et al. 2022）

**贡献**：用人类一次性写下的原则（**16 条**）驱动模型自我批判—修订，再训偏好模型做 RL（RLAIF），在无需数万条人类标注下提升无害性。**关键结论**：RLHF 有效（规模越大收益越明显）但**需上万条人类标签**；**SL 阶段**修订轮次↑→无害性↑、有用性↓，合计单调改善，但**单独 Constitutional SL 仍不如 RLHF**；**RL 阶段**用 AI 反馈训偏好模型 → **Constitutional RL + CoT 拿下最好的帕累托前沿**；Elo 对比显示 CAI 基本同样有用（略降）而**无害性显著更高**。**讲师强调**：规则奏效的前提是模型擅长遵循指令；偏好模型仍需**小规模人类一致性校验**；微调规模远小于基座训练就不会掉能力；**自我批判往往比多模型共识批判更难**；宪法更新/遗忘旧规则属于**持续学习与遗忘的开放难题**，靠可解释性删除知识"尚未被证明可行"。

## 六、动手启示

1. **先判断反馈信号是否够硬，再决定要不要上自改进回路。** 能跑测试、能查库、能被规则判定的任务（代码、数学、SQL、检索问答）优先；纯主观任务先别急着做 RL。
2. **ReAct 最小实现**：定义一小组**合法动作**（`search`/`lookup`/`finish`），用少样本示例写清 `thought → action → observation` 格式，**严格串行**（每个 observation 必须影响下一个 thought）；要并行必须显式设计。
3. **给 ReAct 配 fallback。** 课上结论是 ReAct 并不总是赢 CoT，实践里应按 ReAct ↔ CoT-SC 双向回退，并在把答案交给用户前加一层验证 guard rail。
4. **代码/执行类智能体务必拆分 public / private 测试。** public 只用于推理时快速迭代（取小子集），private 生成期完全不可见、只用于算奖励——否则模型学到的是"背测试"。
5. **奖励粒度提前想清楚**：只在最终结果给（outcome）还是逐步给（process）？课上无定论，建议在自己的任务上做消融；若用 PPO 且是多轮修正型任务，可考虑**轮次级价值函数**（整条回复共享一个 advantage）。
6. **用"宪法/原则"做对齐或风格约束时**：人类只写一次原则 → critique → revision → 在修订轨迹上做**小规模** SFT（太大会掉能力）→ 再用 AI 反馈训偏好模型做 RL；偏好模型上线前**用少量人类打分做一致性校验**。若自我批判效果差，改成**多模型共识批判**。

## 七、遗留问题与开放挑战

- **模型的自知之明 [13:27]**：模型是否"知道自己知道什么"有争议；一致现象是**过度自信、校准很差**，讲师明确说这仍是待解决的研究问题。
- **噪声/误导性环境反馈 [23:38]**：需要反思层、回溯能力、更好的置信度度量——课上只列方向，无方案。
- **推理与行动的最优配比 [26:43]**：不同任务的最优 ratio 未知；现实中模型"想太多"，如何控制思考长度是开放问题。
- **过程奖励 vs 结果奖励 [39:56]**：讲师原话"没有彻底解决，每个领域每个基准都要重新选"。
- **SFT 还是 RL [40:58]**：讲师承认"仍是有争议的问题"——RL 泛化略好，SFT 域内一定有效。
- **public/private 切分的必要性 [41:59]**：学生质疑"反正都是训练用的测试，泄漏与否有何区别"，讲师没能当场说清，只说"我们线下再聊"。
- **二元执行反馈够不够 [37:52]**：更难的题大概需要 error trace / 更多元数据——被点名为"很好的项目方向"。
- **大代码库超出上下文 [44:05]**：需要检索 + 摘要 + 结构化表征 + "信息够了吗"的验证循环；SWE-bench 是对应基准，问题远未解决。
- **持续学习与遗忘 [53:18]**：宪法要修订、旧规则要移除时怎么办；用可解释性方法"取消"某块知识**尚未被证明可行**。
- **推理空间的自动搜索 [65:34]**：搜索空间良定义（如游戏）时可自动化；真实任务不良定义，只能先去环境收集观察——这是当前不得不用语言空间 ReAct 式方法的根本原因。
- **自我批判的可靠性 [59:28]**：模型自我批评往往比多模型共识批评更难，因为模型对自身无知过度自信。
- **（学生提问、讲师认可为项目方向，[16:31]）**：thought 与 observation 在 KV cache 表征上是否存在可区分的交错模式？
