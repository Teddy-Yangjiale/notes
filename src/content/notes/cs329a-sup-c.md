## 一、这一讲在课程里的位置

整门课讨论"自我改进"，但有一个前提问题始终悬着：**智能体的经验存在哪？** L04/L06 的改进写进了权重（训练），L02/L03 的改进留在单次会话的上下文里（用完即弃）。而真正的"持续自我改进"需要第三种载体——**跨会话、可积累、可检索的记忆**。

这一讲的两个工作恰好代表记忆的两条技术路线：**MemGPT 把记忆当系统问题**（学操作系统做分层存储与换页，模型自己管理），**Cartridges 把记忆当表示问题**（把语料离线压缩成一段可训练的 KV cache，随取随用）。前者不改权重、灵活但每步都花推理成本；后者一次性训练、服务便宜但内容冻结。

## 二、核心概念

- **虚拟上下文管理（virtual context management）**：MemGPT 的核心思想——类比 OS 的虚拟内存，通过数据在"快存（上下文窗口）/慢存（外部数据库）"之间的换入换出，让有限上下文窗口表现出"无限上下文"的效果。
- **主上下文 vs 外部上下文（main context vs external context）**：主上下文 = prompt tokens（类比 RAM）；外部上下文 = 数据库（类比磁盘），分 recall storage（完整消息历史）与 archival storage（任意长文档，可向量检索）。
- **自编辑记忆（self-editing memory）**：模型通过函数调用自己决定写什么进记忆、驱逐什么——记忆管理的决策者是 LLM 自己，不是外部规则。
- **心跳机制（heartbeat）**：函数调用可携带 `request_heartbeat=true`，执行完立刻把控制权交还模型继续推理——这是 MemGPT 实现"一次提问、多步检索"的控制流基础；没有它就退化成单步 RAG。
- **递归摘要（recursive summary）**：FIFO 队列溢出时，把被驱逐的消息压缩成摘要留在队首——有损但保连续性。
- **KV cache**：Transformer 推理时为已读 token 缓存的注意力键值；成本随输入长度增长，是长上下文服务贵的根源。
- **Cartridge**：对某个语料离线训练出来的一段小型 KV cache，推理时直接加载代替把整个语料塞进上下文。
- **自学（self-study）**：训练 Cartridge 的方法——围绕语料生成合成对话，用上下文蒸馏目标训练；朴素的"对语料做 next-token prediction"训练出来的 Cartridge 不如 ICL，这是论文的关键负结果。
- **上下文蒸馏（context distillation）**：让"只看 Cartridge 的模型"的输出逼近"看了完整上下文的模型"的输出。

## 三、论文精要

### 3.1 《MemGPT》

- **一句话贡献**：把操作系统的分层内存思想完整搬进 LLM——主上下文（RAM）+ 外部上下文（磁盘）+ 换页中断，让模型用函数调用自主管理记忆，在超长文档分析与跨会话聊天两个场景突破上下文窗口限制。
- **方法（三个层次）**：
  1. **主上下文三段式**：只读的系统指令 → 可读写的工作区（存用户事实、偏好、persona）→ FIFO 消息队列（队首带递归摘要）。队列到 70% 水位插"内存压力"警告，到 100% 驱逐一半并更新递归摘要。
  2. **外部上下文两层**：recall storage 存全部历史消息（被驱逐的永不丢失），archival storage 存长文档（实验用 PostgreSQL + pgvector，HNSW 索引，亚秒级近似查询）。
  3. **事件驱动 + 心跳控制流**：用户消息、定时器、系统警告都是事件；函数带 `request_heartbeat=true` 时执行完立即续推，模型因此能连续翻页检索多轮再作答；检索做了分页防止一次撑爆上下文。
- **关键结果**：
  - **Deep Memory Retrieval**（跨会话记住早期细节）：GPT-4 基线 32.1% → **+MemGPT 92.5%**；GPT-4 Turbo 35.3% → **93.4%**；GPT-3.5 38.7% → 66.9%
  - **嵌套 KV 检索**（140 个 UUID 对，0–4 层嵌套）：GPT-4 基线到 3 层嵌套准确率归 0；**MemGPT+GPT-4 不受嵌套层数影响**，是唯一超过 2 层还能稳定完成任务的方案
  - **多文档 QA**：性能不随文档总量增长而下降（截断基线则随压缩比恶化）
  - **Conversation Opener**：MemGPT 写的开场白在相似度指标上接近甚至超过人类手写
- **局限（论文自述）**：模型常**没翻完检索结果就提前停止**；强依赖底层模型的函数调用能力（GPT-3.5 上性能显著退化）；反直觉的是 GPT-4 Turbo 上反而不如 GPT-4（因为后者做了更多次查找）。
- **与课程主线的关系**：MemGPT 的"内存压力警告 → 模型自主决定转存"就是一个微型的**感知-决策-行动闭环**——只不过环境是自己的上下文窗口。它也是 L08"长时程任务"的基础设施：没有记忆，长时程无从谈起。

### 3.2 《Cartridges》

- **一句话贡献**：把"每次查询都把整个语料塞进上下文"换成"离线为语料训练一段小 KV cache（Cartridge）、推理时直接加载"，在长上下文基准上**与 ICL 打平，同时内存省 38.6 倍、吞吐高 26.4 倍**。
- **方法**：
  - **朴素做法的失败**：直接对语料做 next-token prediction 训练 KV cache，效果不如 ICL——这是论文最重要的负结果。
  - **self-study 配方**：围绕语料自动生成合成对话（关于语料的问答、讨论、推理），用**上下文蒸馏**目标训练 Cartridge——让加载 Cartridge 的模型复现"读过全文"的行为。训练成本一次性，可摊销到之后所有查询上。
  - **意外收获**：self-study 把有效上下文拉长（MTOB 任务上从 128k 扩展到 **484k tokens**）；且不同语料的 Cartridge **推理时可以直接拼接组合**，无需重训。
- **关键结果**：在 LongHealth、MTOB 等长上下文基准上，self-study Cartridge 与全量 ICL 打平；服务成本大幅降低（38.6× 内存、26.4× 吞吐）。
- **与课程主线的关系**：Cartridges 是"把上下文里的知识蒸馏进可复用表示"——和 L06"把推理时搜出来的轨迹蒸馏回权重"是**同一个思想在表示层的镜像**。它也指出了记忆系统的工程分界线：内容稳定、查询频繁的语料走 Cartridge（训练摊销）；内容流动、需要实时读写的走 MemGPT 式在线管理。
- **局限**：语料变了要重训（或在边界上拼接）；蒸馏质量取决于合成对话的覆盖面；与真正微调权重相比，Cartridge 只改 KV cache、不改模型能力本身。

## 四、放进课程主线里看

两条路线对应记忆系统的两个极端，中间是工程权衡：

| | MemGPT | Cartridges |
|---|---|---|
| 记忆形态 | 外部数据库（文本） | 训练出的 KV cache（向量） |
| 是否改模型 | 否（纯推理时机制） | 改 KV cache，不改权重 |
| 更新方式 | 实时读写，模型自主决定 | 离线训练，内容冻结 |
| 每次查询成本 | 高（多轮检索推理） | 极低（加载即用） |
| 适用场景 | 对话历史、流动的知识、需要反思改写 | 稳定大语料、高频重复查询 |

对照课程主线：**记忆是自我改进闭环的"硬盘"**。L02–L06 的每一环（采样经验、验证结论、反馈轨迹）如果要跨会话积累，都需要这样的持久层；而 MemGPT 的自编辑记忆 + Cartridges 的蒸馏压缩，分别给出了"怎么管"和"怎么存"的两个答案。

## 五、如果自己动手

1. **先分清语料的"流速"**：稳定且被反复查的（代码库、法规、产品文档）优先考虑 Cartridge 式离线压缩；天天在变且要读写的（用户历史、项目状态）走 MemGPT 式在线管理。多数真实系统需要两者组合。
2. **实现 MemGPT 的最小内核**：一个 FIFO 队列 + 水位警告 + 三个函数（写工作区、搜 recall、翻页 archival）+ `request_heartbeat` 标志，就能复现核心能力——难点从来不在存储，在**让模型学会什么时候该查、什么时候该停**。
3. **警惕"提前停止翻页"**：MemGPT 论文自己承认的失败模式。工程上要给检索步数设下限或显式提示"是否已查完"。
4. **评估要分层**：Deep Memory Retrieval（记得住）→ 多步检索（找得全）→ 任务端到端（用得上），三层分开测，否则定位不了瓶颈。
5. **算摊销账**：Cartridge 的训练成本是固定的，查询越多越划算；查询稀少的语料不值得做。先估算 QPS 再决定路线。
