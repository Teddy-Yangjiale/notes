## 1. 数据管线的四个算子

```text
Transformation：原始载体 → 规范文档
Filtering：单文档是否保留/权重多大
Deduplication：文档相对其他文档是否重复
Mixing：各来源以什么概率被采样
```

过滤是 unary decision，去重是 pairwise/global decision，混合是训练分布 decision。三者顺序会互相影响：先去重可防大量模板扭曲质量模型，先过滤可减少去重成本；实际常分阶段迭代。

## 2. Transformation：先定义“文档”（课件开头）

原始 web/PDF/code 不是可直接训练的字符串。转换包括：

- HTML boilerplate removal、正文与标题抽取；
- Unicode normalization、charset 修复、控制字符处理；
- PDF/OCR 阅读顺序、断行、页眉页脚；
- code 的文件边界、repo metadata；
- 对话的 role/template；
- 保留 URL、时间、source、license 等 metadata。

转换失败会制造假重复和假低质量。例如导航模板未去除，会让不同页面 Jaccard 很高；PDF 每行硬换行会让语言模型困惑。

转换应保留 raw-id → document-id 映射，支持回溯、删除和重跑。

## 3. Filtering 的目标与要求

给候选 raw distribution $R$ 和目标高质量分布 $T$，学习 score：

$$
s(x)\approx\text{“x 属于 T 或对目标训练有价值”}.
$$

理想过滤器应：高吞吐、可校准、跨语言/领域稳健、可解释、阈值可调，并能在不同训练规模下保持收益。

### 3.1 规则过滤

长度、字符比例、重复行、标点、URL、脏词、代码/数学标记等。优点便宜且可解释；缺点是阈值脆弱，多个规则叠加会形成意外偏差。

每条规则应记录：触发率、按来源/语言的保留率、抽样 false positive/negative、与其他规则的交集。

### 3.2 生成式质量模型

在目标 corpus $T$ 上训练 n-gram/KenLM，使用：

$$
s(x)=\frac1{|x|}\log p_T(x)
$$

或 perplexity。优点快、只需正例；缺点是偏好表面流畅和与 $T$ 风格相似，长程语义能力弱。ProofPile 等数学过滤可用 math corpus KenLM 与阈值筛选。

### 3.3 判别式分类器

构造正例 $x\sim T$、负例 $x\sim R$，训练：

$$
s(x)=p(y=1\mid x).
$$

模型可为 fastText/linear bag-of-words、random forest on embeddings 或 Transformer classifier。fastText 特别适合语言识别/大规模粗筛；embedding classifier 能学更复杂质量信号，但更贵且可能继承 teacher 偏见。

若训练正负采样先验与真实 corpus 不同，输出概率未校准；阈值应通过 downstream small-model training 选择，而不是默认 0.5。

### 3.4 Model-based Filtering 的闭环

DCLM 类流程：

1. 定义高质量 reference 和 random web negatives；
2. 训练过滤器并给所有文档打分；
3. 取不同 score thresholds/fractions；
4. 固定模型、tokens 和训练 recipe；
5. 比较 validation/downstream；
6. 选择在目标规模有效的阈值。

模型分类 score 只是 proxy，最终标准是训练产物。

## 4. 专门过滤器案例

### 4.1 Language ID

fastText LID 输出语言概率，但短文本、代码混合、音译和相近语言易错。应：设最小长度、允许多语言标签、按语言校准阈值，并用文档/段落两级判断。

### 4.2 Math/Code Quality

可结合 LaTeX 命令规则、目标-domain KenLM、fastText/embedding classifier 和可执行性。课件案例显示不同分类器阈值对数学/非数学文档不同，说明 score 不能跨类别直接解释。

### 4.3 Toxicity

过滤可减少有害内容，但 classifier 对身份词、方言和引用语境可能误报。全部删除还会削弱模型识别/讨论风险的能力。可采用分层标注、降权、保留安全语境，并同时评估 toxicity 与 benign-domain coverage。

## 5. Filtering 的 Scale Dependence

高阈值产生更小、更“纯”的 corpus。小训练预算下它可能最好；训练 tokens 增大后，高质量集合被重复很多 epoch，过拟合和多样性不足会使较低阈值更优。

因此不存在脱离 $N,D$ 的单一最佳 threshold。选择函数应考虑：

$$
L(\tau;N,D,U_\tau,R_\tau),
$$

$U_\tau$ 是阈值后的唯一 tokens，$R_\tau=D/U_\tau$ 是重复率。应画 threshold × scale 曲线，而非只在一个 1B-token 实验决定最终万亿 token 过滤。

## 6. 为什么 Dedup 有效

重复会：

- 浪费 compute；
- 增加记忆和逐字复现；
- 扭曲 domain/站点权重；
- 加剧 train–test contamination；
- 让 validation 因跨 split 重复而虚高。

去重必须明确单位：line、paragraph、document、file、repo 或 sequence window。太粗会误删共享引用，太细又保留重排文档。

## 7. Exact Dedup（Hash）

### 7.1 规范化

在 hash 前可做 Unicode normalization、空白折叠、大小写/标点处理。规范化越强，召回越高但误合并风险越大。应保存 raw hash 和 normalized hash 两层。

### 7.2 算法

```python
for doc in documents:
    key = hash(normalize(doc.text))
    emit(key, doc)
group_by_key()
for group in groups:
    keep(select_representative(group))
```

分布式实现按 hash partition/shuffle，使相同 key 到同一 worker，再排序/聚合。代表文档选择可按质量、来源优先级、时间或 license，而不是随便保留输入第一条。

### 7.3 Hash 选择

- SHA-256：碰撞抗性强、较慢，适合内容身份/审计；
- MurmurHash/CityHash：快，适合哈希表/大规模 shingling，但理论碰撞更多。

非加密 hash 发生相同值时可再比较 normalized bytes，避免误删。Hash 只能找到 exact normalized duplicate，不能发现插广告、改一段或镜像格式变化。

## 8. Jaccard 近重复（课件 Jaccard 部分）

把文档转为 shingles 集合，例如连续 5-grams：

$$
A=\operatorname{shingles}(d_1),\quad B=\operatorname{shingles}(d_2).
$$

Jaccard：

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|}.
$$

若 $J\ge\tau$，认为 near-duplicate。直接比较所有文档对是 $O(n^2)$，不可扩展；MinHash/LSH 用概率候选生成避免全对比较。

Shingle 大小影响：小 shingle 对局部重合敏感、误报高；大 shingle 对改写敏感、召回低。集合会忽略重复次数；必要时可用 weighted Jaccard。

## 9. MinHash 原理

设随机排列 $\pi$ 作用于 shingle universe，定义：

$$
h_\pi(A)=\min_{a\in A}\pi(a).
$$

因为 $A\cup B$ 中最小排列元素等概率是 union 中任一元素，它同时属于 A、B 的概率为：

$$
P[h_\pi(A)=h_\pi(B)]
=\frac{|A\cap B|}{|A\cup B|}=J(A,B).
$$

使用 $n$ 个独立 hash 得 signature：

$$
\operatorname{sig}(A)=(h_1(A),\ldots,h_n(A)).
$$

估计：

$$
\hat J=\frac1n\sum_{i=1}^n\mathbf1[h_i(A)=h_i(B)],
$$

其标准误约：

$$
\sqrt{J(1-J)/n}.
$$

实际不生成随机 permutation，而用多个 seeded universal/non-cryptographic hash 对每个 shingle 求最小值。

## 10. LSH Banding

MinHash signature 仍不能两两比较。把 $n=br$ 个 hash 分成 $b$ bands，每 band $r$ rows。对每个 band 的 r-tuple 再 hash 到 bucket；只要某个 band 完全相同，就成为候选对。

若真实相似度 $s=J(A,B)$：

- 一个 band 全匹配概率 $s^r$；
- 所有 bands 都不匹配概率 $(1-s^r)^b$；
- 至少一个 band 碰撞：

$$
P_{candidate}(s)=1-(1-s^r)^b.
$$

曲线呈 S 形，近似阈值：

$$
s_0\approx(1/b)^{1/r}.
$$

增大 $r$ 提高精度、降低召回；增大 $b$ 提高召回、增加候选和内存。LSH 只生成候选，最终应对候选计算真实 Jaccard 再按 $\tau$ 判定。

## 11. 从重复 Pair 到 Cluster

近重复关系可构图：文档为节点，相似 pair 为边。用 union-find/connected components 得 clusters。注意近重复不具严格传递性：A≈B、B≈C 不保证 A≈C；connected component 可能链式合并过宽。可限制 cluster 规则、选择中心或使用更严格代表比较。

代表文档应优先高质量、原始来源、许可清楚、较完整版本。记录 cluster id 和被删除成员，支持审计。

## 12. Data Mixing

设来源 $s$ 有 $N_s$ tokens。

### 12.1 Uniform 与 Proportional

- uniform：$p_s=1/S$，强 oversample 小来源；
- proportional：$p_s=N_s/\sum_jN_j$，保持原始规模，大 web 来源主导；
- temperature/power：

$$
p_s=\frac{N_s^\alpha}{\sum_jN_j^\alpha},\quad0\le\alpha\le1.
$$

$\alpha=0$ 为 uniform，$\alpha=1$ 为 proportional。

预计每来源 epoch：

$$
E_s=\frac{D p_s}{N_s}.
$$

必须检查 $E_s$，否则高质量小来源可能重复数百次。

### 12.2 Regression-based Mixing / RegMix

1. 从 Dirichlet 等分布采样多个 mixtures $p^{(i)}$；
2. 每个 mixture 训练小模型；
3. 得到目标 validation loss/能力 $y^{(i)}$；
4. 拟合 $\hat y=f(p,N,D)$；
5. 在 simplex 上优化 $p^*=\arg\min_p f(p)$；
6. 在更大模型验证 transfer。

Mixture 各分量和为 1，普通回归存在共线性；可用 log-ratio、树模型或受约束优化。小规模最优 mixture 未必能迁移，因为重复率和能力阈值随 scale 变化。

### 12.3 防止“小模型偏爱高质量小集”

若 sweep 的训练 tokens 太少，小模型看不到 oversampling 的代价。可先把每来源按最终预期 epoch 下采样，或显式把 $E_s$/unique tokens 加入回归，使过度重复的 mixture 在小实验中也受惩罚。

## 13. Post-training 与 Synthetic Data

后训练数据更像 evaluation：prompt、可验证任务、工具环境、偏好对，而不是连续 web 文档。

来源三类：

- **真实**：用户请求、GitHub PR/issue、人工题目；
- **半合成**：真实 repo/environment + 模型生成任务；
- **全合成**：模型生成 prompt、解答、critique 和 tests。

合成流程：

```text
seed domains/tasks
→ generator 产生候选
→ rule/LLM/classifier 过滤
→ verifier 执行代码/数学答案/环境 tests
→ dedup + difficulty balance
→ 小规模训练与 held-out 验证
```

强 teacher distillation 可迅速扩数据，但会继承 teacher 错误、风格和覆盖盲区。能执行就尽量执行；仅用同一模型自评会形成 correlated error。

## 14. 完整管线验证

每阶段输出 manifest：输入/输出 docs 和 tokens、按语言/来源保留率、重复 clusters、mixture epochs、PII/toxicity、benchmark overlap。训练侧做固定小模型 ablation：

```text
raw baseline
→ + transformation
→ + filtering
→ + exact dedup
→ + fuzzy dedup
→ + optimized mixture
```

同时报告 overall 和分领域 validation，避免平均值掩盖某语言/来源被清空。

## 15. 常见误区

- 过滤 score 不是客观“质量”，而是参考分布和标签器的产物。
- 一个规模的最优 threshold/mixture 不能直接外推。
- Exact hash 不能发现 near duplicates；LSH 碰撞也不是最终相似判定。
- MinHash 估计 Jaccard，需要多个独立 hash；一个碰撞证据很弱。
- 去重 cluster 代表选择会改变来源和许可证分布。
- Proportional mixing 看似中立，却让最大来源决定训练；uniform 会极端重复小来源。
- 合成数据通过语言模型 judge 不等于事实正确，优先使用外部 verifier。

本讲的核心是把数据选择从“清洗脚本集合”提升为可测量算法：过滤要通过下游训练校准，去重要通过概率候选和真实相似度验证，混合要显式考虑规模与重复率，合成数据要用独立可执行信号闭环。
