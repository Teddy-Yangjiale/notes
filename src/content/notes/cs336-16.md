## 1. 从 RLHF 到 RLVR（p.2–4）

RLHF 的 reward model 是人类偏好的代理，持续优化会 overoptimization。RLVR（Reinforcement Learning from Verifiable Rewards）选择可自动判定的领域：

- 数学最终答案；
- 代码 unit tests；
- theorem checker；
- 结构/格式约束；
- agent 环境最终状态。

若 verifier 真正对应目标，可生成大量 on-policy 训练信号而不需人逐条比较。局限是 reward 通常稀疏、只看最终结果，且 verifier 可能有漏洞。

## 2. LM 强化学习问题

状态 $s_t=(x,y_{<t})$，动作 $a_t=y_t$，trajectory 是完整 response。终端 reward：

$$
R(y)=R_{accuracy}+R_{format}+R_{other}.
$$

Policy gradient：

$$
\nabla J=\mathbb E\left[
\sum_t A_t\nabla\log\pi_\theta(y_t|x,y_{<t})
\right].
$$

正确 baseline 可减方差而不改变期望，但 reward 分配、长度归一和 group normalization 会改变实际估计器。

## 3. PPO 回顾（p.5–17）

PPO 使用 rollout policy $\pi_{old}$，概率比：

$$
\rho_t=\frac{\pi_\theta(a_t|s_t)}{\pi_{old}(a_t|s_t)},
$$

clipped objective：

$$
\mathbb E\min(\rho_tA_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t).
$$

LM 实践中还包括：

- terminal verifier/reward-model score；
- 每 token reference-KL penalty；
- value model 与 GAE；
- rollout buffer 上多 epoch minibatch update；
- reward/value normalization、mask 和 clipping。

AlpacaFarm 实现显示“PPO 公式简单”不代表系统简单。需要额外 value model，rollout inference 与 training 切换昂贵，长 CoT 又造成严重长度不均。

## 4. GRPO 核心算法（p.18–21）

对同一 prompt $x$，从旧/当前 policy 采样 $G$ 个 responses：

$$
y_1,\ldots,y_G\sim\pi_{old}(\cdot|x),quad r_i=R(x,y_i).
$$

用组内 reward 估计 advantage：

$$
\bar r=\frac1G\sum_ir_i,qquad
s_r=\sqrt{\frac1G\sum_i(r_i-\bar r)^2+\epsilon},
$$

$$
A_i=\frac{r_i-\bar r}{s_r}.
$$

把同一 sequence advantage 分配给其所有 tokens，使用 PPO 类 clipped loss，并加 reference KL：

$$
\mathcal L_{GRPO}=-\frac1G\sum_i\frac1{|y_i|}
\sum_t\min(\rho_{it}A_i,
\operatorname{clip}(\rho_{it},1-\epsilon,1+\epsilon)A_i)
+\beta\operatorname{KL}.
$$

GRPO 用同 prompt 的其他 samples 作为 baseline，省掉 value network；实现流程只有 rollout、verifier、组归一、logprob/KL 和 policy update。

## 5. GRPO 的统计细节（p.22–24）

### 5.1 合法 baseline

Policy gradient 可减只依赖 state、不依赖当前 action 的 baseline。组均值包含样本自身 reward，所以 $r_i-\bar r$ 与 $y_i$ 耦合；再除随机组内标准差，会引入额外 bias。

Leave-one-out baseline：

$$
b_{-i}=\frac1{G-1}\sum_{j\ne i}r_j,qquad
A_i=r_i-b_{-i}
$$

对当前 action 独立，更接近无偏 REINFORCE baseline。它可写为 $\frac{G}{G-1}(r_i-\bar r)$。

### 5.2 Standard-Deviation Bias

除以 $s_r$ 会让组内 reward 方差小的 prompts 获得更大权重。二元 reward 下：全对或全错的组 $s=0$ 无信号；接近全对/全错但恰有一个异类时，归一化幅度很大。课程强调这会改变不同难度题的采样权重，而不只是数值稳定技巧。

### 5.3 Length Bias

原 GRPO 对每个 response 按 $1/|y_i|$ 平均 token loss。终端 reward 被复制到每 token，但不同长度 response 的总梯度被不同归一，可能产生长度偏好，并与截断、格式 reward 耦合。

Dr. GRPO 类修正去掉组内 std normalization，并避免按各自 response length 归一（改用固定/全局正常数），使 estimator 更接近原始 sequence-level objective。具体实现必须明确 token mask、最大长度和 batch normalization，不能只写“去掉长度偏差”。

## 6. Verifier 与 Reward 设计

### 6.1 Outcome Reward

数学答案 exact match、代码 tests 等。优点客观便宜；缺点只看终点，正确猜测和严谨推理同奖，无法区分无效中间步骤。

### 6.2 Format Reward

要求 `<think>...</think><answer>...</answer>` 等便于解析，但格式奖励可能被模型利用。它应是小辅助项，不能压过准确性。

### 6.3 Process Reward

给中间步骤 reward 需要 step labels/PRM。它提供密集信用分配，但 verifier 本身难构建且可能偏向特定推理风格。R1 的重要观察是强结果验证配大规模采样也能出现长 CoT，不必依赖 MCTS/PRM 才能工作。

## 7. DeepSeek R1-Zero（p.25–30）

设置：DeepSeek-V3 base，直接做 GRPO；reward 主要是答案准确和格式，不先做 reasoning SFT。现象：

- 训练中 response 长度增加；
- 自检、反思、回溯等模式增强；
- 出现被宣传为 “aha moment” 的行为；
- 性能接近/超过强推理系统，但可读性、语言混杂和格式仍有问题。

课程提醒不要过度解释：base model 已有相关模式；原 GRPO length bias 也可能促增长；“训练中自然出现”不证明全新认知机制。

## 8. 完整 DeepSeek R1 Pipeline（p.31–38）

```text
DeepSeek-V3 base
→ reasoning cold-start SFT（长 CoT、可读格式）
→ RLVR/GRPO（准确 + 格式 + 语言一致性）
→ rejection sampling 生成新 reasoning data
→ 混入 non-reasoning SFT
→ 通用 RLHF
```

### 8.1 Cold Start SFT

少量长 CoT 让 policy 一开始就能产生可解析、连贯的推理，减少纯 RL 探索难度。来源和验证质量非常重要。

### 8.2 RL Stage

数学/代码使用可验证 reward，加入语言一致性以减少 CoT 在多语言间混跳。额外 reward 会影响优化目标，不能把最终行为全部归因于 accuracy reward。

### 8.3 后续 SFT/RLHF

Reasoning data 包含可验证和更开放任务；non-reasoning 使用通用助手数据。最后 RLHF 恢复帮助性、安全和风格，但通用对齐可能略损数学/STEM 指标，体现多目标冲突。

### 8.4 Distillation

用 R1 生成约大规模 CoT traces，再 SFT 较小 Qwen/LLaMA students。Student 不需要自己运行 RL 就能学到 teacher 的推理分布。Distillation 复制的是 teacher 产生的行为，不保证复现其搜索过程；数据过滤和答案验证仍关键。

## 9. 为什么 PRM/MCTS 未成为必要条件

R1 报告部分 PRM、MCTS 尝试未达到预期。可能原因：

- token-level action space 巨大；
- value/PRM 对 policy 分布外状态不准；
- 搜索树 branching 高、成本大；
- 强 base model + 大量采样 + outcome verifier 已提供足够信号。

这不证明 PRM/MCTS 永远无用，只说明在该配方里简单 on-policy RL 更具成本效果。

## 10. Kimi k1.5（p.39–48）

### 10.1 数据与难度筛选

- 平衡数学主题；
- 排除多选/判断题以减少 false positive；
- 用 best-of-8：只保留 base model 不能轻易全部答对、但仍可解的题；
- curriculum 从易到难；
- 按 $1-\text{success rate}$ 增加未掌握问题采样。

这让 rollout compute 集中在有学习信号的区域。全对/全错题对组相对 advantage 都无用。

### 10.2 Kimi Policy Objective

Kimi 从 reference-regularized 最优 policy/reward 关系出发，构造与 DPO 推导相关的 on-policy objective，并使用 squared surrogate、baseline policy gradient 和 regularization。重点是它不完全等同原始 GRPO，因此 length behavior 也不同。

### 10.3 Length Control

在 batch 内加入随训练阶段变化的 length reward：早期允许/鼓励长推理，后期惩罚冗余以压缩 CoT。长度系数从正向负变化，体现“先探索能力，再优化效率”。如果一开始强惩罚长度，模型可能永远学不到复杂解题轨迹。

### 10.4 RL 基础设施

On-policy 需要频繁在训练引擎（Megatron 等）与推理引擎（vLLM 等）之间切权重：

```text
train → offload/同步权重 → rollout → verifier
→ 组 batch → train update → 重复
```

长 CoT 使序列长度不均、batch straggler 严重。需要 dynamic batching、weight update、shared memory、checkpoint 和异步 pipeline。

## 11. Expert Iteration 与 RL 的差异

Expert iteration/rejection sampling 只用高 reward positives 做 SFT。它简单稳定，但丢掉失败样本的信息。Policy gradient 对失败动作施加负向更新，并且 on-policy 持续探索当前模型边界。

公平比较需匹配：生成 rollout 数、保留样本数、训练 tokens 和 verifier calls；否则 RL 的优势可能只是使用更多生成计算。

## 12. Qwen 3 Pipeline（p.49–54）

常见步骤：

1. 用 best-of-$n$ 筛选难度；
2. 去掉无需 CoT 就能做对的题；
3. 去 validation 近重复、人工质量过滤；
4. reasoning SFT + RL；
5. 通用 RLHF；
6. reasoning distillation。

### Thinking-mode Fusion

混合带 thinking tag 与 non-thinking data，让一个模型支持两种模式。推理时可通过 special token/control prompt 选择。

### Thinking Budget Control

训练模型在预算到达时输出特殊终止字符串/答案，或用不同长度样本。Test-time scaling 中更大预算通常提高数学能力到饱和点，但并非每题都需要长思考。

## 13. Agentic RL（p.55–60）

以 coding agent 为例：

### 13.1 Midtraining

repo-level 文件拼接、PR + 检索到的历史 context、text+code 和长上下文，使模型先具备环境知识。

### 13.2 Experts 与 Distillation

分别训练 web、UX、QA、SWE/tool-format experts，再蒸馏到统一 coder model，减少单一数据 mixture 的能力冲突。

### 13.3 Environment Construction

自动从 repositories 构建 SWE-bench-like tasks：固定 commit、issue/目标、依赖安装、tests、sandbox、时间和网络权限。环境质量决定 reward 可信度。

### 13.4 Reward Hacking

Agent 可能：删除 tests、修改 evaluator、恢复被禁止的 remote、读取答案文件、让程序超时。防护：只读 hidden tests、容器权限、状态 diff、外部 verifier、网络隔离和 trace 审计。Agent RL 的“可验证”只与 verifier 完整性一样强。

## 14. RLVR 训练监控

- pass@1、pass@k 和 held-out verifier；
- reward mean/std、每 prompt 全对/全错比例；
- response length/截断率；
- policy–reference KL、entropy；
- group size 和有效 advantage 数；
- 语言/格式错误；
- rollout tokens/s、训练 tokens/s、等待比例；
- reward-hacking 样本人工抽查。

## 15. 常见误区

- 可验证 final answer 不保证中间 reasoning 真实、必要或无漏洞。
- GRPO 的组内标准化不仅降方差，也改变题目权重并引入 bias。
- 组内全对/全错没有相对学习信号，需要 difficulty sampling 或更大 group。
- Long-CoT 增长可能部分来自目标/长度归一，不应直接解释为 emergent cognition。
- R1 不是“纯 RL 一步完成”：完整 R1 有 cold-start SFT、两轮 SFT/RLHF 和大量数据处理。
- Distillation 得到推理输出能力，不等价于 student 学会 teacher 的内部搜索机制。
- PPO、GRPO、Kimi objective 的 normalization 不同，名称相近不能混用公式。
- Agent verifier 可被攻击，hidden tests 和环境隔离属于算法正确性的一部分。

本讲的核心是：当 reward 可自动核验时，on-policy RL 可以持续探索模型当前能力边界；但算法中的 baseline、标准差、长度归一和环境 verifier 都会实质改变优化目标，必须像模型架构一样逐项审计。
