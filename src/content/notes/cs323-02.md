## 1. 有穷自动机基础

**有穷自动机（finite automata，有穷自动机）是识别模式的最简单的机器**：输入一个串，输出 "yes"（匹配）或 "no"（不匹配）。

| | NFA（非确定有穷自动机） | DFA（确定有穷自动机） |
|---|---|---|
| 同一状态同一符号 | 可以有**多条**出边（多个目标状态） | **恰好一条**出边 |
| ε 边 | **允许** | **不允许** |
| 构造难度 | 容易（Thompson 直接构造） | 较难（要子集构造） |
| 模拟效率 | 低（要同时跟踪多个状态） | 高（每个字符一次查表） |

**核心事实**：**NFA 与 DFA 识别的语言类完全相同**，都恰好是**正则语言**，也就是 regexp 能描述的语言。

## 2. NFA 的形式定义 ★

一个 NFA 是一个**五元组**：

1. 有穷状态集 **S**；
2. 输入符号集 **Σ**（输入字母表）；约定 **ε 永远不是 Σ 的成员**；
3. **转换函数**：对每个状态、每个 `Σ ∪ {ε}` 中的符号，给出一个**状态集合**（a set of next states）；
4. **开始状态** `s0 ∈ S`；
5. **接受状态集** `F ⊆ S`。

> 记忆：`(S, Σ, δ, s0, F)`。NFA 与 DFA 的全部差别都藏在第 3 条里：NFA 的 δ 返回**集合**且定义域含 ε，DFA 的 δ 返回**单个状态**且定义域不含 ε。

### 2.1 例子

- `S = {0,1,2,3}`，`Σ = {a,b}`，开始状态 0，接受状态 `{3}`
- 转换函数：`(0,a) → {0,1}`（**这就是非确定性**）、`(0,b) → {0}`、`(1,b) → {2}`、`(2,b) → {3}`

**转换图（transition graph）**：

```
        a,b (自环)
       ↻
start →(0) --a--> (1) --b--> (2) --b--> ((3))
```

这个 NFA 识别的语言是 `L((a|b)*abb)`。

### 2.2 转换表（Transition Table）

NFA 的另一种表示：行是状态，列是输入符号或 ε，表项列出下一状态的**集合**。

| STATE | a | b | ε |
|---|---|---|---|
| 0 | {0,1} | {0} | ∅ |
| 1 | ∅ | {2} | ∅ |
| 2 | ∅ | {3} | ∅ |
| 3 | ∅ | ∅ | ∅ |

`∅` 表示转换函数对该"状态-输入对"没有信息 —— **该动作不被允许，识别过程出错**。

> 转换表便于程序实现，但空间开销大（尤其 Σ 很大时，如 Unicode），实际实现常用压缩表。

### 2.3 串的接受（Acceptance）★

**NFA 接受串 x，当且仅当**：转换图中**存在**一条从开始状态到某个接受状态的路径，路径上的符号连接起来构成 x（**ε 标签被忽略**）。

- 注意是"**存在一条**"，不是"所有路径"。只要有一条成功路径就接受。
- **NFA 定义（接受）的语言**：所有能标记一条从开始状态到某个接受状态的路径的串的集合。

例：上面的 NFA 接受 `aabb`（路径 0→0→1→2→3，前两个 a 中第一个走自环）。

### 2.4 识别语言练习

| NFA 描述 | 语言 |
|---|---|
| 0 上 a,b 自环，0-a→1-b→2-b→3(接受) | `L((a\|b)*abb)` |
| 起点 ε 分叉：一支 a 后 a 自环，一支 b 后 b 自环 | `L(aa* \| bb*)` |

## 3. DFA 的定义与模拟

**DFA 是特殊的 NFA**，满足：

- 没有 ε 上的动作（no moves on input ε）；
- 对每个状态 s 和每个输入符号 a，**恰好有一条**标号为 a 的出边（恰好一个目标状态）。

### 3.1 模拟 DFA 的算法 ★

```
输入：以 eof 结尾的串 x；DFA D（开始状态 s0，接受状态集 F，转换函数 move）
输出：D 接受 x 则 "yes"，否则 "no"

s = s0;
c = nextChar();
while (c != eof) {
    s = move(s, c);
    c = nextChar();
}
if (s ∈ F) return "yes";
else        return "no";
```

**结论**：DFA 能以 **O(|x|)** 时间、每字符常数次查表地接受/拒绝串，这正是词法分析器要用 DFA 而不是 NFA 的原因。

### 3.2 DFA 例子

给定输入串 `ababb`，某 DFA 依次进入状态 `0,1,2,1,2,3` 并返回 "yes"。

## 4. 从正则表达式到自动机：总路线

- regexp 简洁精确地描述 token 模式；
- DFA 能高效识别模式（相比之下，NFA 的模拟不直接——**看到一个符号时可能有多条转换**）；
- 因此实现词法分析器时：

```
Regexp ──Thompson's construction──▶ NFA ──subset construction──▶ DFA
```

## 5. 子集构造算法（Subset Construction，子集构造法）★★★

### 5.1 核心洞察

**构造出的 DFA 的每个状态，对应 NFA 状态的一个子集（集合）。**

为什么？因为读完输入 `a1a2...an` 后，**DFA 只处在一个状态，而 NFA 可能处在多个状态**。算法"并行模拟" NFA 在给定输入下所有可能的动作，把一组 NFA 状态映射成一个 DFA 状态。

### 5.2 三个基本操作 ★

| 操作 | 定义 |
|---|---|
| `ε-closure(s)` | 从 NFA 状态 s 出发，**只沿 ε 边**能到达的状态集合（含 s 自身） |
| `ε-closure(T)` | `⋃_{s∈T} ε-closure(s)`，T 中某个状态只沿 ε 边可达的所有状态 |
| `move(T, a)` | T 中某个状态在输入符号 **a** 上可以转移到的状态集合 |

### 5.3 计算 ε-closure(T)：一次图遍历

```
把 T 的所有状态压栈;
result = T;
while (栈非空) {
    弹出栈顶 t;
    for (每条从 t 出发、标号为 ε 的边 t → u)
        if (u ∉ result) { 加入 result; 把 u 压栈; }
}
return result;
```

**本质就是只沿 ε 边做 DFS/BFS。**

### 5.4 主算法

```
初始：Dstates 只含一个未标记状态 ε-closure(s0)
while (Dstates 中存在未标记状态 T) {
    标记 T;
    for (每个输入符号 a) {
        U = ε-closure( move(T, a) );
        if (U ∉ Dstates) 把 U 作为未标记状态加入 Dstates;
        Dtran[T, a] = U;
    }
}
```

- **开始状态**：`ε-closure(s0)`
- **接受状态**：所有**含有至少一个 NFA 接受状态**的子集
- "未标记"表示这个状态的后继还没被探索过 —— 整个算法就是一次**工作表（worklist）搜索**。

### 5.5 完整实例（课件例子）★

NFA（识别 `(a|b)*abb`，接受串 `babb`），Σ = {a,b}，开始状态 0，接受状态 10：

```
0 -ε→ 1, 7
1 -ε→ 2, 4
2 -a→ 3
4 -b→ 5
3 -ε→ 6      5 -ε→ 6
6 -ε→ 1, 7
7 -a→ 8
8 -b→ 9
9 -b→ ((10))
```

**第 0 步**：`ε-closure(0)`（用栈演示）

| 动作 | 栈 | result |
|---|---|---|
| 压 0 | 0 | {0} |
| 弹 0，压 1,7 | 1,7 | {0,1,7} |
| 弹 7（无 ε 边） | 1 | {0,1,7} |
| 弹 1，压 2,4 | 2,4 | {0,1,7,2,4} |
| 弹 4、弹 2（无 ε 边） | 空 | {0,1,2,4,7} |

→ `A = {0,1,2,4,7}`（开始状态）

**练习（课件留的）**：`ε-closure({3,8}) = {1,2,3,4,6,7,8}`
（3 -ε→ 6 -ε→ 1,7；1 -ε→ 2,4；8 无 ε 出边）

**逐步探索**：

| 当前 | 输入 | move | ε-closure | 结果 |
|---|---|---|---|---|
| A={0,1,2,4,7} | a | {3,8} | {1,2,3,4,6,7,8} | 新状态 **B** |
| A | b | {5} | {1,2,4,5,6,7} | 新状态 **C** |
| B={1,2,3,4,6,7,8} | a | {3,8} | {1,2,3,4,6,7,8} | 已存在 → B |
| B | b | {5,9} | {1,2,4,5,6,7,9} | 新状态 **D** |
| C={1,2,4,5,6,7} | a | {3,8} | = B | B |
| C | b | {5} | = C | C |
| D={1,2,4,5,6,7,9} | a | {3,8} | = B | B |
| D | b | {5,10} | {1,2,4,5,6,7,10} | 新状态 **E** |
| E={1,2,4,5,6,7,10} | a | {3,8} | = B | B |
| E | b | {5} | = C | C |

**最终 DFA**：

| STATE | a | b |
|---|---|---|
| **A**（开始） | B | C |
| B | B | D |
| C | B | C |
| D | B | **E** |
| **E**（接受，含 10） | B | C |

- 开始状态 A，接受状态 `{E}`（因为 E 含 NFA 的接受状态 10）；
- 课件提示：**该 DFA 还可最小化** —— A 和 C 在所有符号上的动作相同（a→B, b→C），可以合并。

**验证 `babb`**：A --b→ C --a→ B --b→ D --b→ E ∈ F ✔

### 5.6 复杂度直觉

- n 个 NFA 状态 → 最坏情况 `2ⁿ` 个 DFA 状态（指数爆炸），但实际中通常很小；
- 时间换空间的权衡：DFA 构造一次、运行无数次，对词法分析器是划算的。

## 6. Thompson 构造算法（Regexp → NFA）★★★

算法**递归地**把 regexp 拆成子表达式，用下面的规则自底向上构造 NFA。

**不变量（非常重要）**：构造出的每个 NFA **只有一个开始状态和一个接受状态**，且接受状态**没有出边**。这保证了各条规则可以自由拼接。

### 6.1 两条基础规则

**规则 1**：空表达式 ε

```
start →(i) --ε--> ((f))
```

**规则 2**：单个符号 a ∈ Σ

```
start →(i) --a--> ((f))
```

### 6.2 三条归纳规则

**归纳规则 #1：并（union）`s | t`**

新建开始状态 i 和接受状态 f：

```
        ε ↗ N(s) ↘ ε
start →(i)            ((f))
        ε ↘ N(t) ↗ ε
```

- i 到 N(s)、N(t) 的**旧开始状态**各加一条 ε 边；
- N(s)、N(t) 的**旧接受状态**各加一条 ε 边到 f；
- 旧的开始/接受状态失去其"开始/接受"身份。

**归纳规则 #2：连接（concatenation）`st`**

```
start →[ N(s) ]--[ N(t) ]→ ((f))
```

- **把 N(s) 的接受状态和 N(t) 的开始状态合并成一个状态**（不需要新建状态，也不需要 ε 边）；
- 开始状态取 N(s) 的开始状态，接受状态取 N(t) 的接受状态。

**归纳规则 #3：Kleene 闭包 `s*`**

新建开始状态 i 和接受状态 f：

```
                  ┌──────ε──────┐（回边，实现"重复"）
                  ↓             │
start →(i) --ε--> [ N(s) ] --ε--> ((f))
         └──────────ε────────────┘（跳过边，实现"零次"）
```

四条 ε 边：`i → N(s).start`、`N(s).accept → f`、`N(s).accept → N(s).start`（重复）、`i → f`（零次）。

### 6.3 性质

- 若 regexp 有 `n` 个符号和算符，构造出的 NFA 至多 `2n` 个状态、至多 `4n` 条边；
- 每个状态至多 2 条出边。

### 6.4 完整例子：`r = (a|b)*a`

先画语法结构（从外到内拆）：

```
        concat
        /     \
      *        a
      |
      |
      a   b   （即 (a|b)）
```

构造步骤（课件的 6 步）：

1. 为第一个 `a` 应用基础规则 → `N(a)`：`(2)--a-->(3)`
2. 为 `b` 应用基础规则 → `N(b)`：`(4)--b-->(5)`
3. 为 `(a|b)` 应用归纳规则 #1：新建 1、6，`1-ε→2, 1-ε→4, 3-ε→6, 5-ε→6`
4. 为 `(a|b)*` 应用归纳规则 #3：新建 0、7，`0-ε→1, 6-ε→7, 6-ε→1, 0-ε→7`
5. 为第二个 `a` 应用基础规则 → `(7')--a-->(8)`
6. 为 `(a|b)*a` 应用归纳规则 #2：把第 4 步的接受状态 7 与第 5 步的开始状态合并

最终：开始状态 0，接受状态 8。

> 做题技巧：**先把 regexp 画成语法树，再严格自底向上套规则，并按构造顺序给状态编号**（这样编号与构造过程一致，批改老师一眼能看懂）。

## 7. 合并多个 NFA（词法分析器的做法）★

### 7.1 为什么要合并

词法分析器需要**一个自动机**同时识别匹配**任意模式**的词素。

### 7.2 怎么合并

引入一个**新的开始状态**，用 **ε 边**连到每个模式 `pi` 的 NFA 的开始状态。

- 大 NFA 接受的语言 = 各小 NFA 接受语言的**并**；
- **不同的接受状态对应不同的模式**（这是关键：接受状态携带"我匹配的是哪个 token"的信息）。

### 7.3 转成 DFA 后的冲突处理 ★

用子集构造把大 NFA 转成 DFA：

- DFA 的接受状态对应一个 NFA 状态子集，其中**至少有一个是 NFA 的接受状态**；
- 如果子集中**有多个 NFA 接受状态**，说明**冲突**：输入的这个前缀同时匹配多个模式；
- **消解规则：取在规则列表中出现最早（先声明）的那个模式**作为该 DFA 状态的输出。

### 7.4 例子

三个模式：

| 模式 | 动作 |
|---|---|
| `a` | A1（p1） |
| `abb` | A2（p2） |
| `a*b+` | A3（p3） |

- 先为每个模式构造 NFA；
- 用新开始状态 + ε 边合并；
- 子集构造转 DFA。

其中某个 DFA 状态同时含 NFA 接受状态 6（属于 p2 的 `abb`）和 8（属于 p3 的 `a*b+`），按"先声明优先"选择 **p2**。

> 除了"先声明优先"，实用的词法分析器还遵循**最长匹配优先（maximal munch）**：先尽量往后读，直到无法继续匹配，再回退到最后一次进入接受状态的位置。两条规则配合使用（`<` vs `<=`、`if` vs `iffy` 都靠它们消解）。

## 8. 三种表示的转换关系总结

```
        Thompson            subset construction        Hopcroft
regexp ────────────▶ NFA ─────────────────────▶ DFA ────────────▶ 最小 DFA
   ▲                                              │
   └──────────── Kleene 构造（状态消去法）───────────┘
```

三者**表达能力等价**，都刻画正则语言。
