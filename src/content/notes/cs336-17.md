## 1. 多模态模型的两个问题

1. **理解**：如何把图像/视频/音频变成与文本 LM 对齐的表示？
2. **生成**：如何让统一模型输出非文本模态？

Transformer 处理 token 序列。token 可为：

- 离散 ID：文本 BPE、VQ image code；
- 连续向量：ViT patch features、audio features；
- 不同模态 token 的交错序列。

连续视觉 encoder + projector + LLM 容易做理解，但不能直接生成 pixels；离散统一 tokenizer 能自回归生成，但图像 token 熵高、序列长，训练更难。

## 2. Vision Transformer 基础

图像 $X\in\mathbb R^{H\times W\times3}$ 用 $P\times P$ patch 切分，patch 数：

$$
N=\frac HP\frac WP.
$$

每个 patch flatten 后线性投影：

$$
z_i=W_p\operatorname{vec}(patch_i)+e_{pos,i}.
$$

再经过 Transformer encoder。ViT-L/14@336 表示 large ViT、14×14 patch、336 输入；token 数为 $24\times24=576$（忽略特殊 token）。分辨率提高会二次增加 visual tokens 和 vision attention 成本。

## 3. CLIP（Contrastive Language–Image Pretraining）

### 3.1 双编码器

batch 中有 $B$ 对 $(I_i,T_i)$：

$$
u_i=\frac{f_I(I_i)}{\|f_I(I_i)\|},\qquad
v_i=\frac{f_T(T_i)}{\|f_T(T_i)\|}.
$$

相似度：

$$
s_{ij}=\frac{u_i^Tv_j}{\tau},
$$

$\tau$ 为学习/固定 temperature。

### 3.2 对称 InfoNCE Loss

Image-to-text：

$$
\mathcal L_{I\to T}=-\frac1B\sum_i
\log\frac{e^{s_{ii}}}{\sum_je^{s_{ij}}}.
$$

Text-to-image：

$$
\mathcal L_{T\to I}=-\frac1B\sum_i
\log\frac{e^{s_{ii}}}{\sum_je^{s_{ji}}}.
$$

总 loss 为二者平均。batch 内其他 $B-1$ 对是 negatives，所以大 batch 提供更多负例，但分布式训练需 all-gather embeddings 形成全局 $B\times B$ similarity，通信和内存增长。

### 3.3 数据与预处理

CLIP 通过大量查询收集约 400M noisy image–text pairs。图像通常 resize/crop 到固定分辨率、normalize；这会丢 OCR、小物体和原始纵横比信息。

Text supervision 给视觉 encoder 注入语义，不要求固定类别标签。Zero-shot classification 将类别写成文本模板，计算 image embedding 与各 class text embedding 相似度。

### 3.4 为什么比 caption generation 高效

Caption decoder 必须逐 token 预测完整文本；CLIP 只做 batch pair ranking，训练信号直接作用于全局语义表示，更适合大规模弱配对数据。但 CLIP 优化的是对齐/检索，细粒度空间关系和像素细节不一定强。

## 4. SigLIP

CLIP 对每行/列做 multiclass softmax，依赖全局 negatives。SigLIP 把每个 pair 做二分类。令 $z_{ij}=+1$ 当 $i=j$，否则 $-1$：

$$
\mathcal L=-\frac1{B^2}\sum_{ij}
\log\sigma(z_{ij}(\alpha u_i^Tv_j+b)).
$$

### 4.1 关键差异

- 每个 pair 的 sigmoid loss 不需在全局 batch 上归一；
- batch size 与 loss 定义解耦，小 batch 也能工作；
- 分布式上可把 negatives 分块/旋转计算，降低 all-gather 压力；
- 正负极不平衡，需要 bias/normalization 和高效实现。

WebLI 使用十亿级图文、OCR text 等。课程对比显示 SigLIP 用更少 TPU/时间达到强结果，但不能只归因于 loss：数据、硬件和实现也不同。

## 5. 从对齐 Encoder 到视觉助手：LLaVA

### 5.1 架构

```text
image
 → frozen CLIP ViT patch features Z_v
 → trainable projector W
 → LLM embedding-width visual tokens
 → 与 text tokens 拼接
 → causal LLM 生成回答
```

若 $Z_v\in\mathbb R^{N_v\times d_v}$：

$$
H_v=Z_vW,quad W\in\mathbb R^{d_v\times d_{lm}}.
$$

视觉 tokens 放在 `<image>` 占位位置，LLM self-attention 可共同处理视觉与文本。

### 5.2 合成 Instruction Data

利用 COCO captions/bounding boxes 让 GPT-4（只读文本描述）生成 conversation、detailed description、reasoning questions，再与原图配对。它把廉价 annotation 转为多轮视觉指令，但 teacher 没直接看 pixels，问题/回答受 caption 信息上限限制。

### 5.3 两阶段训练

1. **Alignment**：冻结 vision encoder 和 LLM，只训练 projector $W$，让视觉 feature 进入 LM embedding space；
2. **Instruction tuning**：冻结 vision encoder，训练 projector + LLM，使其按多模态指令回答。

先对齐再联合可避免随机 projector 的噪声破坏 LLM。也意味着视觉 encoder 的细粒度缺陷难被修复。

## 6. LLaVA-OneVision 与 AnyRes

固定 336 crop 会丢小字和高分辨率结构。AnyRes：

1. 选与原图纵横比接近的网格 $a\times b$；
2. 每块 resize 到 vision encoder 基础分辨率并独立编码；
3. 保留 global/base view；
4. 按空间顺序拼接/加入分隔；
5. 若 visual tokens 过多，用 bilinear interpolation/pooling 压缩。

OneVision 使用 SigLIP 特征、Qwen2 decoder，统一单图、多图、视频：

- 单图可给更高分辨率；
- 多图每图基础分辨率，控制总 token；
- 视频每帧更低分辨率并稀疏采样。

跨场景 transfer 的来源是共享视觉表示和 LM：单图 OCR、关系推理、visual prompting 训练可迁移到视频/GUI。但“出现能力”仍应检查是否来自训练数据近似任务。

## 7. Qwen-VL 三阶段训练

架构仍是 vision encoder + adaptor/resampler + Qwen LM，并加入 `<img>`、`<box>`、`<ref>` 等 tokens 支持 grounding。

1. **大规模预训练**：低质量海量图文，冻结 LM，训练 vision encoder + adaptor；
2. **多任务学习**：更高质量 caption/OCR/VQA/grounding，提高分辨率并训练更多参数；
3. **Instruction tuning**：冻结或弱调 visual encoder，训练 adaptor + LM 的聊天行为。

先建立视觉词汇，再学习任务，最后对齐交互，减少阶段目标冲突。

## 8. Qwen2-VL：Dynamic Resolution 与 MRoPE

### 8.1 Naive Dynamic Resolution

图像不强制到单一尺寸，而按原始分辨率映射为可变数量 patches。ViT/14 处理后，2×2 spatial merge 把四个 patch tokens 压成一个，降低送入 LLM 的长度。

高分辨率图获得更多 tokens，OCR/图表更强；成本随像素增长，必须设置 min/max pixels。视频按固定帧率采样并限制总 visual tokens。

### 8.2 Multimodal RoPE

文本位置是一维；图像需要 $(h,w)$，视频需要 $(t,h,w)$。MRoPE 把 head dimensions/frequency bands 分给 temporal、height、width：

$$
R_{multi}=R_t\oplus R_h\oplus R_w.
$$

文本可令三轴位置同步增长，图像/视频分别编码空间时间坐标。这样同一 causal Transformer 接受不同模态而保留结构。

## 9. Qwen3-VL 的进一步设计

- 使用 SigLIP-2 视觉 encoder；
- Interleaved MRoPE 将 t/h/w 信息分布到低频和高频，不让单轴只占某一频段；
- 视频 timestamp 作为显式 tokens，而不只藏在 position embedding，便于语言模型直接引用时间；
- dense/MoE Qwen3 decoders 扩展容量。

### 9.1 多模态 Loss Balancing

视频样本 token 很长。若简单按所有 tokens 平均，视频会因 token 数主导梯度；若每样本平均，极短文本与超长视频权重相同。课件提到 square-root-normalized per-token loss，可在“按 token”与“按样本”之间折中，例如样本权重与 $1/\sqrt{T_i}$ 相关。具体公式必须与实现核对，但核心是显式控制模态/长度贡献。

## 10. Chameleon：统一离散 Token 模型

### 10.1 VQ-VAE Tokenizer

Encoder 得连续 latent $z_e$，对 codebook $\{e_k\}_{k=1}^K$ 量化：

$$
k^*=\arg\min_k\|z_e-e_k\|^2,qquad z_q=e_{k^*}.
$$

Decoder 从 $z_q$ 重建图像。训练包括 reconstruction/perceptual loss、codebook 和 commitment loss（常用 stop-gradient）：

$$
\mathcal L=\mathcal L_{recon}
+\|\operatorname{sg}[z_e]-e\|^2
+\beta\|z_e-\operatorname{sg}[e]\|^2.
$$

课件案例把 512×512 图像编码为 1024 tokens，codebook 8192。图像可被离散 ID 表示并由自回归 LM 生成。

### 10.2 统一词表与序列

文本 BPE tokens 和 image code tokens 放进统一 vocabulary/序列：

```text
text → image → text → image ...
```

模型用同一 next-token loss 学理解和生成。训练数据包括纯文本、图文对和交错文档，并分阶段扩大多模态比例。

### 10.3 数值稳定问题

文本 token entropy 相对低，图像 code entropy 高；共享 softmax 时图像 logits/hidden norm 可能增长并导致 logit drift。Chameleon 使用 QK-Norm、z-loss 等稳定：

$$
\mathcal L_z=\alpha(\log\sum_je^{l_j})^2.
$$

### 10.4 优缺点

优点：统一、自回归、可交错理解和生成。缺点：图像 token 很长、高熵，细节重建受 VQ tokenizer 限制；相比 diffusion，生成质量/效率有不同 trade-off。

## 11. 理解 Encoder 与生成 Decoder 的目标冲突

CLIP/SigLIP 鼓励语义不变性：不同 crop/像素细节只要语义相同，embedding 可接近。图像生成却需要保留纹理、颜色、位置等低层细节。因此最适合理解的 encoder 不一定适合重建。

现代系统常组合：

```text
连续 vision encoder → 语义理解
LLM → 推理/规划/文本
diffusion/flow decoder → 高保真图像生成
```

而统一离散模型追求接口简洁，但承担更高序列与建模难度。

## 12. 多模态数据与计算账本

visual token 数决定 LLM context 和 attention 成本：

$$
T_{total}=T_{text}+\sum_iT_{image,i}+\sum_fT_{frame,f}.
$$

训练必须平衡：分辨率、帧率、多图数量、OCR 细节、batch size 和 context length。图像/视频虽然原始信息密度高，经过冗余 patches 后每 token 的监督密度可能不同于文本，不能只按 token 数混合。

## 13. 训练与评估清单

### 对齐

- image↔text retrieval、zero-shot classification；
- global batch/negative 数影响；
- 按语言、OCR、细粒度类别分层。

### 理解

- VQA、OCR、chart/document、grounding、多图关系、视频时间；
- 分辨率/visual-token budget 控制；
- 防止只凭文本 prior 回答，使用 counterfactual images。

### 生成

- reconstruction/codebook utilization；
- 图像质量、文本渲染、prompt adherence；
- 同时检查语义和细节。

## 14. 常见误区

- CLIP 的 batch 其他样本是 negatives；SigLIP 才把 pair 独立 sigmoid 化。
- CLIP embedding 强不代表细粒度空间/OCR 一定强。
- Projector 不只是 reshape，而是在两个预训练表示空间间学接口。
- AnyRes 保留细节但 visual tokens 和 LLM 成本显著增加。
- MRoPE 不是把图片 flatten 后只用普通一维位置。
- 多模态 loss 若不按长度/模态平衡，视频可能主导训练。
- 连续视觉 encoder + LLM 通常只能理解，不能直接生成 pixels。
- VQ token 统一接口的代价是量化误差、高熵和长序列。

本讲的核心是把模态接口分解为三层：tokenization 决定保留什么信息，对齐目标决定表示学什么语义，LLM/decoder 决定如何推理和生成。任何多模态架构都必须在语义抽象、细节保真和 token 计算之间做明确权衡。
