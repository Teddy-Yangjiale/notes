## 一、本讲要解决什么问题（TL;DR）

前面几讲讲的是**推理时扩展（test-time scaling）**：同一个模型多采样几次、多数投票、用工具/代码/验证器挑答案。本讲要回答的是：能不能把推理时搜索产出的"好轨迹"喂回模型，让模型**下一次 pass@1 就做对**，从而把推理算力的收益"固化"进权重里——这就是**训练时扩展（train-time scaling）**。

三条递进主线：STaR 用"采样 → 只保留答对的 → 微调 → 再来一轮"的**自举（bootstrapping）**闭环把推理链造出来；DeepSeekMath 用 **GRPO**（用组内基线替代 critic）把这条闭环换成省显存、可扩展的在线 RL，7B 模型在 MATH 上从 46.8 提到 51.7；DAPO 则把 GRPO 直接搬到大模型长思维链上暴露出的**熵坍缩、输出长度爆炸、训练不稳**等工程问题逐个修掉，在 Qwen 32B 上把 AIME 从 30 分推到 50 分。

讲师反复强调一句总纲：**这些方法提升的是 majority@K，而不是 pass@K**——模型变得更"一致、更会答对已会的问题"，而不是获得了从根本上解新问题的能力。

## 二、核心概念与术语

- **训练时扩展（train-time scaling）**：把模型自己的输出（经过筛选/打分）当作训练信号回灌进模型，用训练算力换模型参数。讲师给的定义是"把 test-time scaling 之后过滤出来的模型输出拿来继续微调"（[05:09]）。与"预训练 = 在互联网上训练"相对。
- **推理时扩展（test-time scaling）**：上一讲的技术，多数投票、best-of-N、推理期采样聚合等纯推理侧技巧。
- **可验证性（verifiability）**：能否判定一条输出对/错。这是训练时扩展成立的前提——数学有最终答案，代码有单元测试与执行反馈，所以能闭环；个人写作、文本编辑这类没有可靠验证信号的领域收益明显更小（[11:20]，GPT-4o 对比 thinking model 的胜率在可验证域 >50%，写作/编辑域则不高）。
- **STaR 自举（bootstrapping）**：小模型先少样本（few-shot）生成推理链（rationale），只保留最终答案正确的样本微调模型，再用变强的模型重新生成，迭代。
- **合理化 / 反向解释（rationalization）**：STaR 的关键补丁。对模型做不对的题，**把正确答案当提示（hint）喂给它**，让它倒着编出一条通往该答案的推理链，然后把"题目 + 推理链 + 答案"加入训练集（训练时不带 hint）。用来把难题也纳入训练分布。
- **拒绝采样微调（Rejection sampling Fine-Tuning, RFT）**：生成多条、只留下答对的、拿去 SFT。STaR 可视为其迭代版；RFT 的"在线"版（online RFT）是本讲比较 GRPO 时的基线之一。
- **PPO**：RLHF 的标准算法，需要同时常驻 **4 份模型**——旧策略（old policy）、新策略（new policy）、critic（价值函数）、奖励模型（reward model）。显存是它 scale 不上去的主要瓶颈。
- **GRPO（Group Relative Policy Optimization）**：DeepSeekMath 提出。去掉 critic/价值网络，改成**对每个问题采样一组答案、用组统计量当基线**：advantage ≈ (r − mean(r)) / std(r)。只需 3 份模型，省显存因而能 scale。讲师点明其合理性来源：奖励模型本来就是在**比较数据**上训的，给"组内相对比较"的上下文天然合适（[44:55]）。
- **DAPO**：字节/清华开源的 RL 系统论文，针对长思维链场景把 GRPO 的一堆实现细节显式化、修好。
- **clip-higher（非对称裁剪）**：PPO 的裁剪对概率上升和下降用同一个 ε，低概率 token 涨不上去、高概率 token 又被截断，**探索被压死（entropy collapse）**。改成上界更宽的**非对称裁剪**，允许更大的正向概率提升。
- **动态采样（dynamic sampling）**：过采样后，**丢掉"全对"和"全错"的组**，只保留 0 和 64 之间、有区分度的组。因为全对/全错组的 advantage 恒为 0，只会白占 batch、浪费梯度。
- **token 级损失（token-level loss）**：GRPO 默认按**样本级（sample-level）**算损失，一整条序列算一个损失，于是一条很长的垃圾回答和一条短的好回答权重相同。改成按 token 加权（本质是长度惩罚/形状控制），可同时压住熵和输出长度。
- **超长惩罚 / 软性超长惩罚（overlong filtering / soft overlong punishment）**：思维链太长被截断会引入大量噪声。两条路：一是直接过滤掉超长样本，二是给接近长度上限的 token 加**渐进式惩罚**，让训练重新稳定。
- **熵（entropy）**：讲师把它当作"模型还有多少探索空间"的代理指标。熵坍缩 = 模型过早过度自信、不再探索；熵持续上涨 = 输出失控。两头都要盯。
- **majority@K vs pass@K**：pass@K = 采样 K 次里至少一次对（衡量"能不能解出来"的上界）；majority@K = 多数投票后的正确率（衡量"输出的稳定性/一致性"）。本讲核心论断：这三种方法只推高了后者。
- **蒸馏回训练（distilling test-time compute back into the model）**：把"扔意大利面看哪根粘墙上"（[14:24]，讲师原话）的推理期搜索，通过 SFT/RL 变成模型内化的 pass@1 能力。

## 三、主线内容

### 1. 动机：为什么 7B 模型能在 AIME 上打过 175B？（[01:07]–[03:08]）

课程启用了新基准 **AIME 2024 / AIME 2025**（MATH 基准今年已经饱和且被大量模型污染，所以换掉；作业一用的是更新的数学推理基准）。关键对比：

| 设置 | AIME 准确率 |
|---|---|
| GPT-3.5（175B） | ≈ **5%** |
| DeepSeekMath（**7B**，训练时扩展） | **51.7%**，加上额外技巧可达 **60%** |
| DAPO（**Qwen 32B**） | **50%** |

这直接打脸了第一讲的"参数量越大能力越强"叙事：**小模型也能在推理基准上拿到高分，靠的是训练时扩展**。讲师给出三条 insight：

1. 训练完就结束的时代过去了——**让模型从自己的输出里学，只要筛选得当，还能再涨**（这也是本课叫"自我改进智能体"的原因）。
2. **投在"拿模型自身输出训练"上的算力，可以替代模型参数**。这与"给小模型喂更多数据也能涨"的早期结论一脉相承。
3. **RL 比监督学习对实现细节敏感得多**，规模一大，一个小小的修正确定性极强。

### 2. 四种范式与"闭环"的定义（[04:08]–[05:09]）

讲师把技术栈划成四层：**预训练（在 internet 上训练）→ 微调 / RLHF / RLHF-on-preference-data（得到 chatbot）→ 推理时扩展（majority voting、推理期采样聚合等）→ 训练时扩展**。最后一步的定义非常朴素：**把推理时扩展产出的模型输出过滤一遍，再拿去微调**。"如果你这一讲什么都没记住，只记住这个闭环，那你就学到了训练时扩展的基础。"

学生当场问了三个问题，讲师都押后到讲完三篇论文再答：① 训练时算力和推理时算力怎么分配、有没有 ROI 平台；② 训难题会不会让简单题回退；③ SFT vs RL 什么时候选、数据和算力差多少（[17:26]、[15:24]、[35:45]）。

### 3. 训练算力 vs 推理算力（[06:09]–[12:22]）

o1 发布时的那张图：横轴分别是**训练时算力**（左）和**推理时算力**（右），纵轴是 AIME 的 **pass@1**，两条都是 log-linear 上升——**两个方向的算力都能换 pass@1**，而且互为循环：生成输出 → 回灌 → 模型变强 → 生成更好的输出。

有学生当场指出这张图"左图的斜率看起来比右图更划算、有点可疑"，讲师承认"我是直接拷的图，他们家的图不总是对的"（[12:22]，全场笑）。随后讲师补了限定条件：**测试时算力只在验证器足够鲁棒的基准上划算**，否则你必须先让模型本身会推理，两条路各有其目的。

### 4. 为什么是数学？推理链里到底发生了什么（[07:10]–[11:20]）

训练时扩展在**可验证域**最有效。讲师用一个细致的观察说明"thinking"到底多出了什么 token：思维链里的 token 会花在四类行为上——**问题分析（problem analysis）、任务分解（task decomposition）、自评与回溯（self-evaluation / backtrack）、并行尝试多种解法（try different approaches）**。

o1 系列的两个例子：① 用户要一个 bash 脚本打印矩阵转置，模型先确认输入输出格式再动手（问题分析），然后显式列出"解析输入串 → 建矩阵 → 转置 → 按同样格式输出"（任务分解）；② 一道化学 pH 题，模型算到一半突然说"等一下，正确的公式不是这个"，然后换公式重算（自我纠正）。这些行为在**数学、编程、数据分析**上让 thinking model 相对 GPT-4o 的胜率超过 **50%**，而**个人写作、文本编辑**收益很有限。

### 5. STaR：用推理教推理（[15:24]–[33:41]）

**问题背景**（[16:25]）：Chain-of-thought 既提供可解释性又提升数学/常识推理，但拿推理链数据很贵——**互联网规模的数据里几乎不自带推理步骤**、人工标注极贵、按模板自动生成只适用于极窄的领域、few-shot  prompting 又干不过"在大量（无推理链的）数据上微调"。

**STaR 的做法**（17:26 起，讲师给的代表性数字）：
1. 用一个**小的、带 rationale 的种子集**（few-shot 提示用）；
2. 对约 **10K 道题**采样生成 rationale + 答案；
3. **只保留答案正确的**，微调模型，然后**迭代**（下一轮模型更强，能解出更多题）；
4. 对答错的题启用 **rationalization**：把正确答案当 hint 喂进去（"答案是 42，请给出推理"），让它倒推出 rationale，把"题目 + rationale + 答案"加入训练集，**训练时不带 hint**。

讲师对它的定性：*"这是一种非常朴素的、几乎可以称为 off-policy 强化学习的方法"*（[19:28]）。

**STaR 成立依赖三个假设**（[19:28]–[20:29]）：
- **最终答案正确 ≈ 推理质量高**（在数学上大体成立，代价是把"乱蒙对答案"的坏推理也收进来，也学不到"推理对但算错"的样本）；
- **给答案当 hint 时模型能生成有效推理链**；
- **初始模型足够强**，能从 few-shot 起步；若问题类别整体超出模型能力，就没有爬坡信号。

**实验设置与结果**（[27:36]）：基座是 **GPT-J（开源 6B）**；很小的 warmup + **恒定学习率**；外层循环做若干轮迭代，每轮**逐步增加内层循环步数**（论文主张起步慢一点，再逐步加量）。数据集三块：**GSM8K**（小学奥数应用题，约 9K 样本）、**CommonsenseQA**（常识多选）、**多位加法算术**（合成数据）。结果要点：

- 相对直接监督微调有明显提升，但**只用上了 70%–87% 的数据**（答不出来的题被丢掉）；
- **不是真的 RL，迭代几轮后就开始 plateau**，迭代次数需要调；
- **CommonsenseQA 上做了人工评测**：让人类标注者在 STaR 生成的 rationale 和种子集里的 few-shot rationale 之间做偏好选择，STaR 的看起来相当合理；
- 讲师报的一个数字：STaR + rationalization 用 **86% 的数据**达到 **72.5%** 的准确率，而直接微调需要更多数据才能到同等水平（**待核对**：转写在此处表述含混，"72.5%"与"51.7%"两个数字在本讲中位置可能有误，见第七节）；
- **GSM8K 上 rationalization 没带来提升**（[30:40]）：因为 GSM8K 对 GPT-4o / GPT-J 来说本就在能力范围内，题太简单时"教它推理"没用；强制 CoT 与它自己生成的计算步数本来就差不多。

**STaR 的失效模式**（[31:40]–[33:41]）：rationalization 的质量没人把关——**没有好的 rationale 评估手段**（只能人工看，或上 process reward model）；**给 hint 后生成的推理链本身可能是错的**，模型会从"假对"里学坏推理，且论文**在第三步不做任何过滤**，因此无法持续爬坡；按最终答案过滤会产生**假阳/假阴**（中间步骤无效但答案对）。此外**few-shot 的写法会偏置 rationale 的风格**，进而偏置你训进去的东西。

课堂讨论（[33:41]–[36:46]）里有个很尖锐的提问："如果只想训小模型，直接用前沿大模型造数据不就行了？"讲师承认这在工业界更省事，但坚持本课的重点是**从零构建、理解这条路要付出什么**——她把"拿强模型输出训弱模型"明确归为**蒸馏（distillation）**，与自举是两回事。

**STaR 家族的后续**（[36:46]）：**V-STaR**（转写作 "var"）——在循环里**同时训练一个生成器（generator）和一个验证器（verifier）**；**Quiet-STaR**——把推理步骤从自然语言空间挪到**隐空间（latent space，用 MLP）**，"既然能让模型在内部想，何必用英语想"。

### 6. "什么限制了 STaR 的上界？"（[37:46]–[40:48]）

两分钟小组讨论，学生给出的答案被讲师认可为"方向正确"：① STaR **做不出训练分布之外的逻辑跳跃**，rationale 的水平不会超过模型原本能梦到/想到的水平；② 模型太差时，给了 hint 也生成不出像样的 rationale，反而往训练集里注入坏样本；③ 答案是否"好倒推"（比如答案 225 能让人猜到 15×15）影响 rationalization 的难度；④ 大批量不会做的题会迫使模型疯狂 rationalize，反而需要更多数据才能形成可泛化的推理与回溯能力。讲师总结：*"这里很多魔法其实取决于基座模型本身能做什么"*——这句话是后面 RL 部分的伏笔。

### 7. DeepSeekMath：先把模型" priming "好，再把 RL 做对（[40:48]–[52:01]）

**第一步：数据策划（priming）**（[41:49]）。Minerva 的做法是在 **arXiv 论文**上继续训 PaLM；DeepSeekMath 反其道而行——**arXiv 没用**，真正起作用的是：① **从代码预训练的基座（DeepSeek-Coder）出发**；② 从 **Common Crawl 网页里挖数学内容（OpenWebMath）**，发现网页比论文在数学各子领域上的**覆盖度更好、token 产出量高得多**。讲师称这是**第一次被证明"从代码模型出发做数学更好"**，理由是代码让模型更会推理、更会用工具。这一步对应前面学生的提问：**模型在某域太弱时，你得先补这个域的能力，RL 才爬得动**。

**第二步：GRPO**（[43:54]）。PPO 要常驻 **旧策略 / 新策略 / critic / 奖励模型 4 份模型**，7B 还行，再大就爆显存。GRPO **砍掉 critic**，改为对每个问题采样一组答案、各自打分，用 **(r − mean(r)) / std(r)** 当作 advantage（讲师没写完整公式，只要求建立直觉：*"拿奖励减掉平均奖励，再除以奖励的离散程度"*）。这样只剩 **3 份模型**，显存省下来就能 scale RL。

在讲梯度时她给了一个统一视角（[45:55]）：不同 RL 算法的差别无非是**数据来源**怎么变、**梯度系数（gradient coefficient）**怎么算。三者的对照是——**STaR / RFT**：离线或在线生成一次，对=1、错=0，错的全部丢掉；**GRPO**：在线采样 + 奖励模型打分 + 组内基线给出 advantage。

**结果**：MATH 上 **46.8 → 51.7**，是**第一个不依赖 critic 就在 7B 规模突破 50% 的开源模型**。

**GRPO 的关键缺陷**（[47:56]–[49:58]）：如果一组样本**全对或全错**，mean/std 归一化就会失效——*"如果所有奖励都是 0 或都是 1，归一化根本没意义，模型没有可学的东西"*。也就是说**必须有奖励的方差，模型才有爬坡信号**；题目全太难（永远 0）或全太易（永远 1）都白搭。有学生补充说 PPO 里的 **KL 散度项**正是用来防止模型偏离原本会做的东西（讲师认可这个解读，但她自己的框架更侧重"题目难度分布要给对"）。

**一个重要的负面结论**（[52:01]）：DeepSeekMath 的 RL **提升了 majority@K，但没有提升 pass@K**。也就是 32 次采样里"是否能解出"没变，**变的是多数答案现在是对的**。讲师原话：*"模型变得更一致了，而不是从根本上变聪明了。"*

### 8. DAPO：修掉长思维链 RL 的工程坑（[52:01]–[61:08]）

直接把 GRPO 放大到 **Qwen 32B** 上跑 AIME，只能拿 **30%**（而 DeepSeek-R1 论文在 AIME 上做到 **47%**）。具体问题：**熵坍缩（模型过早过度自信）、训练不稳定、输出长度不可控地爆炸**。DAPO 的贡献就是把 GRPO 没写清的技巧显式化：

| 技巧 | 做法 | 直觉 |
|---|---|---|
| **clip-higher**（非对称裁剪） | 放宽 PPO 裁剪的上界，允许低概率 token 更大幅度上涨 | 否则探索被压死；讲师：*"熵是模型还能探索多少的代理指标"*，非对称裁剪后精度更高且熵不塌 |
| **动态采样（dynamic sampling）** | **过采样**（不止 64 条），**丢掉全对和全错的组**，只保留 0–64 之间的组 | advantage 为 0 的组纯浪费梯度；同时维持有效 batch size |
| **token 级损失** | 按 token 而非按样本加权（等效长度惩罚/形状控制） | 否则一条超长垃圾回答和一条短的好回答权重相同；加了之后熵和平均响应长度都被压住 |
| **超长过滤 + 软性超长惩罚** | 过滤超长样本 / 对接近长度上限的 token 加**渐进式惩罚** | 被截断的思维链会灌进大量噪声；渐进惩罚让训练重新稳定（另一条路线是在 RL 循环中逐步放长上下文） |

**逐级增益（Qwen 32B 上 AIME，[59:06]）**：朴素 GRPO **30** → 超长过滤 **36** → 非对称裁剪 **38** → 软性超长惩罚 **41** → token 级损失 **42** → 动态采样 **50**。**50 超过了 DeepSeek-R1 蒸馏到 Qwen 32B 的结果**，即自己从头 hill climb 就打过了蒸馏。

**从 DAPO 学到的判据**（[60:07]）：**损失函数本身不是 RL 里的好代理指标**。你要同时盯三个东西——**响应长度**、**熵（不能太低也不能太高）**、**拿到满分 1 的样本占比**（它告诉你还要采多少）。出问题时的排查方向：长度爆炸 → 管住损失；熵异常 → 调裁剪；**跑一定步数后不再涨 → 奖励模型可能已经饱和了**。

关于 64 这个采样数是否太小（学生提问，[57:05]）：讲师说这只是论文里的一个示例值，实际取决于**基准难度、基座模型能力、以及思维链的长度**。

### 9. SFT vs RL，以及三种方法怎么选（[61:08]–[63:09]）

回答开头押后的问题：**在有强奖励信号的领域，RL 能用更少的样本 hill climb，但要把它调对非常费功夫**；**SFT 在你有大量高质量数据时通常更快，但它不会给模型带来/增强推理轨迹能力**。选择指南：

- **STaR**：你只有**约 100 条带推理的示例**、**没有 RL 基础设施**时的好起点；GSM8K 这类简单推理任务会有一定提升（但不惊人），且基本**不会超出模型原本的能力范围**。
- **DeepSeekMath / GRPO**：需要**足够好的基座 + 用指令数据 priming 过**；不需要 critic，**GPU 显存有限也能跑**；标准数学推理任务已充分验证。
- **DAPO 那一整套**：当**思维链变长（通常对应更难的题）**、你需要 SOTA 表现时才必须上；对 AIME、IMO 这类竞赛级题目非常有用。

讲师也提到"更新全部权重导致回退"这个问题：她倾向认为**回退未必发生**（除非推理链被训成了"过度思考 / overthinking"式的重复链），可用 **KL 散度**或**只更新部分参数/低秩更新**来缓解，最近已有博客类工作在做后者。

结论性的判断（[63:09]）：三种方法都会提升 **majority@K、答案格式、多步连贯性**，但**都不会提升模型的根本能力**，不会教会它解全新的问题、也不会产生很强的**域外泛化（out-of-domain generalization）**。

### 10. 收尾：RL 的算力占比与开放问题（[65:14]–[72:24]）

讲师强调这条闭环的**上限由奖励信号决定**：模型太强会**奖励破解（reward hacking）**，奖励模型信号不足就爬不动——"这是一个更难的优化问题"。可验证奖励目前主要集中在**数学（最终答案）与代码（执行反馈、单元测试，如上周五讲的 RLEF 论文）**。

**最后两个问题**：① 学生问前沿模型训练里 pre-training 数据 vs 推理类合成数据的比例——讲师说 Anthropic 没公开，**Grok** 相对公开：去年 RL 相对预训练的比例大概 **99% : 1%**，后来长到约 **5%**；**Grok 4 宣称做到 50% RL**，但"50% 的 RL 本该带来一次大跳，实际没有"——瓶颈恰恰就是她今天讲的这些（奖励不够强、奖励有噪声）。② 学生问 AIME / USAMO（转写作 "USML"，**待核对**）这类题量很少的基准怎么保证足够的验证信号且不泄漏——讲师的回答是**换抽象**：问题不是"数据够不够"，而是"**够不够让你爬坡**"；RL 本身比 SFT 数据高效得多，而验证信号更多取决于**有没有一组好的验证器（verifier ensemble）**，而不是单一验证器。

## 四、论文精要

### STaR: Bootstrapping Reasoning With Reasoning（Zelikman et al. 2022）

- **一句话贡献**：不需要人工标注推理链——让模型自己生成 rationale，用最终答案正确性过滤，答错的再"给答案倒推"，微调后迭代自举。
- **关键结论/数字**：基座 **GPT-J 6B**（转写称其为 GPT-3 的开源 6B 版）；数据集 **GSM8K（约 9K）、CommonsenseQA、合成多位加法**；训练用**小 warmup + 恒定学习率**，外层迭代、内层步数逐轮递增；**只用上 70%–87% 的数据**；rationalization 用 **86% 的数据**达到 **72.5%**（**待核对**，见第七节）；CommonsenseQA 上人工评测认为生成的 rationale 质量合理。
- **讲师强调的点**：① 它是**近乎 off-policy 的朴素 RL**，不是真 RL，迭代几轮就 plateau；② 三大假设（答案对≈推理好 / 给 hint 能倒推 / 基座够强）各自都是失效点；③ 论文**第三步没有任何过滤**，导致会学坏推理、无法持续爬坡——后续工作才补上（PRM 等）；④ **GSM8K 上 rationalization 无效**，因为题太简单，已在模型能力内；⑤ few-shot 的格式会**偏置**生成的 rationale 风格。

### DeepSeekMath（arXiv 2402.03300）

- **一句话贡献**：证明了"先做好数学数据策划 + 用 GRPO 替代 PPO 的 critic"，就能在 7B 规模把数学推理做到 SOTA。
- **关键结论/数字**：**arXiv 数据没帮助**，**Common Crawl 挖出来的数学数据（OpenWebMath）覆盖更广、token 产出更高**；**从代码基座（DeepSeek-Coder）出发显著优于从通用基座出发**（首次被证明 code→math 有效）；GRPO 让驻留模型从 **4 份降到 3 份**；MATH **46.8 → 51.7**，是首个无 critic 破 50% 的开源 7B。
- **讲师强调的点**：① priming（补足域内能力）是 RL 能爬坡的**前置条件**，呼应"什么限制了 STaR"；② GRPO 的合理性来自**奖励模型本就在比较数据上训**，组内相对基线天然契合；③ 全对/全错的组会让归一化失效，**没有方差就没有学习信号**；④ **提升的是 majority@K 而不是 pass@K——"更一致，不是更聪明"**，这句话是本讲最核心的保留意见。

### DAPO（arXiv 2503.14476）

- **一句话贡献**：把"如何稳定地把 GRPO 用在长思维链上"的四个工程技巧（clip-higher、动态采样、token-level loss、overlong 处理）显式化、量化并开源。
- **关键结论/数字**：Qwen 32B 上 AIME 逐级：**30 → 36（超长过滤）→ 38（非对称裁剪）→ 41（软性超长惩罚）→ 42（token 级损失）→ 50（动态采样）**，超过 DeepSeek-R1 蒸馏到 Qwen 32B 的 **47**；朴素 GRPO 只有 30。
- **讲师强调的点**：① **损失函数不是好代理**，必须同时看**响应长度、熵、满分样本占比**；② **熵是探索能力的代理**，非对称裁剪是防坍缩的关键；③ advantage=0 的组是**纯浪费梯度**，所以过采样 + 过滤全对全错；④ 长度爆炸/截断是长 CoT RL 的特有噪声源；⑤ **训练一定步数后不涨了，可能是奖励模型饱和了**；⑥ 采样数（如 64）不是定值，取决于基准难度、基座能力、思维链长度。

## 六、动手启示

1. **先问"有没有可验证的奖励"再决定要不要上 RL**。数学的最终答案、代码的执行反馈与单元测试是现成的；写作、编辑这类域里训练时扩展的边际收益很低，别硬套。
2. **低成本起步就用 STaR 闭环**：几十到 100 条带推理链的种子 → 采样 → 只留答对的 → SFT → 迭代；答错的用 rationalization 补。**但要给这个循环加个上限**：它迭代几轮就会 plateau，且**必须给生成的 rationale 加质量把关**（PRM、人工抽检、或至少长度/格式规则），否则会往训练集里灌"倒推出来的假推理"。
3. **盘题目难度分布，而不是只盘数据量**。全对或全错的组 advantage 恒为 0，是纯浪费：至少要保证每个 batch 里有一批**处于模型能力边界上**的题。这正是 dynamic sampling 在做的。
4. **把熵、平均响应长度、满分样本占比当成和 loss 同等重要的一级监控指标**。loss 平了但长度在涨 = 快出事了；跑若干步不涨 = 大概率是奖励模型饱和或被 hack，而不是学习率调错。
5. **长思维链场景优先上 clip-higher 和 token 级损失**。前者防探索坍缩，后者防止"超长垃圾回答和短的好回答等权"。被截断的样本要么过滤、要么给渐进惩罚，别直接丢进梯度里。
6. **评估时分开报 majority@K 和 pass@K**。只报多数投票准确率会掩盖"模型根本能力没变"这一事实——这是本讲反复叮嘱的坑。

## 七、遗留问题与开放挑战

- **为什么只涨 majority@K、不涨 pass@K？**（[63:09]、[66:14]）讲师明确列为头号开放问题：要提升 pass@K 就等于要提升模型解新问题的根本能力，而历史上的能力阶跃要么来自方法论突破，要么来自某个维度上的 scaling，目前这套 RL 闭环还没做到。
- **推理行为是真"涌现"还是只是被放大？**（[66:14]）我们在思维链里看到了回溯、自评、自纠、并行尝试，但**这些行为是新出现的，还是基座模型本来就有、只是 RL 让它们在统计上变得更常见**？未定论。
- **怎么从失败中学习？**（[23:31]、[66:14]）*"从负样本中学习这件事还没被攻克"*，当前主流做法（包括 STaR、GRPO、DAPO）都是**直接把失败样本过滤掉**。已有少数论文尝试，但本讲未展开。
- **rationale 的质量评估**（[32:40]、[21:30]）：除最终答案外没有好指标，只能人工看或上 process reward model；STaR 原论文第三步不过滤。讲师直接把它点为一个**课程项目方向**。
- **奖励模型的两难**（[65:14]）：太弱 → 没信号爬不动；太强 → 被 reward hacking。以及如何让 RL **对奖励噪声鲁棒**、该用什么样的奖励。
- **验证信号的覆盖面**（[66:14]）：目前可靠的验证信号几乎只在数学和代码里，**还有多少领域能有这种信号**？能否用**验证器集成（ensemble of verifiers）**补上单个验证器的盲区？（讲师说集成验证器的论文前面已讲过。）
- **简单题回退问题**（[15:24]、[49:58]）：训难题理论上会不会拖累简单题？讲师倾向"通常不会，除非训出了 overthinking 式的重复推理链"，并提到 KL 散度项或只更新部分权重是缓解方向，但**没有给出确定结论**。
- **训练算力 vs 推理算力的最优分配**（[05:09]）：学生问有没有 ROI 平台，讲师押后到第三篇论文，最终**没有给出定量答案**——只给了按方法分场景的定性选择指南。
