## 1. 引言：描述语法

- 编程语言构造的**语法**可以用**上下文无关文法**指定；
  - 文法给出语言的精确语法规约，定义程序结构；
  - 对某些文法，可以**自动构造**出高效的语法分析器（这正是 yacc/bison 存在的理由）。
- 也可以用 **BNF（Backus-Naur Form）**记号描述，BNF 基本上可看作 CFG 的一个变体。

### 语法分析器（Parser）的作用

- 从词法分析器获取 **token 串**，验证该串能否由源语言的文法生成；
- 以合理的方式**报告语法错误**；
- 对良构程序，构造**语法分析树（parse tree）**。

```
源程序 → [Lexer] → token 流 → [Parser] → 语法分析树（+ 错误报告）
```

## 2. 上下文无关文法的形式定义 ★★

一个 CFG 由**四部分**组成：

| 组成 | 说明 |
|---|---|
| **终结符号（terminals）** | 组成串的基本符号，即 **token name** |
| **非终结符号（nonterminals）** | 语法变量，表示**串的集合**，通常对应某种语言构造（如 `stmt`） |
| **开始符号（start symbol）** | 某个被指定的非终结符号；**它表示的串集就是该文法生成的语言** |
| **产生式（productions）** | 规定终结符号与非终结符号如何组合成串 |

**产生式格式**：`head → body`

- head 必须是**一个非终结符号**（这正是 "context-free" 的含义：替换 A 时不看 A 的上下文）；
- body 由零个或多个终结/非终结符号组成；
- 例：`expression → expression + term`

`→` 可读作：可具有形式、可被替换为、可重写为、可产生、可生成。

### 2.1 例子：简单算术表达式

- 终结符号：`id, +, -, *, /, (, )`
- 非终结符号：`expression`、`term`（项）、`factor`（因子）
- 开始符号：`expression`
- 产生式：

```
expression → expression + term
expression → expression – term
expression → term
term       → term * factor
term       → term / factor
term       → factor
factor     → ( expression )
factor     → id
```

### 2.2 记号简化

```
E → E + T | E – T | T
T → T * F | T / F | F
F → ( E ) | id
```

- `|` 是**元符号（meta symbol）**，表示"或"，用来罗列同一个 head 的多个 body；
- `(` 和 `)` **不是**元符号，它们是**终结符号**（程序里真实的括号）。

> 这个文法通过"E→T→F"的层次结构把**优先级**（`*` 比 `+` 先算）和**结合性**（左递归 ⇒ 左结合）编码进了文法本身，是最值得背下来的模板文法。

## 3. 推导（Derivation）与语法分析树 ★★

### 3.1 推导

**推导**：从开始符号出发，不断用产生式重写非终结符号，直到只剩终结符号。

例：CFG `E → – E | E + E | E * E | ( E ) | id`

`E ⇒ –E ⇒ –(E) ⇒ –(id)`

### 3.2 记号

| 记号 | 含义 |
|---|---|
| `⇒` | 一步推导（derives in one step） |
| `⇒*` | 零步或多步推导 |
| `⇒+` | 一步或多步推导 |

性质：

- 对任意串 α，`α ⇒* α`；
- 若 `α ⇒* β` 且 `β ⇒* γ`，则 `α ⇒* γ`；
- 例：`E ⇒ –E ⇒ –(E) ⇒ –(id)` 可写作 `E ⇒* –(id)`。

### 3.3 句型与句子 ★

- 若 `S ⇒* α`（S 为开始符号），则称 α 是该文法的**句型（sentential form）**
  - 句型可以同时含终结符号和非终结符号，也可以为空；
- **句子（sentence）**：不含非终结符号的句型；
- **文法生成的语言 = 它的所有句子的集合**。

例：`E ⇒ –E ⇒ –(E) ⇒ –(E+E) ⇒ –(id+E) ⇒ –(id+id)`

这里每个串都是句型，但只有最后的 `–(id+id)` 是句子。

### 3.4 最左推导与最右推导 ★

每一步推导都要**选择替换哪个非终结符号**：

- **最左推导（leftmost derivation，最左推导）**：总是替换句型中**最左边**的非终结符号，记作 `⇒lm`

  `E ⇒lm –E ⇒lm –(E) ⇒lm –(E+E) ⇒lm –(id+E) ⇒lm –(id+id)`

- **最右推导（rightmost derivation，最右推导）**：总是替换**最右边**的非终结符号，记作 `⇒rm`

  `E ⇒rm –E ⇒rm –(E) ⇒rm –(E+E) ⇒rm –(E+id) ⇒rm –(id+id)`

> 关联：自顶向下分析（LL）对应**最左推导**；自底向上分析（LR）对应**最右推导的逆过程**。这条对应关系后面两讲会反复用到。

### 3.5 语法分析树（Parse Tree）★

语法分析树是推导的**图形表示**，它**过滤掉了产生式应用的先后顺序**。

- **根结点**：文法的开始符号；
- **叶子结点**：终结符号（这里假定推导最终只产生终结符号串）；
- **内部结点**：非终结符号，表示一次产生式应用
  - 内部结点标号为产生式 head 的非终结符号；
  - 其子结点从左到右依次标号为产生式 body 中的符号。

**性质**：

- 叶子结点从左到右连接起来构成一个句型，称为该树的**结果（yield）**或**边缘（frontier）**；
- 推导与语法分析树是**多对一**关系；
- **最左推导 / 最右推导与语法分析树是一一对应的**。

上例的最左推导和最右推导对应**同一棵**语法分析树。

## 4. 二义性（Ambiguity）★★

**定义**：若某个文法对**某个句子**存在**多于一棵**语法分析树，则该文法是**二义的**。

### 4.1 经典例子

CFG：`E → E + E | E * E | ( E ) | id`

对句子 `id + id * id`，有两个不同的最左推导：

```
推导一                       推导二
E ⇒ E + E                   E ⇒ E * E
  ⇒ id + E                    ⇒ E + E * E
  ⇒ id + E * E                ⇒ id + E * E
  ⇒ id + id * E               ⇒ id + id * E
  ⇒ id + id * id              ⇒ id + id * id
```

- 推导一的树：`+` 在根，右子树是 `id*id` → 含义 `id + (id*id)`（符合通常的优先级）；
- 推导二的树：`*` 在根，左子树是 `id+id` → 含义 `(id+id) * id`。

**两者都是最左推导**，但对应**不同的树**，所以该文法二义。

### 4.2 为什么要消除二义性

- 编程语言的文法**通常必须无二义**，否则同一个程序有多种解释方式；
- 消除手段：
  1. **改写文法**（引入 `E → E + T`、`T → T * F`、`F → id` 的层次，把优先级/结合性写进文法）；
  2. 保留二义文法 + **消歧规则（disambiguating rules）**丢弃不想要的树（例如"乘法优先于加法"、悬空 else 归属最近的 if）。这在实践中（如 yacc 的 `%left`、`%prec`）很常用且高效。

## 5. CFG vs 正则表达式 ★★

**结论：CFG 的表达能力严格强于 regexp。**

1. 每个能被 regexp 描述的语言，都能被某个文法描述（**每个正则语言都是上下文无关语言**）；
2. **存在**上下文无关语言**不能**用 regexp 描述。

```
正则语言 ⊊ 上下文无关语言
```

### 5.1 命题 1 的构造性证明：NFA → CFG

每个正则语言都能被某个 NFA 接受，据此构造 CFG：

- 对 NFA 的每个状态 `i`，创建一个非终结符号 `Ai`；
- 若状态 `i` 在输入 `a` 上转移到状态 `j`，添加产生式 `Ai → a Aj`；
- 若状态 `i` 在 `ε` 上转移到 `j`，添加产生式 `Ai → Aj`；
- 若 `i` 是接受状态，添加 `Ai → ε`；
- 若 `i` 是开始状态，令 `Ai` 为文法的开始符号。

**例**（对应 `(a|b)*abb` 的那个 4 状态 NFA）：

```
A0 → a A0 | b A0 | a A1
A1 → b A2
A2 → b A3
A3 → ε
```

对串 `baabb`：NFA 接受它的过程，**恰好对应**该文法推导出这个句子的过程：

```
A0 ⇒ b A0 ⇒ b a A0 ⇒ b a a A1 ⇒ b a a b A2 ⇒ b a a b b A3 ⇒ baabb
```

> 这种每条产生式形如 `A → aB` 或 `A → ε` 的文法称为**右线性文法（正则文法）**，它与 NFA 是同一个东西的两种写法。

### 5.2 命题 2：反例 `L = {aⁿbⁿ | n > 0}`

- L 可由 CFG 描述：`S → a S b | ab`；
- L **不能**用 regexp 描述，换言之**不存在接受 L 的 DFA**。

### 5.3 反证法证明（课件版本）★

假设存在接受 L 的 DFA `D`，它有 `k` 个状态。

1. 处理 `a^(k+1)...` 时，因为每读一个符号进入一个状态，读前 `k+1` 个 a 会经过 `k+1` 个状态（不计初始），由**鸽笼原理**，`D` 必然**不止一次进入同一个状态 s**。
2. 设 `D` 在读完第 `i` 个 a 和第 `j` 个 a 之后都进入状态 `s`（`i ≠ j`，`i, j ≤ k+1`）。
3. 由于 `D` 接受 L，串 `a^j b^j` 必须到达接受状态，因此**存在一条从 s 出发、标号为 `b^j` 的路径通向接受状态**。
4. 但 `a^i` 也到达 `s`，于是沿同一条 `b^j` 路径，`D` 将接受 `a^i b^j`（`i ≠ j`）—— 而 `a^i b^j ∉ L`。**矛盾！**

所以不存在这样的 DFA，L 不是正则语言。

> 这本质上就是**泵引理（pumping lemma）**的直观版本。直觉解释：有穷自动机**没有无界的计数能力**（只有有限个状态，记不住"已经读了多少个 a"），而 CFG 靠递归产生式天然具备"配对"能力 —— 这也正是**括号匹配、嵌套结构必须交给语法分析器而不是词法分析器**的根本原因。

### 5.4 分工小结

| | 工具 | 负责的东西 |
|---|---|---|
| 词法分析 | regexp / DFA | 标识符、数字、关键字、运算符等**无嵌套**结构 |
| 语法分析 | CFG / 下推自动机 | 括号匹配、表达式嵌套、语句块等**递归**结构 |
