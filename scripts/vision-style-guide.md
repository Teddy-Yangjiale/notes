# 视觉大模型专栏 · 写作模板（STA-5007 风格）

> 2026-10-19 起生效。第 12 讲（ViT）是按本模板重写的样板；新写的第 25 讲起全部按本模板写，已写的 01—24 讲逐篇改写。
> 校验脚本 `scripts/vision-verify.mjs` 不检查风格，只检查公式、链接、图片和可运行代码，所以风格靠本文件约束。

## 一、旧稿为什么"不易懂"：审稿结论

对 01—24 讲（约 134 万字）和 STA-5007 四讲（约 68 万字）做了对照统计：

| 指标 | 旧视觉稿 | STA-5007 |
| --- | ---: | ---: |
| "不能 / 不等于 / 不保证 / 不意味着 / 不是" 每万字出现次数 | 14 | 3 |
| `🖼 逐元素图解`（讲清图里每个方块和箭头） | 29 处 / 25 篇 | 160 处 / 4 篇 |
| `💡` 直觉框 / `⚠️` 易错框 | 0 | 75 / 58 |
| 带 `<details>` 折叠解析的练习 | 0 | 148 |
| 每篇三级标题数 | 45—60 个等权重小节 | 每模块 4—8 个主题 |

具体症状：

1. **是事实清单，不是一堂课。** 一讲被切成 45—60 个 `### 12. xxx` 小节，每节两三段，所有小节同等权重，读者分不清哪五个概念是主干。没有"这一讲要回答什么问题"的主线，也没有每个模块的开场白。
2. **先给定义，不给动机。** 小节第一句就是"设提示集合 P=…"，而不是"为什么需要这个东西、它解决了上一步的什么失败"。
3. **每段都在纠错。** 大量句子是"X 不是 Y；不能把 A 当作 B；不保证 C"。初学者还没形成这些误解，读起来像一堵否定句的墙。该说的易错点应该先把正确机制讲透，再集中放进一个 ⚠️ 框。
4. **图只有一行标题。** 每张 SVG 下没有逐元素解释，读者不知道该看图里的哪个箭头。
5. **算例和练习与概念脱节。** 算例集中堆在文末；练习答案一行带过（"**解析：** 并集是 11……"），没有"为什么这样算"的推理过程，也没有折叠。
6. **符号密度过高，没有喘息。** 一段里塞四个定义（"设 B 张原图，每图两视图，得到 M=2B 个向量。一次 anchor 排除自己……"），没有表格、没有代码块、没有加粗的结论句。
7. **排版细节。** 中英文和数字之间没有空格（"τ0.5时logits""queryencoder"），折叠标题处理不一致；第 14—23 讲改写时删掉了全部三级标题，目录只剩十个二级标题，反而更难导航。
8. **缺少课程定位和速查。** 没有"这一讲在课程中的位置"框，没有文末概念速查表和高频问题。

## 三、段落写法

- **先问题，后机制。** 每个主题开头一句话说清它回答什么问题，或上一步留下了什么失败。
- **一个公式三件事。** 公式之后立刻：每个符号是什么、每个张量的维度、一个两三行就能手算完的数字例子（"跟着算"）。
- **结论句加粗，放段首。** 像 STA-5007 的"**关键词是 Synergy，不是 Combination。**"
- **把否定句收进 ⚠️ 框。** 正文讲清正确机制；易错点集中成一个 `> **⚠️ 标题**` 框，一框只讲一个易错点，并说明"错在哪一步、怎么发现"。
- **💡 框讲"为什么这样设计"。** 设计动机、工程权衡、与前后讲的联系。
- **表格代替排比句。** 三个以上并列对象（三种 pooling、五种模型规模、两种插值约定）一律用表。
- **代码块展示结构。** 张量形状链、序列布局、索引顺序用等宽代码块画出来，而不是用句子描述。
- **术语第一次出现给中英文和一句话定义。** 之后可以只用英文缩写。
- **中英文、数字之间加空格**："ViT-B/16 有 196 个 patch""τ = 0.5 时"。
- **教学数字的免责声明只写一次**（导语或附录），不在每个算例里重复。

## 四、算例与练习

- **跟着算**：紧跟在它要说明的公式后面，不另立章节；给完整中间步骤；每一步写明用到了上面哪条公式。
- **大型算例**（完整反传、参数账本）可单独成 `### 算例X：标题`。
- **练习**：每模块末尾 4—8 题；带 ★ 的是常见笔试/面试题；解析用 `<details>`，先给思路再给数字，最后一句说"这题在考什么"。
- **可运行核查**：保留 `~~~python` 块；块前用一两句说明它核对什么、不核对什么（不说明"不构成论文复现"之类的通用免责）。

## 五、图

- 每张图必须有 `**🖼 逐元素图解**`：图里每个方块、箭头、颜色、数字各是什么；读图顺序是什么；图没画出来但要注意的是什么。
- 新图用 `scripts/vision-diagrams.mjs` 生成（卡片 + 箭头 + 小网格的统一风格），运行 `node scripts/vision-diagrams.mjs`。
- 一讲至少一张"整体数据流"图（输入 → 中间张量 → 输出，标维度），再按模块配机制图。

## 六、篇幅与密度

- 篇幅由知识范围决定，不设上限，但**主题数控制在每模块 4—8 个**，细分点用 `####`。
- 每个主题 3—8 段；超过就拆主题或下沉为 `####`。
- 一讲的二级标题 5—8 个，附录 2—3 个。

## 七、改写旧稿的步骤

1. 列出旧稿全部小节，归并成 5—8 个模块、每模块 4—8 个主题；旧的 45—60 个小节标题变成主题内的段落或 `####`。
2. 旧稿每一句"不能 / 不等于"：要么删（读者不会犯的错），要么合并进本主题的一个 ⚠️ 框。
3. 每张已有 SVG 补 🖼 逐元素图解；缺整体数据流图的讲补一张。
4. 旧算例移到对应公式后面；旧练习按模块分组，补推理过程，改成 `<details>`。
5. 补 📌 位置框、附录 A/B/C。
6. 保留全部 `~~~python` 块与数值结论；运行 `node scripts/vision-verify.mjs --source-only`，再 `npm run build` 后跑完整校验。
