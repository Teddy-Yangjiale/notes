# CS184 笔记写作与图解规范

适用范围：`src/content/notes/cs184-*` 全部讲次正文，以及 `scripts/cs184-*-diagrams.py` 生成的配图。

这份规范是从第 02 讲（光栅化 = 采样）的两次返工里定下来的：**第一版是"逐页翻译幻灯片"，第二版才是"按关系重画图 + 保留关键页截图"**。后续讲次直接按第二版走。

## 一、一篇讲义怎么组织

1. **开头先压一条推理链**，不要先讲背景。用一张流程图或一段 5–7 行的 `text` 块写出"整讲只有这一条链"，再逐节展开。
2. **一级章节承担叙事转折**，不是页码分组。章标题写"这一节在解决什么问题"（例如「屏幕为什么是离散的」），不写「幻灯片 P3–P23」。
3. **每个 `####` 小节对应一张课件原页**，标题用课件原标题，副标题斜体写原文里的补充行。
4. **正文解释"这页想让你看到什么"**，不是复述 bullet。允许补充课件没写但必要的推导、手算、反例。
5. **动画分页（build）不要一页页摆**：九页只累加一个 bullet 的情况，放首尾两张 + 一张表说明中间加了什么。
6. **结尾要回到开头那条链**，列出"这一讲解决了什么、还差什么、谁来解决"。

## 二、图：两个来源，职责不同

### 1. 课件截图（`images/pNN.png`）

- 用途：**对照原文**。读者要能看到老师到底写了什么。
- 只放**关键页**，不放纯空白页、纯分节页、纯 build 中间帧（除非中间帧本身有信息）。
- 渲染参数：宽 1200 px、HTML 页面宽度的二倍图；量化到 256 色（体积降到约 1/3，画质无损）。
- **`images/` 只保留正文实际引用的页面**：渲染完全部页后按引用表删掉未被引用的，仓库里不囤用不上的中间帧（讲次脚本可随时重渲染）。
- 生成：`python scripts/cs184-render-pages.py <pdf> <输出目录> [--pad 2|3]`。**页数超过 99 必须加 `--pad 3`**，否则会出现 `p01..p99` 与 `p100..p277` 混杂，按字符串排序错乱、正文引用也对不上（第 4–5 讲踩过，误删了 99 张）。
- 图注写**这一页的关键信息**，不写「如图所示」。

### 2. 原创示意图（`diagrams/dNN-*.png`）

- 用途：**讲清一个关系**。课件没画出来的东西才需要它。
- 生成：`python scripts/cs184-l02-diagrams.py`，全部用 matplotlib 画矢量几何，可复现。

**硬性约定：**

| 项目 | 规定 |
|---|---|
| 一图一事 | 一张图只讲一个关系；要讲两个关系就画两张 |
| 无坐标轴 | 不画 tick / grid / 边框，`ax.axis("off")` |
| 无标题 | 图内不写标题（标题归正文），只留必要的局部标注 |
| 无图例框 | 颜色含义直接标在图上，或写进正文的表格 |
| 扁平风格 | 圆角矩形 + 箭头 + 少量象形元素，不用阴影/渐变/3D |
| 颜色语义 | teal `#0f766e` = 主链路/内侧；orange `#b45309` = 本讲焦点；purple `#5b21b6` = 数据形态；red `#b91c1c` = 错误/异常；灰 `#5b6b7c` = 说明文字 |
| 字号 | 局部标注 ≥ 8.5 pt，正文级说明 ≥ 9.5 pt；手机屏幕放大后要能读 |
| 文字不压线 | 标注放在空白区或加白底 bbox；生成后必须逐张看过 |
| 图注在正文 | 图片下方紧跟一段斜体，**读图注就能懂这张图在说什么**，不依赖正文上下文 |

**自检清单（每张图生成后逐条过）：**

1. 把图缩小到手机宽度，还能看出主结构吗？
2. 图里每个元素在正文或图注里都被指认了吗？
3. 有没有两个标注互相压住？（最常见的返工原因）
4. 这张图讲的是"关系"还是"数据"？如果是数据，它该不该用表格代替？
5. 删掉这张图，读者会损失什么？答不出就删图。

## 三、文字与公式

1. **每个新公式**：先讲符号和假设 → 推导 → 代入小数字 → 指出它对应哪一页课件。
2. **手算要能自己验**：给具体坐标，算出具体数，最后给一个反例或边界情况。编号写「🔧 手算 N」。
3. **易错点用 `⚠️` 引用块**，说清"错在哪、正解是什么"。
4. **超出本讲的联系用 `🔭`**，只指方向不下结论（例如"这是第 3 讲的入口"）。
5. **课件原话引用用 `>`**，保留英文原文，别意译成看不出原句的样子。
6. 数学用 KaTeX：行内 `$...$`，独立成块 `$$...$$`。中文标点不要塞进公式里。
7. **`$$` 必须单独占一行**（开、闭各一行）。写成 `$$x=1` 这种"同行起头"会让 remark-math 配对整体错位，**后面所有公式连带标题一起变成原始文本**——第 4–5 讲踩过，症状是 h2 只剩 2 个、img 数量骤降，而 HTML 体积却很大。构建后务必核对 `<img>` 与 `<h2>` 数量是否与正文一致。

## 四、必须区分的证据层级

- **课件原文**：直接引用，标页码。
- **推导**：由本讲假设推出，标明假设（例如"此处假设顶点逆时针排列"）。
- **手算**：只能证明算术对，不能替课件背书。
- **推断/外部知识**：明确写"课件没讲，但……"，不要伪装成讲义内容。

## 五、发布前逐篇检查

- 读者只凭正文能否说出：这一讲讲什么、核心公式是什么、哪里会错？
- 每张图是否都在正文或图注里被解释？
- 所有 `images/` 与 `diagrams/` 引用是否都存在？(`python -c` 检查一遍)
- `npm run build` 是否通过？产出的 HTML 里 `<img>` 数量是否等于正文引用数？
- 手机宽度下图片是否溢出、表格是否横向滚动？
- 附录里的「98 页索引」是否与正文覆盖范围一致？

## 六、讲次间的衔接

- 每讲第 1 节要与上一讲最后一节**显式接上**（例如「上次课第一句话：Is this the best we can do?」）。
- 结尾的"还差什么"表要指向**具体讲次编号**，不要写"后面会讲"。
- 同一门课的示意图保持同一套颜色语义，读者跨讲阅读时不用重新学。

## 七、文件与命名

```
src/content/notes/cs184-02-drawing-triangles/
├── index.md
├── images/p01..pNN.png          # 课件截图，页序命名
└── diagrams/d01-<slug>.png      # 原创示意图，序号 + 短横线语义名
```

- 图文件用**语义名**（`d07-halfplanes.png`），不用 `fig1.png`。
- 生成脚本放 `scripts/cs184-<讲次>-diagrams.py`，一个讲次一个脚本，可重复运行。
- 不要留 `_fix.py`、`_fix2.py` 这类迭代文件；收敛后只保留一个脚本。
- **matplotlib 的 mathtext 不支持 `\begin{bmatrix}`**：矩阵要么用等宽文本逐行写，要么画成小方格。同理 `\dfrac` 也建议换成 `\frac`。
